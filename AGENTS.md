# AGENTS.md — общие правила работы ChatGPT и Codex над «Лешим»

> Этот файл — рабочая инструкция для кодовых агентов, использующих репозиторий. Он не заменяет Конституцию Федерации Леших, `LESHY_POLICY.md`, правила владельца и ограничения безопасности. Читайте их до любых действий.

## Источник истины

- Канонический репозиторий: `jaster351/leshy-AI`; рабочая база — актуальная `main`.
- Код, действующие PR, Issues, `CHANGELOG.md`, `VERSION` и русская документация имеют приоритет над предположениями и старыми сообщениями.
- История диалогов ChatGPT **не синхронизируется автоматически** с Codex. Не заявляйте, что знакомы со всеми обсуждениями. Недостающие решения уточняйте в доступных документах/Issues, а не придумывайте.
- Владелец ставит конечную цель: рабочий «Леший» под ключ, без лишних запросов «продолжай». Готовность функции подтверждается интеграцией и проверенным результатом, а не наличием файла или PR.

## Роли и общая очередь

- **ChatGPT:** основная автономная разработка, архитектура, backend, SSH/RDP, SuperAgent, межмодульная интеграция и независимая проверка результатов Codex.
- **Codex на Windows:** локальная Windows/Web UI-интеграция, графические баги, диагностика Windows и **независимая проверка результатов ChatGPT**. Это распределение по умолчанию, а не жёсткий запрет выполнять другую непересекающуюся задачу.
- Один репозиторий, одна очередь Issues и PR, один `main`. Ни один агент не начинает отдельную «новую реализацию всего проекта».
- Перед **каждым** заданием: прочитайте свежие `main`/HEAD SHA, открытые PR и Issues, их затронутые файлы и актуальные обсуждения. Сначала завершайте или ревьюйте существующую работу по теме, не создавайте дубликат.
- Если задача уже занята, выберите другую независимую. Если задачи дополняют друг друга, заранее зафиксируйте границы файлов и зависимости в Issue/PR. Случай с дублирующими PR #283 и #285 по RDP timeout — пример того, что нельзя повторять.
- Начав работу, оставьте в соответствующем Issue краткую запись `В работе: ChatGPT` или `В работе: Codex`, ветка/PR, файлы, граница задачи. Не полагайтесь только на текст метки: перед записью вновь проверьте состояние.
- Для ChatGPT использовать ветки вида `chatgpt/<issue>-<topic>`, для Codex — `codex/<issue>-<topic>`, когда это совместимо с текущими ветками. Использовать отдельные Git worktree при локальной параллельной работе. Не писать прямо в `main`.
- Один ответственный писатель на каждый пересекающийся набор файлов до завершения PR. Не перетирать чужую ветку, не выполнять force push в общий `main`.

## Взаимное ревью

1. ChatGPT **проверяет PR Codex**: актуальный diff, реальную маршрутизацию до Web/Telegram/Windows runtime, безопасность прав, владение данными, отмену операций, обработку ошибок, совместимость, отсутствие регрессий и дублей.
2. Codex **проверяет PR ChatGPT**: независимо читает diff и соседний код, проверяет Windows-совместимость/CRLF/пути, UI, сигнатуры, состояние и восстановление, негативные сценарии. Не переписывает исправление вместо ревью без обозначения отдельной задачи.
3. Автор PR не может сам объявить свою реализацию «проверенной вторым агентом». Результат второй проверки должен быть реально опубликован в PR-комментарии с пометкой `Review-by-Codex` или `Review-by-ChatGPT`, номером коммита/head SHA, выводами и оставшимися рисками. Если оба агента пользуются одной учётной записью GitHub, комментарии **не являются** независимым GitHub-одобрением разных пользователей.
4. Если второй агент недоступен, оставлять PR как `draft`/непроверенный, чётко указывать блокер. Не придумывать его согласие и не объединять непроверенный критический код.
5. После замечаний автор корректирует *свою* ветку. Ревьюер перепроверяет **новый** head SHA. Взаимное ревью не заменяет разрешённые фактические тесты и Windows E2E.
6. Перед merge: повторная проверка свежей `main`, конфликты, статическое ревью, контроль рисков, read-back записанных файлов, план отката и честный отчёт о реально доступных проверках. Для изменений исполняемого кода — обновлять `VERSION` и `CHANGELOG.md` согласно политике репозитория.

## Ограничения текущего периода

- До **01.12.2026** не запускать GitHub-hosted CI/Actions без отдельного разрешения владельца; локальные сборки и автотесты «Лешего» также не запускать без отдельного явного разрешения. Не маркировать непроверенные тесты/Windows E2E как успешные.
- Не менять и не публиковать секреты, пользовательские данные, персональную память и LeshyBrain. Не делать обходов owner/auth/UAC, не повышать роль самому себе.
- Приоритет основной разработки: сначала реально работающие разрешённые терминальные сценарии на Windows/Linux (SSH, а для Windows также PowerShell/CMD внутри авторизованного RDP-сеанса, когда он доступен), затем расширенный графический RDP, браузерный SuperAgent и прочий backlog. Другие независимые потоки не должны мешать этому приоритету.
- Безопасность не подменять удобством: опасные действия подтверждаются владельцем через предусмотренный механизм, неоднозначный результат операции не повторяется автоматически.
- Отчитываться только о подтверждённых коммитах, PR и проверках. Не выдавать спланированную работу за выполненную.

## Шаблон описания PR

- `Issue / ответственный агент / область файлов / базовый main SHA / head SHA`.
- `Что изменено / каким способом подключено к пользовательскому runtime`.
- `Проверено фактически / не проверено и почему`.
- `Независимый review: кем, на каком SHA, замечания`.
- `Риски / откат / следующая задача`.

**Важное ограничение:** файл задаёт процесс координации, но сам по себе не запускает Codex, не открывает доступ к компьютеру и не создаёт сквозную синхронизацию разговоров между ChatGPT и Codex.
