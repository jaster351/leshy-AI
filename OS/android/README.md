## Первый разговор с Лешим через Android (версия 1.10.186)

В текущем прототипе появился **разговор по нажатию кнопки**. Android использует
системную службу распознавания речи (она может использовать интернет поставщика
Android) и системную озвучку TTS. На сервер Лешего отправляется только распознанный
текст по **HTTPS**; аудио/видеозаписи не отправляются.

1. Обновите и соберите **сервер** из `main` командой `windows/build.ps1`.
   Старый сервер не знает маршруты `/v1/android/voice/status` и
   `/v1/android/voice/chat`.
2. На ПК с сервером в PowerShell (обычно с правами администратора) запустите
   `./windows/android-voice-pair.ps1`. Он сохранит в
   `dist/Leshy/LeshyBrain/secrets/android_voice_access.json` **только SHA-256**
   ограниченного ключа, а ключ покажет один раз в терминале. Не пересылайте его
   в чат и не публикуйте в GitHub. Для отзыва/замены используйте
   `./windows/android-voice-pair.ps1 -Rotate`.
3. Соберите APK через `./windows/build-android.ps1`, откройте на телефоне с
   Android 14+ файл `Leshy-Android-current.apk` с рабочего стола и установите вручную.
4. В приложении сохраните HTTPS-адрес доступного сервера, затем введите
   **Android voice key** (это НЕ `LESHY_API_TOKEN`) и нажмите
   «Сохранить ключ разговора» / «Проверить доступ к разговору».
5. Нажмите «Говорить с Лешим», произнесите вопрос, дождитесь текста и голосового
   ответа. Если отсутствует системная служба распознавания, используйте поле
   «Или введите вопрос текстом».

Серверный маршрут специально ограничен диалогом: он не принимает
`owner_id`, не разрешает администраторские API, SuperAgent/SSH/RDP и исполняемые
команды. Он использует ту же LLM и проверенные записи Knowledge, но не весь
функционал веб-чата (веб-поиск, отправка картинок и инструменты отключены).
История разговора изолирована отдельным Android-сеансом.

**Соединение извне:** у телефона должен быть сетевой доступ к серверу по HTTPS
с корректным сертификатом. Нахождение сервера за NAT само по себе не
обеспечивает доступ; понадобится реальный HTTPS-вход/проброс порта/личный
VPN или отдельный ретранслятор. Отказ от проверки сертификатов запрещён.

**Ограничения:** нет непрерывного диалога с hotword «Леший», распознавания
человека по лицу и голограммы. Голосовой режим работает только после нажатия
кнопки, результат зависит от Android Speech Services и TTS. Реальная сборка
APK, Android-установка, HTTPS-транспорт и голосовая проверка ещё не проводились.

## Новая точка входа для сборки — 1.10.185

После включения изменений в `main` запускайте обычный `windows/build.ps1` из корня репозитория: он последовательно обновляет Windows-бинарник и обеспечивает сборку APK. Если Windows уже собран для HEAD, будет обработан только Android.

- Компоненты Java 17, Android SDK Platform 35 / Build Tools 35 / Platform Tools и Gradle 8.9 автоматически проверяются, при необходимости устанавливаются; для первоначальной загрузки требуется интернет и достаточное место на диске.
- APK на рабочем столе: `Leshy-Android-current.apk` и `Leshy-Android-VERSION-SHA-debug.apk` (три последние копии), в репозитории кэш `.autobuild/android-apk/`.
- При авторизованном `gh` появляются отдельные GitHub Android prerelease `android-vVERSION-SHA`; старые однотипные выпуски удаляются после подтверждения загрузки нового, серверные релизы не затрагиваются.
- APK устанавливается на телефон **самим владельцем**. Нет `adb install`, нет принудительной выдачи прав на телефоне. До появления полноценной авторизации, LLM-диалога и 3D это разработческий прототип.

# Android Satellite для «Лешего» — исходный прототип

Цель: **нативный клиент Android 14+** для существующего сервера «Лешего» (Issue #304, общая концепция спутников #303). Это самостоятельный Android-модуль внутри того же репозитория, **не отдельный интеллект**.

## Реализованный исходный код на этом этапе
- Запуск **по нажатию пользователя** foreground-service типа `microphone` с постоянным системным уведомлением.
- Локальное чтение PCM 16 кГц через `AudioRecord`, не сохраняется и не отправляется. Само по себе не включает активацию словом «Леший»; голосовой чат теперь отдельно запускается кнопкой.
- Частичный `PARTIAL_WAKE_LOCK` держит CPU активным во время захвата; экран может быть выключен. Это расходует заряд. `START_STICKY` позволяет системе попытаться восстановить службу, но **не гарантирует невыгрузку**.
- После перезагрузки Android 14+ receiver **не пытается** незаконно включить микрофон из фона. При разрешённых уведомлениях предлагает открыть приложение и запустить прослушивание.
- CameraX + локальный ML Kit: подсчёт лиц в кадре **при открытом приложении**. Обнаружение лица **не является распознаванием личности**.
- Системный TTS теперь озвучивает ответы нейросети и уведомления о сети; Bluetooth-динамик необязателен. Голосовые движки Android могут требовать интернета.
- Изображения, биометрия и локальный PCM не передаются по сети. Отдельный HTTPS-маршрут Android Voice передаёт распознанный текст и принимает текстовый ответ; разговорный токен хранится в Android Keystore.

## Нереализовано и обязательные следующие этапы
1. Безопасная привязка спутника к владельцу, проверенный TLS/auth-протокол к реальному API сервера, текстовый/голосовой ответ.
2. Локальная модель слова активации; VAD, шумоподавление, отмена, ошибки аудиоустройства.
3. **Идентификация зарегистрированных лиц**: явное согласие, enrollment, локальные защищённые эмбеддинги/шаблоны, удаление, проверка качества и порогов, гостевой fallback. Не разрешать опасные команды на основании одной биометрии.
4. Проверка поведения разных Android-прошивок при выключенном экране, режиме энергосбережения и остановке FGS через Task Manager. Для фона камеры требуется отдельный законный режим и UX.
5. Аудиовывод, Bluetooth-маршрутизация, автоподключение к серверу и отладка на реальном устройстве.

## Ограничения Android
Микрофонный FGS нельзя запускать из `BOOT_COMPLETED` при target API 34+, а также в обычном фоне без исключений. Независимо от `START_STICKY` Android/прошивка и пользователь могут завершить приложение. Режим энергосбережения можно изменить вручную в настройках, но приложение не может обещать абсолютную непрерывность.

## Оповещение о потере интернета — исходный код
Во время работы микрофонной foreground-службы `ConnectivityNotifier.kt` следит за `ConnectivityManager` и `NET_CAPABILITY_VALIDATED`. При отсутствии подтверждённого выхода в интернет выдаёт однократное предупреждение «Нет подключения к интернету», при восстановлении — «Подключение к интернету восстановлено». Текст отражается в системном уведомлении. Для речи используется установленный **локальный русский голос Android TTS**, чтобы предупреждение не зависело от облака. Если офлайн-голоса нет — только текст. Bluetooth-динамик необязателен.

Этот блок проверяет только внешнюю интернет-связь: наличие связи с сервером «Лешего» теперь проверяется отдельно через HTTPS GET /v1/status. Это ещё не авторизация и не голосовой канал. Локально доступный сервер по LAN проверяется даже без внешнего интернета. Манифест запрашивает `ACCESS_NETWORK_STATE` и `INTERNET`, но **не отправляет** голос, изображения или биометрию.

**Не проверено:** фактическое произнесение TTS, поведение ConnectivityManager на разных прошивках, сборка, E2E. Внешний интернет и доступность сервера — разные состояния.


## Подключение к серверу: диагностика, не авторизация
- Добавлено поле HTTPS-адреса `https://host[:port]` и кнопка проверки. Только проверенный платформой сертификат TLS; никакого HTTP, перенаправлений, логинов в URL или отключения проверки сертификатов.
- Реально существует `GET /v1/status` из `src/leshy/web_server_impl.py`. При установленном на сервере `LESHY_API_TOKEN` он требует Bearer token. Прототип **не передаёт токен и не авторизуется**, даже если сервер отвечает 200/401.
- При открытии приложения, при ручной проверке и во время пользовательского foreground-прослушивания (каждые 20 секунд) делается HTTPS-проверка доступности указанного сервера. При исчезновении ранее отвечавшего сервера — «Нет связи с сервером Лешего». Для авторизованного разговора служит отдельная кнопка., при появлении — уведомление о восстановлении. Без внешнего интернета локальный HTTPS-сервер можно проверять по LAN.
- INTERNET permission позволяет GET проверки статуса и POST текста в ограниченный Android Voice API. Биометрия, локальный PCM и профили не передаются; серверное исполнение команд отсутствует.
- Сборка, реальная камера, аудио, TLS и Android E2E не проверялись. Версия по-прежнему разработческая.

## Подготовка безопасной привязки телефона — 18.11.2026

- Новый `DeviceIdentity.kt` создаёт по отдельному нажатию в UI EC P-256 ключ подписи в Android Keystore. Приватный ключ не сохраняется в файлах и не отправляется серверу; аппаратная защита зависит от модели телефона.
- Приложение показывает SHA-256 отпечаток открытого ключа, позволяет повторно посмотреть его и удалить ключ **с подтверждением**. Удаление ключа не означает будущий отзыв доступа на сервере.
- Подготовлен метод подписи 32-байтного challenge с контекстом протокола. Пока он **не вызывается**: на сервере нет согласованного endpoint pairing, никакие ключи и подписи ему не передаются.
- Проект требований к server pairing и проверкам: [PAIRING.md](PAIRING.md).
- Android может получить только ограниченный ключ голосового разговора. Доступ владельца и администрирование не выдаются. Общий `LESHY_API_TOKEN` запрещено копировать в клиент.
- Код сохранён в GitHub, но не собирался и не испытывался на Android; требуется отдельное ревью и будущий серверный протокол.



## Сборка Android APK через существующий AutoBuilder

В Android-ветке существующий Windows AutoBuilder получил на вкладке «Сборка» кнопку **«Собрать Android APK»** и кнопку **«Открыть папку APK»**. Маршрут: windows/autobuilder-ui-v3.ps1 → windows/autobuilder-core.ps1 (Mode android-build) → windows/build-android.ps1. Это тот же интерфейс, не новая сборочная программа.

**Нужно:** Android Studio / Android SDK Platform 35 и Java 17+ (подходит JDK/JBR Android Studio). При первом запуске нужен интернет для Gradle и зависимостей. SDK определяется через ANDROID_HOME, ANDROID_SDK_ROOT, local.properties либо стандартный каталог Android Studio; Java — через JAVA_HOME либо JBR из Android Studio.

**Сборка:**
1. Откройте свою копию репозитория, содержащую OS/android и изменённые скрипты AutoBuilder. Пока draft PR #306 не слит, этих изменений **нет в main**. Не смешивайте старую версию AutoBuilder UI с новым core.
2. Откройте обычный Windows AutoBuilder, выберите вкладку «Сборка», нажмите «Собрать Android APK».
3. После фактически успешной сборки нажмите «Открыть папку APK». Путь: .autobuild/android-apk/Leshy-Android-debug.apk.
4. Альтернатива в PowerShell из корня той же копии, без открытия интерфейса: powershell.exe -NoProfile -ExecutionPolicy Bypass -File windows\build-android.ps1 -RepositoryPath . (или вызвать windows\autobuilder-core.ps1 с -Mode android-build -RepositoryPath .).

Первый запуск загружает Gradle 8.9 с официального сайта, если его нет в локальном кеше .autobuild/android-tools. Файл проверяется по официальной SHA-256 контрольной сумме до распаковки. Логи сборки: .autobuild/logs/android-build-*.log и .autobuild/logs/autobuilder-gui.log. SHA-256 APK печатается после успешной сборки.

**Изоляция:** операция android-build не останавливает Windows-сервер, не обновляет main, не удаляет LeshyBrain, не публикует release и не выполняет тесты. Но **обычный AutoBuilder при запуске по-прежнему выполняет свою прежнюю серверную операцию startup**. Если сборка серверной части не нужна, используйте прямой вызов windows/build-android.ps1 или отдельную рабочую копию для Android.

**Ограничения:** debug APK не равен готовому спутнику: полноценная авторизация на сервере, диалог, 3D/AR и Android E2E ещё не завершены. Фактическая сборка, запуск и независимая проверка текущего SHA не выполнялись из-за действующего запрета на тесты и сборки без отдельного разрешения.
