# Android: регистрация без ручного токена (проект реализации 1.10.193)

**Статус:** код клиента, сервера и Web-подтверждения добавлен в ветку разработки; независимая проверка Codex, сборка Android и E2E на Windows/телефоне ещё НЕ выполнены. Не считать эту функцию рабочей на выпущенном APK до слияния, запуска актуального сервера и проверки.

## Сценарий

1. На Android: **⚙ Настройки → HTTPS-адрес сервера → Подключить этот телефон**. Ручной Android voice token не нужен.
2. Телефон генерирует ключ EC P-256 в Android Keystore и отправляет *только* открытый ключ по HTTPS на \`POST /v1/android/pair/start\`.
3. Сервер даёт 32-байтный challenge, Android подписывает \`b"leshy-satellite-pair-v1\\x00" + challenge\` подписью ECDSA SHA-256. Проверка через \`POST /v1/android/pair/prove\`.
4. Android открывает \`/android/pair?id=<request_id>\` в системном браузере. Владелец должен иметь действующую Web-сессию, привязанную к **подтверждённому Telegram хозяина/создателя**; чужая гостевая сессия не годится.
5. Владелец проверяет устройство и отпечаток открытого ключа, подтверждает действие кнопкой. Web-сервер контролирует session cookie, role и same-origin JSON; \`owner_id\` из браузера и телефона не принимается.
6. Телефон ждёт до 5 минут, опрашивая \`POST /v1/android/pair/status\` с подписью challenge. После подтверждения получает **только отдельный ограниченный ключ голосового диалога**, сохраняет его шифрованным через Android Keystore и не требует повторного ввода.
7. Отозвать доступ можно через авторизованный Web-метод \`POST /v1/android/pair/revoke\` (список устройств: \`GET /v1/android/pair/devices\`); удаление локального ключа телефона само по себе не отзывает серверное разрешение.

## Доступ и ограничения

- Права устройства — только \`GET /v1/android/voice/status\` и \`POST /v1/android/voice/chat\`. Нет выполнения команд ОС, SSH/RDP, SuperAgent и административных функций.
- Общий серверный \`LESHY_API_TOKEN\` не передаётся телефону и не используется при привязке.
- Ключ телефона хранится в локальном Android Keystore; аппаратная защита зависит от устройства. На сервере постоянно хранится только SHA-256 токена устройства вместе с подтверждённым owner ID и временем.
- Неизвестный телефон автоматически не становится хозяином. Нужно один раз подтвердить его уже авторизованным владельцем. При отсутствии подтверждённой Telegram/Web роли сервер не выдаст ключ.
- Начальные запросы ограничены: максимум 3 ожидающих с одного IP и 40 на сервер; заявки действуют 300 секунд.
- Токен и подпись не включаются в URL или логи. Ссылка \`/android/pair?id=...\` сама по себе не даёт ключ.
- Биометрия, голос и камера не используются для авторизации и не отправляются серверу во время привязки.
- Старый ручной Android voice key для совместимости сохранён в свёрнутом разделе «Дополнительно». Старый ключ не восстанавливается из серверного SHA-256.
- **Обязательно проверить перед публикацией:** Android 14+, реальную HTTPS-пару, подтверждение и отказ владельца, просрочку, повторную подпись, отзыв токена, отсутствие Telegram, потерю сети, рестарт сервера во время ожидания, корректность авторизации и CSRF.

## Интерфейс

Главный экран — тёмный разговорный UI: состояние соединения, большая кнопка начала/остановки разговора, текстовый ввод и камера. Технические поля, фоновый микрофон, права и диагностические ключи находятся в настройках, а не на стартовой странице.

Android-приложение не превращается в постоянно работающую фоновую камеру: обнаружение лиц пока только по явному включению, при открытом экране; узнавание личности и полноценная персональная память разрабатываются отдельно.
