# Леший AI

**Леший** — самостоятельный автономный AI-ассистент с локальной LLM, долговременной памятью, базой знаний `LeshyBrain`, инструментами, интернет-исследованием и управляемым самообучением.

Проект развивается независимо от CineMax. CineMax и «Гусли» не являются частью этого репозитория. Будущая интеграция с другими продуктами допускается только через стабильный публичный API/SDK.

## Текущее состояние

Актуальная линия переносится из прежнего общего репозитория из staging-ветки `leshy-1.10-stage`. Версия пакета — **1.10.0**. Отдельная незавершённая линия production persistence `feature/leshy-production-storage-19` сохраняется отдельно и не должна теряться при миграции.

## Основные принципы

- штатный inference работает локально через `llama-cpp-python` и GGUF;
- OpenAI/ChatGPT/Ollama не являются обязательными зависимостями;
- `LeshyBrain` — каноническое локальное хранилище знаний, моделей, памяти, настроек и диагностики;
- офлайн-работа по накопленным знаниям обязательна;
- интернет используется для поиска и управляемого пополнения знаний с provenance и верификацией;
- Telegram работает через исходящее соединение/long polling и подходит для установки за NAT;
- Web/Windows и будущие UI используют единый UX и единое ядро;
- документация и Issues для проекта ведутся на русском языке.

## Актуальность данных

Леший обязан различать статические и динамические данные.

Динамическая информация — погода, курсы валют, новости, цены, расписания, наличие, текущие версии ПО, статусы сервисов, результаты событий и другие изменяемые сведения — не должна выдаваться из старого кэша как актуальная. При наличии сети Леший выполняет live-проверку источника. Для таких данных сохраняются источник, `checked_at`, TTL/freshness policy и время последней успешной проверки.

Если live-проверка недоступна, Леший должен явно сообщить, насколько старые данные он использует, вместо того чтобы представлять их текущими.

## Голосовой UX

Интерфейсы с микрофоном должны поддерживать локальную голосовую активацию по фразам:

- «Привет, Леший»;
- «Слушай, Лёша» / «Слушай, Леший»;
- «Окей, Лёша» / «Окей, Леший».

После активации доступна настраиваемая визуальная, звуковая или короткая голосовая реакция. Цель TTS — максимально естественный человеческий голос без роботизированного звучания.

## Интерфейс

Стартовый режим — минималистичный: образ Лешего и поле ввода. После начала общения интерфейс плавно раскрывается в профессиональный рабочий режим с чатом, задачами, инструментами, знаниями, обучением и системными статусами.

Этот сценарий является общим продуктовым стандартом для Web, Windows/desktop и будущих клиентов там, где он применим.

## Локальные модели

Основная chat-модель: `Qwen/Qwen3-8B-GGUF`, файл `Qwen3-8B-Q4_K_M.gguf` (Apache-2.0).

Embedding-модель: `cstr/multilingual-e5-small-GGUF`, файл `multilingual-e5-small-q8_0.gguf` (MIT).

Модели сторонних авторов не входят в лицензию исходного кода Лешего и используются на условиях их собственных лицензий.

## LeshyBrain

Каноническое локальное хранилище содержит:

- `leshy.db` — знания, память, сессии, audit и состояние;
- `models/` — GGUF-модели;
- `shared-knowledge/` — переносимые проверенные знания;
- `Telegram/` — настройки Telegram и локально защищаемые секреты;
- `secrets/` — локальные API-секреты;
- `logs/` — основной журнал, проблемы и диагностические снимки.

NAS и GitHub могут выступать зеркалами, но не заменяют локальный `LeshyBrain`.

## Quality Gate

Обязательная последовательность перед релизом:

`разработка → unit/regression → staging → полный CI → Web-проверки → Windows frozen smoke-test → основная ветка → повторный CI → Release`

Каждый подтверждённый дефект после исправления должен получить regression-тест.

## Безопасность и знания

Пайплайн знаний:

`research → candidate → verification → trusted`

Для знаний сохраняются источник/URL, дата или версия, confidence и данные для повторной проверки/отката. Секреты не должны попадать в Git, диагностические пакеты и публичные знания.
