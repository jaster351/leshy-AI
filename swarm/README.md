# Леший: только первоначальный вход в глобальный рой

`bootstrap.json` — **статический справочник первоначальных HTTPS-узлов**.
Его назначение — помочь новой установке найти участников сети.
Это **не** реестр всех пользователей и **не** база знаний.

Схема:

```json
{
  "schema_version": 1,
  "network_id": "leshy-public-v1",
  "seeds": [
    {"id": "seed-1", "url": "https://реальный-адрес-узла"}
  ]
}
```

Адрес в примере вымышленный. В опубликованном каталоге список пока **пуст**,
поскольку доступных из интернета и проверенных серверов ещё нет. Пока
оператор сети не развернёт хотя бы один seed, состояние клиентского
Лешего будет `waiting_for_seeds` и **глобальное подключение не состоится**.

## Что хранится здесь

Только публичные, относительно стабильные **адреса входа** и версия схемы.
Список меняется владельцем репозитория редко: при добавлении или
удалении основных узлов.

**Никаких** пулов оперативной памяти, данных моделей, истории диалогов,
вопросов, результатов инференса, статусов обычных пользователей, их
IP-адресов, аккаунтов, списков подключённых компьютеров, приватных ключей
и общего журнала знаний в GitHub быть не должно.

## Что происходит на клиенте

1. При включённом auto-join (по умолчанию) Леший загружает
   `bootstrap.json` через HTTPS и проверяет строгую схему.
2. Список адресов сохраняется локально в
   `LeshyBrain/cluster/bootstrap-directory.json`.
3. Следующее подключение и повторная регистрация идут **на seed напрямую**.
   При успешной работе seed обращения к GitHub не нужны.
4. Если все известные seed недоступны, Леший может заново перечитать
   GitHub-каталог, но не чаще одного раза в 15 минут.
5. Если GitHub недоступен, уже сохранённые seed остаются доступными.
   Если сам рой недоступен, локальная LLM продолжает работать.

Текущая регистрация по HTTPS — **не реальный P2P**. Для полноценного
роя понадобится обмен адресами между участниками (например, подписанные
gossip/DHT-сообщения), NAT traversal/relay и защищённый транспорт задач.
После их реализации GitHub не будет участвовать в распределении задач
или синхронизации знаний.

## Где сохранять остальную информацию

- **Проверенные общие знания:** реплицируемое версионированное хранилище
  между узлами, подписанные изменения, Merkle-хеши, догоняющая
  синхронизация и защита от конфликтов.
- **Объявления о доступности узлов:** краткоживущие записи на узлах роя
  (TTL), без коммитов в GitHub.
- **Задания и ответы:** на согласованных вычислительных узлах, с
  изоляцией владельцев и удалением после срока хранения.
- **Секреты, переписки, личная память:** не попадают в глобальный рой без
  отдельного осознанного разрешения.

Реальный внешний seed должен использовать TLS, защищённую регистрацию,
лимиты и мониторинг. Для вычислительного участия понадобится отдельное
разрешение пользователя, а не только auto-join.
