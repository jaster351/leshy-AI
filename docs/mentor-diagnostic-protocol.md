# Протокол причинной диагностики LiveMentor

Решение владельца от 25.11.2026: сначала найти причины ошибок; не запускать дообучение весов, пока архитектурные причины не отделены от ограничений базовой модели. Тренер из #406 и подготовка из #409 остаются неактивными в части GPU и адаптера.

## Начальное измерение
Пакет 004: 162/180, фактичность 53/60, инструкции 57/60, смысл 52/60; 1 критическая ошибка. Пакеты 002–004 различаются, идентичность модели not_confirmed. Нельзя приписывать рост оценки конкретной правке или обучению. Пакет 005 активен; 006 — практика; 007 — пилот. 008 зарезервирован для отдельного итогового аудита. 009 — диагностический, не использовать для обучения весов. Не перезаписывать активную очередь до подтверждения завершения 005; не использовать уже показанные ответы как независимую аттестацию.

## 009: диагностические группы
- q01–q04: дедукция.
- q05–q08: причинность, отличие корреляции от причины.
- q09–q12: абстракция, перенос общего принципа.
- q13–q16: планирование, зависимости, ограничения.
- q17–q20: понимание намерения, неоднозначность.
- q21–q26: многоходовый контекст, изменение параметров и сброс старой задачи.
- q27–q30: границы доказательств.

Каждый ответ оценивать по фактичности, условиям и смыслу (0–2); критические ошибки отдельно. Привязка к SHA исходного ответа обязательна. Оценка по группам не является мерой AGI. Для каждой ошибки указать наблюдение, гипотезу причины и следующий эксперимент; неизвестную причину оставить неизвестной.

## Наблюдаемость
Для новых успешно сохранённых синтетических ответов diagnostic_evidence фиксирует финальный подготовленный бюджет контекста, оставленные/опущенные пользовательские и ассистентские ходы, оценки токенов, известный backend и фактические счётчики завершения, если backend их сообщил. Поле answer_evidence в performance содержит до 64 первых вопросов пакета с валидными локальными записями, ID, SHA ответа и allowlisted числовыми метаданными. Старые записи без доказательств не реконструируются. Нет текста, произвольных имён моделей, файловых путей, личной памяти, новых сетевых получателей. Отсутствующие данные — null. Оценка токенов не равна фактическому prompt_tokens. Счётчики не доказывают, что модель поняла контекст; идентичность модели остаётся not_confirmed. Финальная выборка при fallback может отражать последнюю подготовку контекста, а не весь путь вызова; это диагностический сигнал, не строгая атрибуция причины.

## Правила принятия решений
1. Сначала сверить фактическую версию, модель, backend и признаки усечения. При отсутствии доказательств не объявлять причину установленной.
2. Если ошибка связана с отсутствием нужного пользовательского условия, проверить сборку истории/бюджет и воспроизвести с полным контекстом. Если условие присутствовало, потеря контекста не доказана.
3. Если логика неверна и при полном вводе, провести парный эксперимент на одной подтверждённой модели, одинаковых параметрах и лимитах. Изменять только один фактор: базовый запрос, системную инструкцию, историю либо внешний проверяющий контур. Использовать отдельные свежие варианты, фиксировать идентичность артефакта локально, не публиковать приватные пути.
4. Если учебный контур успешен, а обычный чат нет, проверить обработку намерения, извлечение памяти и маршрутизацию инструментов в реальном чат-пути на синтетических задачах. Не переносить результаты учебного runner автоматически на продукт.
5. Если подтверждён архитектурный дефект, исправить только его и повторить парный тест с контрольной группой. Если дефект остаётся на чистой модели, сравнить доступные базовые модели на тех же заданиях и ресурсах.
6. Дообучение рассматривать только после воспроизводимого остаточного ограничения, подтверждённого независимой проверкой. Без GPU-прогона не заявлять об изменении весов. До проверки безопасности не активировать адаптер.

Порог приёмки архитектурных изменений: воспроизводимое преимущество на новых заданиях, нет роста критических ошибок, не ухудшается безопасность, фиксируются скорость и затраты памяти. Целевые 99% из #407 остаются исследовательской целью, не гарантией. Парные прогоны, контроль обычного чата и идентификация весов ещё не реализованы этим PR. CI/сборки/автотесты до 01.12.2026 — только с отдельным разрешением владельца. Независимое ревью не заменяется статической проверкой автора.
