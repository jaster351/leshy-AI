# Локальная оптимизация Лешего: Vulkan и CPU

Профиль `leshy.performance_runtime` настраивает **только локальный процесс llama.cpp**. Маршрутизация между кластерными узлами, публикация peer-статуса, балансировка и резервные маршруты не изменяются. Каждый узел самостоятельно определяет доступные ему CPU-потоки.

## Почему это нужно

В Windows-логах llama.cpp на 20-поточном Intel CPU стартовал с `n_threads = 20`, а при генерации Qwen3.5-9B через Vulkan наблюдалось около 6,5 токена/с. При смешанном CPU/GPU исполнении максимальное количество потоков может мешать производительности на гибридных процессорах (P/E-ядра). Это гипотеза, которую требуется подтвердить сравнительными измерениями на реальном оборудовании; никакого гарантированного кратного ускорения не заявляется.

## Что изменяется автоматически

- Vulkan: по умолчанию число вычислительных потоков подбирается по доступным процессору ядрам, максимум 8 в профиле `auto`; отдельным параметром задаётся такое же число потоков обработки батча.
- CPU и OpenVINO: старый порядок использования всех доступных потоков сохранён.
- `os.sched_getaffinity` учитывается на Linux, если процесс запущен внутри ограниченного набора CPU.
- Запущенная модель остаётся resident, настройка применяется лишь при **старте** локального llama-server: никакого внезапного перезапуска во время ответа.
- Загрузка модели в VRAM по-прежнему регулируется встроенным `--fit on` llama.cpp; принудительное `-ngl all` не включается.

## Проверить выбранную конфигурацию

```bash
python -m leshy.performance_runtime
```

## Переопределение (без изменения кода)

```bash
export LESHY_PERFORMANCE_PROFILE=compat
export LESHY_LLAMA_GPU_THREADS=12
export LESHY_LLAMA_BATCH_THREADS=8
python -m leshy.web_server
```

`compat` восстанавливает прежнюю политику всех доступных потоков. Для автоматического профиля уберите эти переменные или задайте `LESHY_PERFORMANCE_PROFILE=auto`. `LESHY_LLAMA_CPU_THREADS` управляет CPU/OpenVINO и отдельно от GPU. `LESHY_LLAMA_THREADS` — общий резервный override.

## Измерение

Сравнивайте производительность **одной и той же** модели, GGUF, промпта, длины ответа и контекста при `auto` и `compat`. В `LeshyBrain/logs/vulkan-server.log` llama.cpp записывает `tg = ... t/s`; изменение потоков не означает доказанного ускорения до появления этих измерений. Не запускайте два llama-server одновременно во время сравнений.

## Кластер

Никакие настройки обмена данными между узлами этим профилем не изменяются. При добавлении второго узла у него будет собственный набор CPU/GPU и независимый профиль. Параметры производительности не передаются в модель, не обращаются к облаку и не запускают дополнительные LLM-запросы.
