# Диагностика отказа vision в Telegram (Issue #75)

Статус: **план проверки, не подтверждённое исправление**. Документ не доказывает наличие работающего vision backend в runtime.

## Сквозной контракт

1. Telegram long polling принимает `photo` (выбор максимального доступного размера) либо `document` с проверенным MIME image/jpeg или image/png. Проверить ограничение размера, ошибки `getFile`, загрузки и декодирования; не сохранять токен или содержимое фотографии в логах.
2. Вход сохраняет `telegram user_id`, изолированный `owner_id`, `chat_id`, `message_id`, `reply_to_message.message_id` и подпись/текст запроса. Если есть reply, именно выбранная реплика является целью, даже если позже появились другие сообщения.
3. Vision-capability проверяется отдельно от текстового health-check: поддерживает ли конкретная загруженная модель image payload и совместим ли формат мультимодального запроса с выбранным backend.
4. В vision backend одновременно передаются текст вопроса и изображение (либо несколько изображений); text-only модель не должна получать фиктивный image token и выдавать догадки.
5. При 503, crash, startup timeout — ограниченный failover только на другой **vision-capable** backend, с circuit breaker и cooldown. При отсутствии такого backend — точное сообщение о невозможности анализа изображения, без выдуманного описания.
6. Ответ публикуется в правильный Telegram chat/reply; метрики фиксируют тип отказа, выбранный backend, latency, failover, но не изображение, текст и секреты.

## Регрессионная матрица (не запускать локально без разрешения владельца)

| Сценарий | Ожидаемый результат |
| --- | --- |
| Фото + «Опиши, что видишь» | Текст и фото попадают в один multimodal request |
| Фото с текстом/ошибкой UI | Извлекается смысл интерфейса, не только OCR |
| Фото без текста | Ответ по визуальным признакам, без требования OCR |
| Несколько изображений | Все изображения привязаны к одному вопросу |
| PNG как document | Корректное декодирование и vision-routing |
| Повреждённый файл/слишком большой файл | Понятная ошибка до inference |
| Нет vision модели, text-only модель доступна | Явное сообщение «модель для изображений не настроена», не hallucination |
| Vision backend возвращает HTTP 503 | Ограниченный failover/cooldown, без повторного долгого ожидания |
| Vision backend падает | Нет падения long-polling процесса, следующий текстовый запрос работает |
| Reply на старое фото с quote | Приоритет выбранного message_id, а не последнего сообщения |
| Два непривязанных Telegram user_id | Раздельные owner/session/память |
| Перезапуск runtime | Сохраняется привязка сообщений и контекст в рамках разрешённого хранения |

## Критерий закрытия

Только после статического read-back всех маршрутов Telegram → загрузка → capability check → multimodal inference → Telegram reply, добавления регрессионных тестов, успешного существующего CI и подтверждённого runtime smoke на настоящем фото. Наличие документа или переключателя не считается реализацией.
