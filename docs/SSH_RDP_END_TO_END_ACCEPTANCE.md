# SSH/RDP: проверяемая приёмка сквозного управления

Состояние: спецификация испытаний, **не** доказательство реализации. База ветки: `aa919ea32e3abca2fa1c79103efd244d730ba25b`. Приоритет: SSH/RDP до браузерного SuperAgent.

## Общий контракт безопасности

- Каждый запрос связывается с серверно подтверждённой идентичностью владельца, конкретным доверенным узлом, разрешённой операцией, scope и сроком действия. IP, hostname, пароль и заявленный owner_id сами по себе не дают прав.
- Default deny; отсутствие подтверждения, отзыв разрешения, истёкший lease, смена владельца и разрыв связи запрещают новое действие.
- Для потенциально необратимой операции требуется отдельное подтверждение с привязкой к точному плану и узлу. После неопределённого результата не повторять действие автоматически.
- Секреты не включать в промпт, журнал, трассу UI или Knowledge; сообщения удалённой системы считать недоверенными.
- «Остановить» прерывает дальнейшие шаги и попытки; уже выполненные побочные эффекты не объявлять отменёнными.

## SSH: сценарии

1. В Web/Windows UI владелец выбирает сопряжённый узел, видит права и открывает постоянный терминал без ручного ввода внутренних идентификаторов.
2. Host key проверяется по сохранённому доверенному отпечатку. Неизвестный или изменённый ключ блокирует соединение с понятной ошибкой.
3. Определяются удалённая ОС и оболочка; поддерживаются PowerShell/CMD на Windows и sh/bash на Linux, без ошибочного предположения об одинаковом синтаксисе.
4. Реальная PTY-сессия сохраняет cwd, переменные окружения в рамках сеанса и потоковый stdout/stderr; UTF-8/кириллица и изменение размеров терминала не ломаются.
5. Таймаут, отключение, закрытие вкладки, потеря сети, отмена и повторное подключение имеют явные состояния; старый процесс не становится бесконтрольным.
6. Проверяется фактический exit status. Для неидемпотентных команд после обрыва показывается «результат неизвестен», без автоматического повтора.
7. Негативные сценарии: чужой owner, узел без разрешения, отозванное право, подмена host key, подмена ответа инструмента, попытка утечки секрета.

## RDP: сценарии

1. Проверить настоящий handshake, серверную идентичность и NLA/CredSSP, а не только TCP-доступность 3389 или наличие классов.
2. Встроенный сеанс отображает реальные кадры, поддерживает клавиатуру, мышь, масштабирование и корректную синхронизацию разрешения на Windows и мобильном Web.
3. Управление вводом требует отдельного права; режим просмотра не разрешает ввод. Clipboard/file transfer отключены по умолчанию.
4. Отключение, отзыв доступа, смена пользователя, сетевой обрыв и закрытие сеанса очищают секреты и ресурсы; UI сообщает о разрыве.
5. Негативные сценарии: неверные credentials, недоверенный сертификат, отказ NLA, пустой/зависший кадр, неавторизованный ввод и переподключение после отзыва.

## Проверки и критерий готовности

Проверять по цепочке UI → авторизация → tool routing → реальный протокол → наблюдаемый результат → аудит → stop/reconnect. Сначала статически проверить существующие модули, маршруты и сигнатуры; затем на разрешённых изолированных Windows/Linux узлах провести реальные E2E. При запрете локальных тестов/сборок отмечать `НЕ ПРОВЕРЕНО`. Наличие класса, переключателя, маршрута или документа не равно готовому SSH/RDP.

Эта спецификация не меняет runtime, не разрешает подключение к узлам и не запускает тесты.
