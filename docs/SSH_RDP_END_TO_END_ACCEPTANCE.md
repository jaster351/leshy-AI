# SSH/RDP — критерии сквозной приёмки

Статус: спецификация, не реализация. Приоритет SSH/RDP до браузерного SuperAgent. Без Guacamole, guacd, Docker и стороннего шлюза.

## SSH

1. В существующем Web UI владелец выбирает подтверждённый собственный узел, а не просто IP.
2. На сервере проверяются аутентифицированная личность, владение узлом, отдельные разрешения на подключение и выполнение, срок действия и привязка сессии. По умолчанию отказ.
3. SSH host key проверяется. Ключи и пароли не сохраняются в prompt, Knowledge или логах.
4. Реальная постоянная PTY-сессия: ввод, поток вывода, resize, определение OS/shell, bounded buffer.
5. Каждой операции назначается уникальный идентификатор. При разрыве после отправки команды с побочным эффектом запрещён автоматический повтор, пока результат неизвестен.
6. Остановка команды, закрытие сессии и отзыв прав должны реально прекращать исполнение и ввод.

## RDP

1. Проверка личности, узла, TLS-сертификата, NLA и разрешений до подключения.
2. Реальный поток кадров, resize/DPI и синхронизация координат указателя.
3. Клавиатура и мышь работают только в активной авторизованной сессии; после отзыва доступа ввод блокируется.
4. Статусы подключения, ошибки, переподключения и закрытия видимы пользователю; секреты не попадают в журнал.

## Негативные сценарии

Чужой узел; поддельный owner_id; просроченное разрешение; отзыв во время сессии; неверный host key; отказ NLA/TLS; offline; переполнение вывода; дублированный запрос; потеря сети после опасной команды; параллельные пользователи; закрытие вкладки. Во всех случаях проверить отсутствие утечки и повторного опасного действия.

## Приёмка

Путь от кнопки Web UI до реальной команды/кадра, результата, остановки и аудита проверяется на Windows/Linux в разрешённой изолированной среде. Статический read-back не заменяет runtime/E2E. Существующий UI сохраняется по docs/INTERFACE_RULES_CURRENT.md. Этот документ не доказывает готовность SSH/RDP.
