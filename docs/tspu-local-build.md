# Леший: локальная сборка и проверка диагностики ТСПУ

## Что изменено

Модуль `network-blocking` встраивается в обычный веб-чат и Telegram; отдельный навык запускать не требуется. При запросе «Проверь блокировку <публичный IP>» Леший выполняет:

1. TCP Connect из своей сети по портам 22 и 3389;
2. Cheburcheck: статическую проверку, затем распределённый Probe (если сервис вернул query_id);
3. Check-Host: TCP/22 и TCP/3389 из доступных российских и зарубежных узлов.

Результат включает статус каждого порта и внешнего узла, ошибки и отсутствие результатов, ссылки на действительно полученные отчёты, отметку времени и ID подтверждений выполнения инструментов.

**Оценка уверенности в признаках блокировки ТСПУ** выводится по шкале 0–99% как *условный диагностический индекс*, а не калиброванная статистическая вероятность или доказательство причины. Признаки из разных источников повышают индекс; только TCP timeout или Connection Refused не могут давать «100% ТСПУ». При недостаточной информации Леший печатает полный отчёт. `blocking_attribution=unconfirmed` означает, что блокировка именно ТСПУ не доказана; это не означает, что её нет.

Короткий копируемый вывод `IP-адрес <IP> заблокирован ТСПУ.` предусмотрен только для отдельно подтверждённой причины с проверенным идентификатором доказательства. Сегодняшние три внешние проверки не являются сами по себе достаточным основанием для автоматической установки такого статуса.

## Вариант 1: быстро проверить из исходников на Windows

Для исходников требуется Python 3.11+ и Git. В PowerShell:

```powershell
git clone https://github.com/jaster351/leshy-AI.git
cd leshy-AI
python -m pip install --upgrade pip
python -m pip install -e .
python -m pip install "llama-cpp-python>=0.3.27,<0.4" --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cpu
$env:LESHY_LLM_BACKEND = "echo"
python -m leshy.web_server
```

Откройте `http://127.0.0.1:8765`. Используйте **только публичный IP, который вправе диагностировать**. Для этого модуля тестовая echo-модель подходит, поскольку сетевые проверки выполняются инструментами, а не текстовой моделью. Результаты сетевой диагностики из Вашей сети могут отличаться от результатов других сетей; при отказе внешнего API будут показаны ошибки.

После обновления существующего клона:

```powershell
git checkout main
git pull --ff-only
```

## Вариант 2: собрать Windows-приложение

Требуется Python 3.11+, Git и Inno Setup 6, включая `ISCC.exe`.

```powershell
# Из корня репозитория
.\windows\build.ps1
```

Скрипт установит зависимости, создаст PyInstaller-сборку, проведёт smoke-проверки приложения и соберёт установщик. При обычном запуске он **останавливает работающий экземпляр Лешего из `dist\Leshy`** и обновляет файлы программы; каталог пользовательских данных `dist\Leshy\LeshyBrain` сохраняется. Перед запуском рекомендуется отдельно сохранить резервную копию пользовательских данных.

Ожидаемые файлы после успешной сборки:

- `dist\Leshy\Leshy.exe` — запускаемая программа;
- `dist\LeshySetup-<версия>.exe` — установщик.

После успешного завершения сборки запустите `dist\Leshy\Leshy.exe` и откройте веб-чат.

## Диагностические тесты

```powershell
python -m unittest discover -s tests -p "test_network_blocking*.py"
python -m unittest discover -s tests -p "test_cheburcheck_probe_assessment.py"
```

Проверяются различия между timeout/refused/connected, совпадение независимых признаков, недоступность внешних сервисов, запись подтверждений запуска и запрет ложного «100%». Реальный веб-сервис не вызывается из unit-тестов: они воспроизводят ответ инструментов с помощью заглушек. Проверка доступности из реальной московской сети требует запуска установленного приложения на Вашем компьютере.

Для общего качества сборки также отслеживайте CI GitHub. Зелёный unit CI **не равен** успешной Windows PyInstaller/Inno Setup сборке; последняя должна пройти локально или в Windows workflow.
