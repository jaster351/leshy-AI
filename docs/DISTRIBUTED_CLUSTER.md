# Распределённый кластер Лешего

## Назначение

Модуль `distributed-cluster` позволяет объединить несколько компьютеров в один вычислительный пул Лешего.

Идея похожа на распределение работы в майнинговых пулах только на уровне принципа «много узлов выполняют части общей работы». В Лешем нет монетизации, Proof-of-Work, бессмысленных хэшей или криптовалюты. Узлы выполняют только полезные задачи Лешего.

Типичные задачи для распределения:

- инференс подагентов;
- RAG и GraphRAG;
- embeddings;
- анализ документов;
- фоновые исследования;
- ASR/TTS и другие независимые вычисления;
- будущие совместимые distributed-inference runtime.

## Архитектура

Каждый компьютер является полноценным узлом и публикует:

- `node_id`;
- HTTP endpoint;
- число CPU-потоков;
- список GPU;
- список NPU;
- доступные модели;
- общий объём и доступную RAM;
- текущую очередь инференса;
- относительную нагрузку.

Origin-узел оценивает доступные компьютеры и выбирает исполнителя с учётом очереди, нагрузки, RAM и ускорителей.

Для обычной работы используется режим `cooperative`: один узел координирует пользовательский запрос, а независимые подзадачи выполняются на других компьютерах. Итоговый ответ собирается на origin-узле.

`model_parallel` зарезервирован для runtime, который действительно умеет делить одну модель между несколькими машинами. Леший никогда не пытается «склеить» половины токенов, независимо сгенерированные разными LLM.

## Статистика и пояснения в настройках

В Web UI: **Настройки → Распределённые вычисления**. Раздел показывает
количество обнаруженных компьютеров, занятые и свободные узлы, суммарные
CPU-потоки, RAM, GPU и NPU. Цифры обновляются по запросу или автоматически,
пока открыт раздел настроек. Отображаются **агрегаты**, без адресов узлов,
идентификаторов, данных владельцев и секретных ключей.

**Важно:** в текущей реализации это статистика только доверенного LAN-кластера,
а не количество установок Лешего в интернете. Полностью открытая сеть со
своими пользовательскими ключами, публичным discovery и безопасным P2P пока
остаётся отдельной задачей; интерфейс не должен выдавать её за работающую.

Пояснение для пользователей:

> Чем больше компьютеров запускают Лешего и добровольно предоставляют ресурсы,
> тем выше общая вычислительная мощность сети и быстрее выполняются
> параллельные задачи. Скорость одного ответа не равна сумме токенов/с всех узлов.

## Защита от перегрузки быстрого компьютера

Оркестратор не выбирает исполнителя только по максимальной скорости CPU/GPU.
Он учитывает опубликованную очередь узла, занятую память, текущую нагрузку и
**собственные незавершённые назначения**. Для подагентских LLM-запросов
предпочтение отдаётся свободным совместимым узлам, а выбор и резервирование
выполняются атомарно. Локальный активный inference-slot также включается
в объявляемую очередь.

Эта защита действует для одновременных запросов одного origin-узла. В текущей
LAN-схеме нет глобального распределённого счётчика всех внешних резервирований,
поэтому абсолютное отсутствие перегрузки от нескольких origin-узлов пока
не гарантируется. Публичной сети понадобятся подтверждения приёма,
лимиты исполнителя и централизованное/согласованное ограничение конкуренции.

## Автоматическое обнаружение в локальной сети

Узлы с одинаковым cluster secret обнаруживают друг друга через подписанные UDP broadcast-пакеты в локальной сети.

Порт discovery по умолчанию:

```text
38765/UDP
```

HTTP-порт самого Лешего по умолчанию:

```text
8765/TCP
```

Если используется другой порт, он берётся из `LESHY_PORT`.

Для явного объявления адреса узла можно задать:

```text
LESHY_CLUSTER_ADVERTISE=http://192.168.1.50:8765
```

Это особенно полезно, если автоматическое определение локального IP выбрало неверный интерфейс.

## Доверие между компьютерами

При первом запуске Леший создаёт:

```text
LeshyBrain/cluster/node-id.txt
LeshyBrain/cluster/cluster-secret.txt
```

`node-id.txt` уникален для каждого компьютера.

Чтобы несколько компьютеров стали одним кластером, у них должен быть одинаковый cluster secret. Его можно передать через переменную окружения:

```text
LESHY_CLUSTER_SECRET=<общий секрет>
```

или безопасно перенести содержимое `cluster-secret.txt` на доверенный узел.

Сам secret по сети не передаётся. Discovery и HTTP-задачи подписываются HMAC-SHA256. Запросы с другим `cluster_id`, неверной подписью или устаревшей временной меткой отклоняются.

## Безопасность

Удалённому узлу разрешён ограниченный список вычислительных задач. Он не получает общий произвольный shell-доступ и не может через кластер вызвать опасный инструмент.

На текущем этапе разрешены безопасные вычислительные типы:

- `agent.prompt`;
- `knowledge.search`;
- `graph.search`;
- `cluster.ping`.

Покупки, платежи, управление ОС и другие необратимые действия остаются под существующими Approval Gate и не становятся автоматически доступными удалённым узлам.

## Использование

Статус можно спросить прямо в чате:

```text
/cluster
```

Леший покажет количество узлов и суммарные CPU/RAM/GPU/NPU.

Через API доступны:

```text
GET  /v1/cluster/status
POST /v1/cluster/refresh
POST /v1/cluster/task
```

`/v1/cluster/task` предназначен для взаимодействия между узлами и использует отдельную кластерную HMAC-аутентификацию.

## Как увеличивается мощность

При одном компьютере Леший работает как раньше.

При двух и более компьютерах оркестратор подагентов распределяет роли между узлами. Например, один ПК может выполнять роль Исследователя на GPU, другой — Архитектора, третий — Критика, пока origin-узел занимается координацией. После завершения результаты собираются и синтезируются в один ответ.

В дальнейшем тот же транспорт можно использовать для batch embeddings, обработки документов, фонового обучения и других параллельных задач без изменения пользовательского интерфейса.
