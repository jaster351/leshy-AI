# Приоритетная рабочая сборка Leshy AI 1.10.3

Этот документ задаёт текущий приоритет разработки. Цель — как можно раньше получить реально пригодный к ежедневному использованию Леший, не блокируя выпуск второстепенными функциями.

## Обязательный состав первой рабочей сборки

1. **Локальный чат**
   - Qwen3-8B Q4_K_M как основная локальная chat-модель;
   - работа без обязательных облачных API;
   - сохранение истории и долговременной памяти;
   - изоляция переписок пользователей;
   - понятные ошибки вместо зависания при отсутствии модели/ресурсов.

2. **Telegram**
   - полноценный Telegram-бот для обычного диалога с Лешим, а не только служебные функции профилей/дней рождения;
   - исходящее соединение / long polling, пригодное для установки за NAT;
   - один и тот же диалоговый runtime и память, что и в Web UI;
   - безопасное локальное хранение токена;
   - проверка разрешённых пользователей/администраторов;
   - устойчивое переподключение после временной потери сети.

3. **Web UI — обязательный согласованный сценарий 4 → 3**
   - внешний вид первой рабочей сборки обязан соответствовать `docs/UI_CONTRACT_1.10.3.md`; старый интерфейс не считается допустимым релизным вариантом;
   - **вариант 4 — стартовый экран:** тёмный лесной фон, визуальное ядро Лешего, название «Леший», фраза «Я здесь. Слушаю. Думаю. Помогаю.», поле ввода, кнопка отправки и компактные переходы к основным разделам;
   - после первого сообщения интерфейс **без перезагрузки** раскрывается в **вариант 3 — рабочий режим**;
   - **вариант 3:** слева сайдбар с разделами, по центру основной диалог, справа системная панель с состоянием модели, backend, CPU/GPU/NPU, базы знаний, обучения, Telegram и сервисов;
   - первая реплика не должна теряться при переходе 4 → 3;
   - запускается штатно после установки;
   - доступен пользователю без ручного запуска Python-модулей;
   - чат, история диалога, системный статус и диагностика;
   - настройка Telegram;
   - настройка и состояние самообучения;
   - просмотр понятного журнала текущей работы Лешего без показа скрытой chain-of-thought;
   - приятный, законченный интерфейс, пригодный для ежедневного использования.

4. **Интернет-поиск**
   - live-search для актуальных данных и пробелов локальной базы знаний;
   - сохранение provenance: источник, URL, время проверки, confidence;
   - старые динамические данные не выдаются как актуальные без повторной проверки;
   - найденные сведения не становятся trusted автоматически.

5. **Управляемое самообучение из интернета**
   - единственный начальный внешний источник знаний — интернет;
   - явный постоянный переключатель **Самообучение: ВКЛ/ВЫКЛ** в Web UI;
   - состояние переключателя сохраняется после перезапуска и обновления;
   - при `ВЫКЛ` запрещено автономное пополнение знаний, но обычный поиск по прямому запросу пользователя разрешён;
   - при `ВКЛ` Леший может самостоятельно искать недостающие знания и проходить цикл `research -> candidate -> verification -> trusted`;
   - автономный curiosity/mastery loop не должен мешать интерактивному чату;
   - обучение работает в фоне и ограничивается доступными CPU/RAM/GPU/NPU ресурсами;
   - конфликтующие, сомнительные и устаревшие сведения не заменяют trusted-знания без проверки;
   - обязательны журналирование, provenance и возможность отката ошибочно принятого знания;
   - изменение базовой модели/весов не выполняется автоматически только из-за найденной веб-страницы.

6. **Память и настройки**
   - долговременная память хранится локально в LeshyBrain;
   - пользовательские настройки переживают перезапуск и обновление;
   - настройки конкретного пользователя не смешиваются с другими пользователями;
   - мужской голос остаётся значением по умолчанию, но голосовые функции не блокируют выпуск этой сборки.

7. **Логи и диагностика**
   - штатные runtime-логи сохраняются в `LeshyBrain/logs`;
   - репозиторная папка `log/` используется для диагностических логов, переданных для анализа разработчиком/пользователем;
   - секреты и токены должны очищаться из экспортируемых диагностических материалов;
   - ошибки чата, Telegram, Web UI, поиска и обучения должны иметь достаточный контекст для bug-fix и regression-теста.

## Что НЕ блокирует первую рабочую сборку

Эти функции продолжают разрабатываться, но не должны задерживать выпуск работающего чата:

- голосовой режим и barge-in;
- vision и понимание экрана;
- Computer Use;
- тяжёлые дополнительные модели вроде DeepSeek 32B;
- полная поддержка всех NPU/AI-ускорителей;
- расширенные автономные сценарии вне чата/поиска/обучения.

Они добавляются после стабилизации базового рабочего инструмента либо включаются только если уже проходят соответствующие тесты и не ухудшают стабильность.

## Минимальный Release Gate

Сборка считается пригодной для передачи пользователю только если одновременно выполнено следующее:

- Web UI реально запускается после установки;
- стартовый экран соответствует варианту 4 из `UI_CONTRACT_1.10.3.md`;
- после первой реплики выполняется переход 4 → 3 без перезагрузки и без потери сообщения;
- рабочий режим соответствует варианту 3 из `UI_CONTRACT_1.10.3.md`;
- пользователь может написать сообщение и получить ответ локальной модели;
- история/память сохраняется после перезапуска;
- Telegram-бот принимает сообщение и возвращает ответ через тот же runtime;
- live-search работает при наличии сети и корректно сообщает об отсутствии сети;
- переключатель самообучения виден в Web UI, сохраняет состояние и реально запрещает/разрешает автономное обучение;
- `candidate` не становится `trusted` без проверки;
- ключевые ошибки пишутся в лог без утечки секретов;
- подтверждённые ранее баги базового сценария имеют regression-тесты;
- установка/запуск проходят smoke-test на целевой машине с 16 ГБ RAM без обязательной дискретной GPU;
- после установки пользователь получает рабочий инструмент, а не только набор библиотек или исходников.

## Приоритет выполнения

1. Рабочий локальный chat runtime.
2. Web UI со строго согласованным сценарием 4 → 3, который действительно запускается и использует этот runtime.
3. Полноценный Telegram-диалог через тот же runtime.
4. Долговременная память и восстановление настроек.
5. Live-search.
6. Переключатель и полный цикл управляемого самообучения.
7. Логи, диагностика и regression-тесты базового сценария.
8. Установочная сборка и smoke-test.
9. Только после этого — расширение voice/vision/Computer Use и других тяжёлых функций.
