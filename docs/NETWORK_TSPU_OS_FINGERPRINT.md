# Леший: геодиагностика ТСПУ с предварительным определением служб и ОС

Обновлено: 12.11.2026. Модуль: `network-blocking`, реализация `src/leshy/network_blocking_module.py` и `src/leshy/network_service_fingerprint.py`.

## Порядок выполнения

1. **Локальная TCP-доступность:** обязательно проверяются SSH/22 и RDP/3389.
2. **Предварительное определение ОС:** параллельно проверяются HTTP/80, HTTPS/443 и SMB/445. Если SSH/22 доступен — считывается SSH-баннер; если веб-порт доступен — анализируется HTTP `Server` и ответ сервера. Для HTTPS выполняется TLS-соединение; проверка сертификата отключена **только для получения диагностического ответа**, это не проверка доверия сертификату.
3. **Геосравнение:** Check-Host запускает TCP/22, TCP/80, TCP/443 и TCP/3389 из выбранных узлов РФ и зарубежных стран. Проверяются фактические статусы `connected`, `refused`, `timeout`, `pending`, `error`; статус `pending` никогда не приравнивается к блокировке.
4. **Независимый сигнал:** Cheburcheck проверяет списки и, если предоставлен `query_id`, запускает распределённый probe; только завершённый SSE `done` считается итоговым.
5. **Отчёт:** предположение об ОС и уверенность, все локальные порты, результаты по странам, ссылки на Check-Host и диагностический вывод с `VerifiedToolReceipts`.

Леший принимает запросы вроде `Проверь блокировку 203.0.113.5` или `Проверь доступность example.com` через существующий чат Web/Telegram. Исполняется тот же `network-blocking`-маршрут.

## Достоверность

- `SSH/22` **не доказывает Linux**; `RDP/3389` и `SMB/445` **не доказывают Windows**. Такие выводы показываются только как гипотезы с **низкой** уверенностью.
- `OpenSSH_for_Windows`, `Microsoft-IIS`, `Ubuntu`/`Debian` в сервисных баннерах — более сильный признак, но максимум **средняя** уверенность: баннер может подменять reverse proxy или иной хост.
- При противоречивых баннерах вывод об ОС — **неоднозначна**.
- Географическая разница не доказывает аппаратную фильтрацию ТСПУ: причиной могут быть WAF, GeoIP ACL, CDN, маршрутизация и различия DNS.
- У Check-Host преимущественно дата-центровые узлы: для вывода о пользователях российских провайдеров нужны собственные абонентские измерения.
- Проверяются только несколько заданных портов. **Это не полное сканирование 1–65535 и не полноценный OS fingerprint через TCP/IP stack Nmap.**

## Эксплуатация

- Python 3, только стандартная библиотека для предварительных проверок.
- Нет ввода паролей, перебора учётных данных и эксплуатации протоколов; короткие соединения и ограниченный набор портов.
- Результат от внешнего API может отсутствовать; в таком случае Леший должен сообщить о неполных измерениях.
- Контрольные тесты: `tests/test_network_service_fingerprint.py`. Для реального подтверждения необходим запуск Лешего из нужной сети и сравнение с зарубежными точками.
