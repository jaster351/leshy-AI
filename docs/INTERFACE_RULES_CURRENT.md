# Текущий неизменяемый контракт интерфейса Лешего

Этот документ имеет приоритет для всех дальнейших изменений **браузерного Web UI Лешего**.

## Главное правило

ChatGPT-подобная оболочка, согласованная с пользователем, является базовой и **не должна изменяться, откатываться или заменяться без прямой просьбы пользователя**.

Новые функции, Marketplace, NAS, голос, Computer Use, Telegram, настройки, модели, логи и будущие возможности должны встраиваться в существующую оболочку, а не менять её структуру.

Это правило интерфейса относится именно к общению с Лешим через браузер. Telegram является отдельным каналом общения и использует собственные возможности интерфейса Telegram.

## Компоновка браузерного интерфейса

- Слева: новый чат, поиск и история диалогов.
- История каждого диалога хранится отдельно; Леший автоматически предлагает название.
- У каждого чата доступны действия через `⋯`: переименование, закрепление/открепление, блокировка/разблокировка, архивирование, удаление и другие согласованные действия.
- Внизу слева: аватар/имя Лешего и выпадающее меню разделов и настроек.
- По центру: чистая область текущего диалога.
- Снизу: единый округлый composer с `+`, микрофоном и кнопкой отправки/остановки.
- Справа не должно быть постоянной панели, перекрывающей контент. Действия справа сверху открываются компактными dropdown-меню.
- Marketplace и системные разделы открываются через меню/настройки, не меняя основную компоновку чата.

## Типографика

Основной стек:

`ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Arial, sans-serif`

Ориентиры desktop:

- основной текст диалога: около 15 px;
- поле ввода: около 16 px;
- история чатов и меню: около 14 px;
- вторичные подписи: 11–12 px;
- код: около 13 px;
- плотность строк и отступов должна оставаться близкой к интерфейсу ChatGPT.

Не увеличивать типографику глобально без прямой просьбы пользователя.

## Неблокирующий чат в браузере

Генерация ответа привязана к конкретному диалогу и **не блокирует браузерный интерфейс**.

Во время ответа пользователь должен иметь возможность:

- переключаться на другой чат Лешего;
- переключаться на другую вкладку браузера;
- открывать левое меню, меню профиля и dropdown-меню;
- переходить в Настройки, Marketplace, Логи и другие разделы;
- создавать новый диалог;
- вернуться в работающий диалог и увидеть накопленный ответ.

Переключение чата, раздела или вкладки браузера не должно автоматически останавливать текущую генерацию.

Если ответ завершился в другом чате Лешего или при неактивной вкладке браузера:

- чат получает индикатор непрочитанного ответа;
- при разрешённых браузерных уведомлениях и доступном secure context показывается системное уведомление браузера/операционной системы;
- заголовок вкладки получает индикатор до просмотра ответа.

## Производительность браузера

Запрещены глобальные `MutationObserver` на весь `document`/`documentElement` для обработки streaming UI.

Запрещено повторно читать/клонировать один и тот же SSE-поток только ради UI-индикаторов.

Streaming-рендер должен пакетироваться и обновлять DOM не на каждый отдельный токен, а с ограниченной частотой, сохраняя отзывчивость меню, вкладки и расширений браузера.

Во время генерации браузер не должен показывать предупреждения о зависшем сценарии/расширении из-за работы интерфейса Лешего.

## Изменение контракта

Менять этот контракт можно только после прямой просьбы пользователя изменить интерфейс или его базовую навигацию.


## UI-first — обязательный контракт разработки всех модулей

При создании или изменении **любой** функции Лешего (SuperAgent, Knowledge, поиск,
кластер, браузер, Telegram, диагностика, настройки, голос, обновления, ОС,
интеграции) одновременно проектировать **пользовательский путь**. Техническое
API или новая команда в чате без доступного пользовательского управления
считается незавершённым функционалом, если функция предназначена для человека.

- **Первый запуск без инструкции.** Пользователь должен понять цель по названию
  раздела, подписи поля, состоянию и следующей рекомендуемой кнопке.
- **Не заставлять запоминать команды, ID, JSON, пути, ключи настроек.**
  Основной сценарий — кнопки, переключатели, поля выбора, подтверждения.
  CLI/чат-команды остаются вторичной опцией для опытных пользователей.
- **Одинаковый смысл во всех интерфейсах.** Web desktop/mobile, Telegram и
  доступные Windows-поверхности используют понятные действия и их честные
  возможности; при ограничениях канала предусмотреть нативные кнопки,
  меню либо понятное альтернативное действие.
- **Сразу показывать статус и результат.** Ожидание, очередь, выполнение,
  блокировка, ошибка и завершение должны быть различимы; после операции
  пользователь видит фактический результат, а не голословное «готово».
- **Защита от ошибки.** Опасные, необратимые и широкие действия требуют явного
  согласия, подсказки о последствиях и возможности отмены, если применимо.
  Скрывать/блокировать недоступные действия; не создавать ложных обещаний.
- **Прогрессивное раскрытие.** Частые операции на первом уровне; диагностика,
  JSON и технические детали в «Дополнительно», без перегрузки главного чата.
- **Сохранять работу пользователя.** При обновлении, сетевых сбоях и
  параллельной генерации не терять введённые данные, выбранный раздел
  и развернутые элементы; сообщения и сессии строго изолировать.
- **Проверка перед релизом.** Оценивать сценарий человека с нуля: вход,
  обнаружение действия, настройка, выполнение, ошибка, отмена,
  повтор, перезапуск, мобильная ширина, клавиатура/доступность, права
  владельца. Если нет возможности выполнить E2E, честно отметить ограничение.

Новый API-контракт должен сопровождаться понятным интерфейсом, документацией
назначения элементов и проверками, которые не позволяют случайно убрать
уже реализованные кнопки. Существующая ChatGPT-подобная оболочка остаётся
неизменной; это правило **дополняет**, а не заменяет её.
