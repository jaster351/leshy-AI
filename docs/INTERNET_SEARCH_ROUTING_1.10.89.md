# Интернет-поиск Лешего: когда нужен и когда мешает (1.10.89)

## Главное правило

Леший не обязан искать в интернете перед каждым ответом. Выбор маршрута
основывается на **намерении пользователя**, **изменяемости внешнего факта**,
наличии релевантных проверенных записей и сроке их актуальности.
Системная дата — из ОС; запросы о собственном состоянии приложения надо
обрабатывать локальными диагностическими инструментами, а не веб-поиском.

| Ситуация | Маршрут | Примеры |
| --- | --- | --- |
| Явный интернет-поиск | **Всегда сеть** (даже при свежем кэше) | «/search …», «проверь в интернете», «найди … онлайн» |
| Быстро меняющиеся внешние факты | Сеть или **свежее trusted-знание с TTL** | Погода, новости, цена, курс, расписание, текущая версия, матчи, выборы, текущие лица, услуги и поездки |
| Регулирование и безопасность | Проверенный свежий источник | ПДД, налоги, тарифы, правила, актуальная CVE/GHSA, противопоказания и дозировки |
| Обычный личный разговор | **Локальная LLM** | «привет», «чем занят?», «как дела сегодня?», «что ты умеешь?» |
| Возможности/состояние самого Лешего | **Локальное приложение/инструмент** | «какая у тебя версия?», «почему ты не отвечал?» |
| Создание или обработка собственного текста | **Локальная LLM** | Поздравление, стих, перевод, исправление текста, сценарий, объяснение понятия |
| Стабильные факты и принципы | Локально, если запрос не о новых результатах | «закон Ома», «что такое налог», «как работает курс валют» |
| Факт без достоверного ответа | Сеть по необходимости | Неизвестная организация, специфичная современная технология, нет trusted-знаний |
| Есть лишь candidate или trusted истёк | Перепроверка **фактического** вопроса | Истекший TTL, непроверенные внешние материалы |
| Провайдеры поиска недоступны | **Без выдумывания** динамических данных | В ответе кратко объяснить, что свежие сведения не проверены; локальный разговор не блокировать |

## Приоритет правил

1. Анализировать **текущее сообщение**, не текст цитаты из Telegram Reply.
2. Явная просьба проверить интернет имеет высший приоритет и не гасится кэшем.
3. Отделять разговор *о Лешем* от событий во внешнем мире. «Чем ты занят
   сейчас?» — беседа; «чем занят президент сейчас?» — внешний факт.
4. Творческое задание не становится поиском из-за слов «новый», «погода»
   или «билеты» внутри придумываемого текста. Но «на основе последних
   новостей» требует подтверждения этих новостей.
5. Если пользователь спрашивает **что означает термин**, это не запрос
   текущей цифры или статуса. «Как работает курс валют?» — объяснение,
   «какой курс валют сегодня?» — актуальные данные.
6. Свежие релевантные trusted-записи могут заменить повторный сетевой
   запрос, пока не истёк **строгий TTL**. Кандидаты не эквивалентны
   проверенным сведениям, а явно запрошенный поиск должен выполняться.
7. При нехватке фактов интернет разрешён по необходимости; сообщение об
   отказе LLM от обычного ответа может запустить одну дополнительную
   попытку найти источник. При провале сети не публиковать выдуманные
   свежие факты и не раскрывать подробные диагностические ошибки
   как разговорный ответ на «привет».

## TTL (максимум для кэша без нового запроса)

- Котировки, курсы и текущее состояние внешнего сервиса: 15 минут.
- Погода: 30 минут; новости: 1 час.
- Безопасность/CVE и транспортное расписание: 6 часов.
- Версии ПО, рестораны/отели и туристические сведения: 24 часа.
- Регулирование, противопоказания и дозировки: 7 дней.
- Обычные проверенные факты: 180 дней; устойчивые фундаментальные
  знания: до двух лет.

У отдельной записи dynamic может быть собственный TTL: применяется
**меньшее** время. Когда сеть недоступна, нельзя утверждать, что
истёкшее значение актуально, даже если оно сохранилось в LeshyBrain.

## Пограничные случаи

| Текст | Ожидается |
| --- | --- |
| «Как дела сегодня?» | Локально |
| «Как дела у Microsoft?» | Фактический поиск при отсутствии проверенных сведений |
| «Слушай, чем занят?» | Локально |
| «Привет, расскажи последние новости» | Поиск (не считать всю реплику приветствием) |
| «Напиши новый текст» | Локально |
| «Напиши поздравление на основе последних новостей» | Поиск новостей |
| «Я закончил работу» | Не считать «закончил» запросом законов |
| «Оценка качества», «курс математики» | Не считать ценой товара или курсом валют |
| «Что такое налог?» | Объяснение без live-search |
| «Какая последняя версия Python?» | Сеть или свежее trusted-знание |
| «Проверь в интернете последнюю версию Python» | Сеть даже при недавнем trusted-знании |
| «Что известно о CVE-2026-119977?» | Свежая проверка первоисточника |

## Диагностика и ограничения

В журнале событие `internet_route_decided` указывает
`online`, `reason`, `ttl_seconds`, количество `trusted_hits` и
`candidate_hits`. При реальном запросе появляются
`live_search_started` / `live_search_finished`.
Недоступный локальный SearXNG **не означает**, что нужно отключить
весь интернет: используются существующие резервные провайдеры и
ограничение времени интерактивного поиска. Ошибки провайдеров диагностируются
отдельно от ошибок LLM и TLS.

Эта политика — консервативный детерминированный маршрутизатор, а не
семантический классификатор всех фраз естественного языка. Неоднозначные
новые формулировки надо добавлять по реальным логам и регрессионным
сценариям, без отключения поиска для широких классов запросов.

Windows-сборку и автотесты не запускали. После локальной сборки пользователь
проверяет маршрутизацию в Telegram и Web. LeshyBrain не изменяется.
