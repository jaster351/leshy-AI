# QA и AI-наставник: живой канал (этап 1)

**Состояние:** реализация в отдельной ветке. Подключение к работающему
экземпляру Лешего, Windows E2E, запуск модели и независимый review не
подтверждены. Ответы Лешего запрещено имитировать.

## Передача обновлений через GitHub

Существующий `windows/scheduled-build-task.ps1` проверяет `origin/main` и
запускает локальную сборку, когда обнаруживает изменение. Если задача
установлена и Windows-пользователь авторизован, она проверяет обновления каждые
15 минут. Само наличие этого скрипта не подтверждает, что задача работает
на конкретном устройстве. **Никаких команд для установки обновлений из GitHub
этот QA-канал не исполняет.**

Публикация необработанных логов в GitHub намеренно отключена в
`windows/publish-build-logs.ps1`. Не снимать этот запрет ради QA.
Полные диалоги хранятся локально в `LeshyBrain/qa_mentor/`, а не в репозитории.

## Настоящее общение

На сервере доступен endpoint `POST /v1/qa-mentor/chat`: обязательный
действующий Bearer `LESHY_API_TOKEN` и JSON
`{"role":"qa","message":"...","session_id":""}` либо роль `mentor`.
Никакие owner_id, Creator-права или учётные данные другого пользователя
не принимаются с клиента. Модель вызывается через реальный `app.chat()`
в изолированном пространстве `qa-mentor:isolated`.
При ошибке доступа или модели нет ложного ответа; пишется запись об ошибке.
`GET /v1/qa-mentor/events` показывает журнал только подтверждённому
владельцу/Создателю через HttpOnly Web-сессию.

Полный текст запросов и ответов остаётся в локальном журнале с ограничением
объёма. Автоматическое удаление всей возможной конфиденциальной информации
не гарантируется; **не отправлять секреты и личные данные в QA-вопросах**.
Новый экран «QA и наставник» открывается через меню, с подписями
«AI-наставник», «QA-тестировщик», «Леший».
Он автоматически обновляет журнал, когда открыт, и показывает отсутствие
событий вместо фальшивого примера.

Для реального внешнего клиента предусмотрен
`scripts/qa_mentor_client.py`. Он требует настройки
`LESHY_BASE_URL` (localhost HTTP либо HTTPS) и
`LESHY_API_TOKEN` **только на доверенном исполнителе**.
Токены и ответы не публикуются в GitHub. Клиент не следует по redirect.

## Что ещё отсутствует

- GitHub является каналом доставки кода, **не** готовым двусторонним
  транспортом для сообщений с работающей моделью.
  Чтобы AI-наставник мог автоматически писать и читать ответы, нужен
  доверенный исполнитель с сетевым доступом к установленному API.
- Пока нет такого подтверждённого исполнителя и фактического API roundtrip,
  сеансы помечаются `NOT_RUN`.
- Пока нет независимых заданий и проверенного сравнения, любой ответ
  имеет вердикт `not_evaluated`, не `PASS`.
- Сохранение QA-правил в изолированной памяти **не** означает изменение
  весов модели или памяти Создателя. Для общего повышения качества
  потребуется отдельный одобренный конвейер анализа, внедрения и повторной
  независимой оценки.

## Правила безопасного внедрения

Не запускать CI и локальные интеграционные тесты до разрешения по AGENTS.md.
Перед merge получить независимый review текущего SHA, проверить изоляцию,
доступ к журналу, отказоустойчивость, отсутствие утечки токена, а затем
проверить запуск именно в работающем приложении. Реальный QA без
авторизованного человека не должен выполнять SSH/RDP/ОС-операции.
