# AGI-02/03: проверяемое удаление производной памяти

Статус: исследовательский протокол, не реализация и не подтверждение удаления в runtime. Дата проверки: 2026-11-18 (+05:00).

## Источник
AfterDeleteBench (Ehsan Saleh, Roozbeh Nahavandi, Sama Salarian, Raef Bassily, Andrew Perrault), препринт 22.10.2026: https://arxiv.org/abs/2610.31366 . В контролируемой схеме удаление исходной записи оставляет производные резюме; удаление зависимых резюме по полному provenance устраняет наблюдаемое восстановление в испытанных условиях. Это не доказательство семантического забывания произвольного агента.

## Совместимая интеграция
Не создавать вторую память. Сначала инвентаризировать persistent chat records, summaries, RAG chunks, embeddings, caches и межузловые реплики; определить существующие owner scope и source IDs. Добавлять к производным объектам идентификаторы источников, версию преобразования и lineage с сохранением прежнего формата чтения. Личную память и общую Knowledge не смешивать.

Удаление: пометить источник tombstone, найти транзитивных потомков, исключить их из retrieval до асинхронного пересчёта, пересоздать допустимые сводки из оставшихся источников, инвалидировать векторные и prompt-кэши. При неполном lineage возвращать unverified, а не deleted everywhere. Репликация tombstone на сопряжённые устройства требует проверки scope и квитанций.

## Независимая приёмка
1. Два изолированных профиля: exposed-then-deleted и never-exposed; фиксированные веса, одинаковый inference и контрольные вопросы.
2. Случаи: буквальная копия, перефразирование, компоненты секрета, старый чат, vector retrieval, повторный импорт, конфликт версий, недоступный сопряжённый узел.
3. Проверять исходную запись, производные записи, retrieval, повторную запись и ответ новой сессии. Отдельно учитывать утечку в сыром ответе и ошибку парсера.
4. Отрицательные проверки: другой owner не теряет данные; общая Knowledge не меняется; восстановление backup не возвращает tombstoned сведения; неполный lineage не даёт ложного успеха.
5. Метрики: exact reconstruction exposed vs clean, raw disclosure, re-commit, fresh-session activation, доля непроверенных потомков, latency p50/p95, ошибки. Фиксировать модель, SHA, конфигурацию, размер выборки.

## Следующий инженерный шаг
После аудита действующих модулей памяти добавить обратносуместимый интерфейс lineage и синтетический harness, затем отдельный PR для tombstone/retrieval gate. Не считать этот документ работающим механизмом.
