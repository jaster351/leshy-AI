# Защита подключения к публичному swarm seed (черновой PR)

Публичный HTTPS hello теперь проходит через `swarm_pinned_transport.post_seed_hello`, а не через urllib opener. Клиент получает **все** A/AAAA, отклоняет DNS-ответ целиком, если хотя бы один IP не глобальный, и подключается к выбранному проверенному IP без повторного DNS. TLS по-прежнему проверяет сертификат и имя исходного DNS-хоста (SNI).

Прокси: для публичного seed при наличии системной конфигурации proxy запрос **не отправляется**. Это намеренный fail-closed: удалённый DNS через HTTPS proxy не поддаётся локальной проверке. Локальный пилот HTTP loopback остаётся разрешённым только при явной настройке. GitHub-каталог продолжает использовать свой прежний транспорт; данный PR меняет только POST hello.

Ограничения: нет перебора альтернативных публичных IP после отказа первого; это безопасный отказ с повтором по существующему циклу. Не заявлять, что публичная сеть уже работоспособна. Перед merge требуется проверить совместимость с PR #135/#139 и регрессионные тесты, включая Windows-прокси. Сборки и тесты локально не запускались. Ручной запуск CI запрещён.

Путь: `SwarmMembership._hello → post_seed_hello → _public_addresses → _PinnedHTTPS.connect → TLS/SNI → JSON response`. Ответ ограничен прежним `_MAX_RESPONSE_BYTES`.


### Локальный HTTP-пилот

При `LESHY_SWARM_DEV_ALLOW_HTTP=1` разрешён только loopback-хост и точный путь `/v1/swarm/hello` без userinfo, query и fragment. Проверка выполняется до сетевого запроса; это не разрешение произвольных локальных HTTP-операций. Добавлены отрицательные регрессии без сетевых обращений. Локальный пилот использует отдельный `_PinnedLoopbackHTTP`: `localhost` и `127.0.0.1` подключаются только к числовому `127.0.0.1`, а `[::1]` — только к `::1`. DNS и системные прокси не используются; перенаправления не обрабатываются. Добавлены offline-регрессии для всех трёх форм адреса. Это изменение пока находится в draft PR, интеграционные проверки не запускались.
