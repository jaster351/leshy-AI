# Устойчивость к повреждённым подсказкам узлов

При обходе локального кэша публичных peer-адресов `SwarmMembership._candidate_hops()` повторно применяет `bootstrap_endpoint()` к каждому адресу. Некорректные записи (в том числе локальные HTTP URL и URL с query) теперь пропускаются отдельно: ошибка одной записи не должна завершать поток членства до блока обработки сетевых ошибок.

Это **не** разрешает подключение к запрещённым адресам: проверка политики сохраняется. Добавлены сценарии `tests/test_swarm_corrupt_peer_hints.py` для смешанного кэша и перехода к следующему допустимому узлу.

Ограничения: локальные тесты и сборки не запускались по указанию владельца. Статическое чтение подтверждает изменение ветки PR; end-to-end и CI требуют отдельной проверки. Изменение не обеспечивает полноценный глобальный вычислительный кластер.


### Повреждённая коллекция seed-адресов

Если сохранённый каталог вместо списка/кортежа адресов возвращает `null`, строку, число или словарь, `_validated_seeds()` возвращает пустой набор без исключения. Это защищает поток membership от повреждённых данных; подключение возобновится после получения корректного каталога. Регрессионный сценарий: `test_malformed_directory_collection_is_ignored`. Проверка добавлена, но не запускалась локально.


### Отказ обновления каталога и повреждение кэша

Исключение при `GitHubBootstrapDirectory.refresh()` больше не выходит за пределы `_discover_seeds()`: сохраняются ранее валидированные seed-адреса и текущий endpoint, а тип ошибки фиксируется в диагностике. Ошибка чтения `SwarmPeerCache.urls()` (OSError, TypeError, ValueError) либо неожиданная коллекция подсказок не должна блокировать корректные адреса каталога. Отсутствие валидных seed по-прежнему означает ожидание, а не фиктивное подключение.

Добавлены регрессионные сценарии в `tests/test_swarm_corrupt_peer_hints.py`: отказ каталога, исключение кэша и некорректный тип коллекции. Проверки не запускались локально; это защита фонового membership, а не подтверждение работы глобального кластера.

## Повреждение кэша при запуске

При создании `SwarmMembership` чтение локального peer-кэша теперь защищено от `OSError`, `TypeError` и `ValueError`. Некорректный тип коллекции заменяется пустым списком подсказок; уже проверенные адреса seed-каталога сохраняются. Диагностика фиксирует класс ошибки без вывода содержимого кэша. Регрессии: `tests/test_swarm_startup_corrupt_peer_cache.py` (ошибки чтения и неверные типы). Тесты и сборка локально не запускались.
