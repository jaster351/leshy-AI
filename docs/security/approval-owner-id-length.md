# Защита идентификатора владельца в ApprovalBroker

`ApprovalBroker` не должен сокращать `owner_id` до первых 200 символов: два различных идентификатора с одинаковым префиксом могли бы получить общий ключ доступа к подтверждениям.

Теперь после удаления крайних пробелов идентификатор длиной более 200 символов отклоняется с `ValueError`. Пустой идентификатор по-прежнему отклоняется. Допустимый идентификатор не изменяется. Правило одинаково действует при создании, просмотре, отклонении и использовании подтверждений.

Регрессионные сценарии находятся в `tests/test_approval_owner_length.py`. Локальные тесты и сборки не запускались по ограничению пользователя; результат внешнего CI необходимо проверить отдельно.

Это точечное исправление коллизии, **не** полноценная защита сессий. Следующая работа: серверное одноразовое подтверждение, связанное с `owner_id`, `session_id`, хешем параметров действия и сроком действия, с проверкой в конечном исполнительном маршруте.
