# Публичный swarm: выбор HTTPS-прокси

Для публичного seed применяется DNS-pinned HTTPS: проверяются все A/AAAA, а TCP-соединение устанавливается с проверенным IP с TLS-проверкой исходного hostname.

Прокси, который действительно обслуживал бы HTTPS-запрос, пока запрещён: он может выполнять DNS самостоятельно и обходить проверку назначения. Наличие одного только `HTTP_PROXY` или `NO_PROXY` не означает, что HTTPS идёт через прокси. При `HTTPS_PROXY`/`ALL_PROXY` учитывается системное исключение для адреса назначения (`proxy_bypass`, в том числе на Windows).

Ограничения: защищённый HTTPS CONNECT через прокси пока не реализован; этот сценарий завершается безопасным отказом. Наличие тестов не означает, что код проверен на реальной Windows-машине. Локальные сборки и тесты не запускались.

Регрессии: `tests/test_swarm_effective_proxy.py`.
