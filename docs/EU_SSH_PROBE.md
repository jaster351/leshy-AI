# Независимый европейский SSH-пробник для Лешего

На зарубежном Linux-сервере работает **только Python-скрипт**, без Лешего,
нейросети, Docker, Nginx, сертификатов и API-токенов. Скрипт слушает
`0.0.0.0:8768`, принимает подписанный HTTP-запрос на проверку публичного IP,
трижды выполняет TCP Connect к запрошенному порту SSH/22 либо RDP/3389 и возвращает подписанный результат.
Логина по SSH/RDP нет. Другие порты (включая TCP/445) не проверяются, вход по SSH/RDP не выполняется.

## Установка на уже работающем CentOS Stream 9

Ранее установленный `/opt/leshy-probe/server.py` можно обновить следующей
командой от root:

```bash
curl -fL https://raw.githubusercontent.com/jaster351/leshy-AI/main/ops/configure-eu-ssh-probe-password.sh -o /root/configure-eu-ssh-probe-password.sh
bash /root/configure-eu-ssh-probe-password.sh
systemctl status leshy-eu-ssh-probe --no-pager
ss -lntp '( sport = :8768 )'
```

Обновляется только скрипт пробника, его конфигурация и собственная служба
`leshy-eu-ssh-probe`. Запущенные Docker, SSH, Nginx, Xray не затрагиваются.

Конфигурация сервера: `/etc/leshy-eu-ssh-probe.env` (root, режим 0600).
При первом запуске обновления генерируется 64-значный цифровой пароль локально
с помощью `secrets.randbelow(10)`; в репозиторий он не отправляется.
При повторных запусках **пароль сохраняется**.

Посмотреть значение только на сервере:

```bash
grep '^LESHY_PROBE_PASSWORD=' /etc/leshy-eu-ssh-probe.env
grep '^LESHY_PROBE_COUNTRY_CODE=' /etc/leshy-eu-ssh-probe.env
```

Не публикуйте пароль в чат, журнал или GitHub. Записывайте действительный код
страны серверной площадки (`DE`, `FI`, `NL` и т. д.).

## Настройка Лешего на Windows

Выполните PowerShell от учётной записи, запускающей Лешего. Адрес зарубежного
сервера не хранится в репозитории — укажите **свой реальный IP** только локально.

```powershell
[Environment]::SetEnvironmentVariable('LESHY_EU_PROBE_URL', 'http://EU_SERVER_IP:8768', 'User')
[Environment]::SetEnvironmentVariable('LESHY_EU_PROBE_EXPECTED_COUNTRY', 'DE', 'User')
$password = Read-Host '64-значный пароль зарубежного пробника'
[Environment]::SetEnvironmentVariable('LESHY_EU_PROBE_PASSWORD', $password, 'User')
Remove-Variable password
```

Код `DE` замените на **фактическую** страну из серверной конфигурации.
Только если Леший действительно выходит в интернет напрямую из России, без
VPN или прокси, дополнительно задайте:

```powershell
[Environment]::SetEnvironmentVariable('LESHY_RU_PROBE_CONFIRMED', '1', 'User')
```

После изменения переменных перезапустите Лешего. Если он запускается под другой
Windows-учётной записью или системной службой, настройте переменные для неё.

## Аутентификация

Пароль является секретной случайной последовательностью цифр длиной 64.
Он присутствует **только** в локальных настройках сервера и Windows.
В HTTP-поле `password` передаётся HMAC-SHA256 от цели, nonce и времени, а не
сам пароль. Сервер проверяет подпись и возвращает подписанный HMAC-SHA256
результат; Леший проверяет подпись и совпадение IP, nonce, порта и времени.
Простое повторное использование запроса блокируется на сервере.

**Без HTTPS содержимое и IP целей видны промежуточным узлам, а подключение можно
прервать.** HMAC защищает от незаметного изменения результата и от раскрытия
пароля в самом запросе, но не шифрует трафик и не заменяет TLS во всех его
свойствах. Открывайте порт 8768 только при согласии с этим ограничением.

## Интерпретация диагностики

| РФ (3 попытки) | Европа (3 попытки) | Вывод по TCP/22 |
| --- | --- | --- |
| connected | connected | Блокировка SSH/22 из РФ не выявлена |
| timeout | connected | Признаки регионального ограничения SSH из РФ |
| timeout/refused | timeout/refused | Недоступно обеим точкам, причина неизвестна |
| connected | timeout/refused | Из РФ SSH/22 доступен |
| смешанные ответы | разные | Недостаточно данных |

Разница сетевой доступности не является доказательством именно механизма ТСПУ:
возможны firewall, ACL, маршрутизация или фильтрация провайдером.
Проверка SSH/22 не подтверждает доступность других TCP-портов.

## Диагностика SSH + RDP: короткое решение и копирование мышкой

После обновления до версии Лешего с двухпортовым пробником зарубежный сервер
принимает два авторизованных запроса: POST `/v1/ssh/check` для TCP/22 и
POST `/v1/rdp/check` для TCP/3389. В каждом запросе указывается **только**
фиксированный соответствующий порт (22 или 3389); произвольное сканирование
портов не допускается. Для обоих используется уже существующий пароль:
заменять его, менять IP подключения либо создавать отдельную службу не надо.

Для обновления уже работающей службы на CentOS Stream 9 от root:

```bash
curl -fL https://raw.githubusercontent.com/jaster351/leshy-AI/main/ops/configure-eu-ssh-probe-password.sh -o /root/configure-eu-ssh-probe-password.sh
bash /root/configure-eu-ssh-probe-password.sh
```

Скрипт меняет только исходник пробника и перезапускает
`leshy-eu-ssh-probe.service`; другие службы не трогает. Пароль остаётся
прежним. Порт входящего API — TCP/8768 на всех IPv4-интерфейсах.

Леший сравнивает по три собственных подключения и по три подключения из
Нидерландов **отдельно** для SSH/22 и RDP/3389, затем учитывает результаты
российских и зарубежных узлов Check-Host. Сведения Cheburcheck служат
дополнительным сигналом и не подменяют фактическую TCP-проверку.

Итог начинается с IP и одного из выводов: «Обнаружена блокировка на стороне
ТСПУ» (при согласованных тайм-аутах из РФ и успешных соединениях из Нидерландов
и зарубежного Check-Host), «Блокировка не обнаружена на стороне ТСПУ» (для
портов, доступных из локальной сети) или «Недостаточно данных»/«Возможное
ограничение», когда измерения противоречат друг другу. **ТСПУ не может быть
непосредственно доказан одними TCP-проверками:** даже согласованные результаты
могут быть вызваны ACL, провайдером и маршрутизацией. Полный протокол находится
в раскрываемом блоке. Нажатие на первую строку решения в веб-чате копирует
только решение с IP в буфер обмена.
