# Перенос Лешего №1, экспорт/импорт и резервное копирование

Дата: 11 ноября 2026 года. Статус: **инструкция по ручному переносу + требования к будущему интерфейсу**. Кнопки «Экспорт», «Импорт», «Резервная копия» и «Восстановить» здесь **описаны как задача для реализации**, а не как уже существующая функция программы. Этот документ не меняет исполняемый код.

## Суть за 30 секунд

Леший №1 можно перенести на сервер, сохранив его знания, историю, личную память и идентичность. Переносить нужно **LeshyBrain** целиком из **фактического каталога запуска**, а не только модель Qwen3 и не только GitHub-репозиторий. Перед копированием следует полностью остановить Лешего. Новый компьютер должен иметь совместимую установку Лешего; сначала следует восстановить данные, и только после этого запускать его с этим хранилищем.

**Отличайте три операции:**
- **Перенос того же Лешего №1:** сохранить идентификатор узла и данные; старый экземпляр после переключения оставить остановленным.
- **Создание нового Лешего на основе данных:** новая идентичность/новый node ID, безопасная процедура явного выбора переносимых данных и разрешений; нельзя автоматически клонировать секреты и личную память.
- **Резервная копия:** восстановление того же экземпляра после сбоя. Требует автоматического расписания, шифрования и проверок.

## Что известно из текущего кода

- `windows/launcher.py`: в собранной Windows-версии каталог мозга — `<каталог_с_Leshy.exe>\LeshyBrain`. Не следует предполагать, что он обязательно `C:\Leshy-AI`: корневой путь выбирает пользователь.
- `src/leshy/config.py`: `LESHY_BRAIN_DIR` для других сценариев запуска, `data/leshy.sqlite3` — основной путь SQLite, `models/` — модели, `workspace/` — рабочие данные.
- `src/leshy/storage.py`: SQLite работает в режиме WAL. При живом приложении обычная копия только файла `.sqlite3` может оказаться неполной без WAL; для будущего горячего бэкапа нужна SQLite Backup API или эквивалентный согласованный snapshot.
- `src/leshy/distributed_cluster.py`: `cluster/node-id.txt` и `cluster/cluster-secret.txt` хранят идентичность узла и кластерный секрет. Перенос того же узла сохраняет их; клонирование двух **одновременно активных** узлов с одинаковым node ID недопустимо.
- `LeshyBrain/secrets` содержит приватные данные и токены. Бэкап должен быть **зашифрован**; хранить его в публичном GitHub нельзя.
- Состояние личных учётных записей/привязок и часть знаний также зависит от SQLite. Модель Qwen3 сама по себе не содержит личную память Лешего №1.

## Пошаговый ручной перенос Windows → Windows сегодня

**1. Найдите корневой каталог.** В Проводнике откройте папку, где находится запущенный `Leshy.exe`. Рядом должна быть `LeshyBrain`; внутри проверьте `data\leshy.sqlite3`. Если папка отсутствует, проверьте реальный путь и настройки запуска; **не создавайте пустую вместо старой**.

**2. Остановите исходную установку.** Закройте Лешего, его фоновые задания, службы/автозапуск и дочерние процессы, которые удерживают хранилище. Убедитесь, что память больше не меняется. **Не убивайте активный процесс с записью без необходимости.**

**3. Создайте резервную копию на другой диск или NAS.** Пример PowerShell — замените пути на свои:

```powershell
$source = 'C:\Leshy-AI\LeshyBrain'
$target = 'E:\LeshyBackup\LeshyBrain'
if (-not (Test-Path -LiteralPath (Join-Path $source 'data\leshy.sqlite3'))) {
    throw "База знаний не найдена — проверьте каталог исходной установки: $source"
}
New-Item -ItemType Directory -Force -Path $target | Out-Null
robocopy $source $target /E /COPY:DAT /DCOPY:DAT /R:2 /W:1 /XJ /NP
if ($LASTEXITCODE -ge 8) { throw "Ошибка резервного копирования: robocopy = $LASTEXITCODE" }
```

Это копирование **не шифрует данные**: сохраняйте папку только на своём защищённом носителе. Для отправки через Интернет сначала создайте защищённый архив подходящим инструментом. Для крупных GGUF-файлов простое копирование каталогов надёжнее, чем ZIP с ограничениями конкретного архиватора. До завершения проверки **не удаляйте** исходную папку.

**4. Установите на новом Windows-сервере совместимую версию Лешего**, предпочтительно ту же, что на старом устройстве; перенесите код/приложение штатным установщиком. Драйверы GPU и исполняемые компоненты должны соответствовать новой машине. Не нужно копировать старые драйверы, пути к ускорителям или системный Python.

**5. Пока Леший на новом сервере остановлен, восстановите каталог мозга.** Если новая установка уже создала пустую `LeshyBrain`, сначала **переименуйте её** в `LeshyBrain.empty-before-restore`; не смешивайте два разных дерева. Затем скопируйте сохранённый каталог целиком из бэкапа в `<каталог_новой_установки>\LeshyBrain`. Не используйте `/MIR` на исходном компьютере: ошибочный путь может удалить файлы.

Пример восстановления в `C:\Leshy-AI`:

```powershell
$backup = 'E:\LeshyBackup\LeshyBrain'
$root = 'C:\Leshy-AI'
if (-not (Test-Path -LiteralPath (Join-Path $backup 'data\leshy.sqlite3'))) {
    throw 'В резервной копии отсутствует data\leshy.sqlite3'
}
$dest = Join-Path $root 'LeshyBrain'
if (Test-Path -LiteralPath $dest) {
    throw "Каталог $dest уже существует: остановите новую установку и вручную переименуйте/сохраните его перед восстановлением"
}
robocopy $backup $dest /E /COPY:DAT /DCOPY:DAT /R:2 /W:1 /XJ /NP
if ($LASTEXITCODE -ge 8) { throw "Ошибка восстановления: robocopy = $LASTEXITCODE" }
```

**6. Запустите только новый экземпляр** и проверьте: `/status`, `/memories`, несколько старых диалогов, историю исследований, модель, доступность рабочих файлов, настройки Telegram и кластер. Если что-либо отсутствует, **не создавайте новый профиль и не стирайте старый архив**; проверьте путь `LeshyBrain`, лог запуска и наличие старой базы.

**7. После подтверждения** оставьте исходный экземпляр №1 остановленным/архивным. Если необходимо снова запустить старую копию, сначала прекратите работу новой — одновременно два узла с одной идентичностью будут конфликтовать.

## Windows → Linux (или другая ОС)

Переносить следует данные и проверяемые портативные файлы модели; **не переносить бинарники Windows и старые нативные runtime-компоненты**. Установите Лешего для Linux, остановите службу, поместите `LeshyBrain` по пути, который новая служба реально использует (`LESHY_BRAIN_DIR` или корень установки), выдайте права её пользователю и проверьте базу до включения автозапуска. Конфигурации, где прописаны абсолютные Windows-пути, необходимо адаптировать. Переносимые векторы/индексы при несовместимости можно перестроить из сохранённых проверяемых данных. Кластерный node ID сохраняется только для настоящего переноса, не клонирования.

## Будущие кнопки в веб-интерфейсе — требования на реализацию

**«Экспорт экземпляра»**: пользователь выбирает «Перенести этого Лешего» либо «Только знания/диалоги». Система создаёт *согласованный* снимок SQLite, закрывает или кратко блокирует запись в нужный момент, добавляет память, историю, настройки и разрешённые файлы, формирует манифест с версиями/контрольными суммами, шифрует результат и проверяет, что архив читается. Токены и приватные профили экспортируются только после явного разрешения и с шифрованием. Модели можно выбирать как включаемые/исключаемые тяжёлые компоненты.

**«Импорт экземпляра»**: до начала операции показать состав архива и версии, проверить цифровую целостность, права, совместимость и свободное место; предложить **«Перенести прежний экземпляр»** (с сохранением идентичности) либо **«Создать новый экземпляр»** (с новым ID, безопасной очисткой/перепривязкой секретов). Сделать резервную копию текущего состояния, восстановить атомарно или с rollback и проверить работу. Нельзя молча перезаписывать действующую память другого Лешего.

**«Создать резервную копию»**: локальный и выбранный удалённый/NAS-адресат, шифрование, проверка hash/манифеста, отчёт о последнем успешном бэкапе. Использовать безопасный SQLite snapshot, а не несогласованную копию работающей БД.

**«Восстановить из копии»**: подтверждение, предпросмотр содержимого, тест совместимости, автоматический снимок текущего состояния, восстановление и rollback при сбое. Возможность выбрать старую дату и запустить контроль проверки памяти.

**«Настроить автоматический бэкап»**: рекомендованное начальное расписание: ежедневно и перед обновлением; хранить, например, 7 ежедневных + 4 еженедельные + 3 месячные копии (настраиваемо). Повтор после неудачи, уведомления в Web UI/Telegram о провале и сроке последней **успешной** копии. Ресурсосбережение во время работы пользователя. Защищённая локальная копия **плюс** отдельный NAS/внешний диск: одно хранилище не спасёт от полной потери носителя. Для защиты от вымогателя желательна история версий и копия, которую Леший не может переписать/удалить.

## Требования к надёжности

- Автоматическое резервирование **не** равно проверенному восстановлению. Периодически проводить пробное восстановление в изоляции, проверять SQLite integrity_check, наличие пользовательской памяти и необходимых секретов.
- Ключ шифрования не должен храниться только внутри того же архива. Предусмотреть защищённый recovery-key, который остаётся доступен владельцу при потере сервера. Потерянный ключ означает невозможность расшифровать бэкап.
- Настройки кластера и привязки пользователей нельзя бездумно объединять между независимыми экземплярами.
- Не отправлять содержимое `LeshyBrain`, SQLite, токены, приватные данные владельцев в публичный GitHub. Публично хранить только инструкцию и безопасные обезличенные шаблоны.
- Поддерживать **разницу между восстановлением из бэкапа**, миграцией идентичности и передачей общих знаний.
- Пока экспорт/импорт не реализованы, не обещать, что простая переустановка и «копировать папку» во время работы сохраняют всё.

## Как понять, что перенос прошёл успешно

У нового экземпляра должны совпасть история диалогов, записанные пользовательские воспоминания, сохранённые знания, настройки разрешений, выбранная модель и *при переносе* сетевой идентификатор. Проверяйте содержимое, не только факт запуска веб-страницы. Пока всё не подтверждено — сохраняйте исходный диск и резервный архив.
