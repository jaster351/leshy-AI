# Интернет-поиск Лешего: исправление резерва и телеметрия (1.10.87)

## Повод

8 ноября 2026 года Леший выдал ошибку поиска при генерации поздравления:
SearXNG отклонил TCP-подключение (WinError 10061), а DDGS не смог
получить результаты либо исчерпал общий 12-секундный бюджет.

Исправление выбора **офлайн-маршрута** для поздравлений выполнено ранее
в 1.10.86. Этот патч исправляет отдельную цепочку **настоящего поиска**
для свежих вопросов.

## Найденное в коде

Резервный HTML-провайдер DuckDuckGo добавлялся после FallbackSearch,
содержавшего SearXNG и DDGS. DDGS мог последовательно обходить до девяти
backend с отдельным timeout, поэтому общий лимит поиска в 12 секунд
заканчивался до начала HTML-резерва.

Основной запуск через web_server_impl6.serve устанавливает обёртку
поиска до создания LeshyApp. Однако вспомогательные пути, создающие
LeshyApp до make_handler, не обязаны вызывать __init__ повторно:
дополнительная настройка имеющегося приложения теперь выполняется
при сборке HTTP handler.

## Что изменено

- Приоритеты: SearXNG → DuckDuckGo HTML → DDGS.
- HTML-резерв ограничен 6 секундами на одну попытку, общий интерактивный
  поисковый лимит по-прежнему составляет 12 секунд.
- При уже созданном LeshyApp конфигурация провайдеров ставится
  напрямую, повторный вызов идемпотентен, дубли HTML не добавляются.
- Консоль показывает на старте цепочку активных провайдеров.
  После реального веб-запроса показывает состояние, длительность,
  число источников и время последней проверки.
- Когда обучение выключено, системная подсказка не утверждает, что
  источники уже записаны в базу знаний: запись разрешена только при
  действующем переключателе.

Наличие имени провайдера в консоли **не подтверждает** доступность
соответствующего сайта. Для этого необходим успешный результат
поиска. Ошибки TLS и прокси ПК №2 не скрываются.

## Проверка

1. «Напиши новый поздравительный текст» — локальная LLM без live-search.
2. «Проверь в интернете актуальную версию Python» — live-search.
3. При остановленном SearXNG проверяется переход к HTML до DDGS.
4. Успешный HTML-поиск не должен запускать DDGS.
5. Повторная инициализация обработчика не создаёт дубли провайдеров.
6. В консоли видны «поисковики: Searxng→DuckDuckGoHtml→Ddgs»
   и последний результат поиска.
7. При недоступном HTTPS честно выводится ошибка, без отключения
   SSL-верификации и без выдумывания источников.

Добавлены unit-тесты без сетевых запросов. Windows E2E и CI
не проводились; реальную работу после сборки необходимо подтвердить.
