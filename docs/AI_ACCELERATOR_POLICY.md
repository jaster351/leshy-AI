# Политика AI-ускорителей Лешего 1.10.3+

## Цель

Леший не должен считать современный процессор только CPU. Если платформа содержит специализированный AI-ускоритель (NPU / Neural Engine / AI Engine), он должен быть обнаружен, показан в диагностике и использован для совместимых локальных задач.

## Поддерживаемые классы платформ

### Intel
- Intel Core Ultra и совместимые платформы с NPU / Intel AI Boost.
- Предпочтительный локальный runtime: OpenVINO NPU, когда драйвер и backend реально работоспособны.
- При ошибках памяти/compute NPU исключается из конкретной тяжёлой задачи и не должен блокировать пользовательский ответ.

### AMD
- Ryzen AI / XDNA / XDNA 2.
- Леший обязан обнаруживать доступный AI-ускоритель и выбирать совместимый локальный runtime для ОС и поколения устройства.
- Отсутствие адаптера не должно маскировать наличие NPU: UI показывает «обнаружен, runtime недоступен».

### Apple
- Apple Silicon с Neural Engine.
- На macOS используется нативный локальный стек Apple (Core ML / Core AI или другой поддерживаемый локальный backend), а не OpenVINO как универсальное предположение.
- CPU, GPU и Neural Engine рассматриваются как отдельные вычислительные ресурсы.

### Qualcomm
- Snapdragon X и другие поддерживаемые платформы с Hexagon NPU / Qualcomm AI Engine.
- Используется совместимый локальный backend (например, QNN/поддерживаемый runtime), если он доступен на данной ОС и архитектуре.

## Общие правила планировщика

1. Интерактивный ответ: сначала самый быстрый проверенный локальный GPU backend; затем работоспособный NPU/AI accelerator; затем CPU.
2. Фоновые AI-задачи (embeddings, STT/TTS, verifier, research post-processing, safety/reflection) по возможности разгружаются на NPU/AI accelerator, чтобы не отнимать GPU у чата.
3. При наличии нескольких ускорителей допускается параллельное использование разных устройств разными задачами.
4. Наличие устройства и наличие рабочего runtime — разные состояния. Автоопределение обязано показывать оба.
5. Ни один ускоритель не считается рабочим только по имени устройства: перед использованием выполняется быстрый health/smoke probe.
6. Ошибка backend переводит только этот backend/тип нагрузки в cooldown; после cooldown он перепроверяется.
7. Переключение backend не должно менять или терять базу знаний, историю диалогов и векторный индекс.
8. Веб-интерфейс показывает CPU, GPU, NPU/AI accelerator, активный runtime, состояние health и причину fallback.

## Операционные системы и архитектуры

Минимальная матрица, которую архитектура обязана учитывать:
- Windows x86-64;
- Windows ARM64;
- Linux x86-64;
- Linux ARM64;
- macOS Apple Silicon (arm64).

Архитектура не должна содержать предположение «NPU = Windows + OpenVINO».

## Quality Gate

Релизный Gate должен иметь unit/regression-проверки для синтетических профилей:
- Intel CPU + GPU + NPU;
- AMD Ryzen AI CPU + Radeon GPU + XDNA NPU;
- Apple Silicon CPU + GPU + Neural Engine;
- Qualcomm ARM64 + Adreno GPU + Hexagon NPU;
- обычный CPU без AI-ускорителя;
- найденный AI-ускоритель без установленного runtime;
- runtime найден, но health probe падает;
- восстановление ускорителя после cooldown.

Для каждого профиля проверяется, что отсутствие или отказ NPU не блокирует чат, а наличие рабочего AI-ускорителя не игнорируется.
