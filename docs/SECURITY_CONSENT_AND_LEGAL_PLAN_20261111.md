## Технические требования
1. По умолчанию рой может обнаруживать узлы, но не делиться CPU/GPU/RAM/диском/интернетом без отдельного положительного выбора владельца. Автоподключение к каталогу и доступ к ресурсам — разные права.
2. Экран разрешения показывает редакцию соглашения, категории ресурсов, предел CPU/GPU, RAM/диска, трафика, стоимость, срок, кому доступны ресурсы и понятную кнопку отзыва; никакой предустановленной галочки.
3. Персональные чаты, документы, токены, фотографии, секреты, локальные файлы и команды ОС не включаются в ресурсное разрешение. Опасные операции требуют отдельного локального подтверждения; противозаконные задачи должны блокироваться.
4. Аутентифицировать инициатора и узел; проверять разрешения перед каждой задачей и непрерывно контролировать квоты. Отзыв согласия прекращает выдачу новых задач и останавливает исполняемые в пределах технически возможного.
5. Сохранять минимальный журнал: идентификатор задачи, подпись/идентификатор инициатора, узел, момент, редакцию условий и согласия, разрешённые scopes, решение проверки, отмену, хеш результата. Не хранить пароли, содержимое личных чатов, персональные данные без правового основания.
6. Сетевая защита: TLS, проверка peer identity, изоляция задач, лимиты скорости, запрет DDoS, подмены пакетов, сниффинга без прав и попыток доступа к чужим устройствам. Успех решения задач и точность ответов LLM не гарантируются.
7. Документ и сведения в интерфейсе должны явно предупреждать об ошибках нейросети, риске утраты данных, травм, неправильных медицинских рекомендаций, финансового ущерба, нагрева оборудования и расходов на электричество/связь. Высокорисковые физические и медицинские действия — без автономного выполнения.
8. Юридические публикации версионировать и проверять перед каждым релизом; изменения условий не подразумевают автоматического согласия уже установивших программу пользователей.

## Реализовано в черновом PR (не включено в main)

- `src/leshy/swarm_resource_consent.py`: строгая проверка наличия разрешения, срока, редакции, выбранного ресурса, квоты и доказанной транспортом идентичности peer. Запросы с доступом к секретам, удалённым управлением, уничтожением данных или сетевой атакой отклоняются.
- `src/leshy/swarm_consent_store.py`: согласие с установленным сроком от 1 минуты до 24 часов, лимитами ресурсов, отдельной фразой подтверждения, а также атомарными записями в SQLite и аудите. Отзыв удаляет разрешение.
- `src/leshy/web_server_impl12.py`: API `GET /v1/swarm/resource-consent`, `POST /v1/swarm/resource-consent` и поле `resource_consent` в `/v1/swarm/status`. Выдача/отзыв разрешения только через loopback, при настроенном `LESHY_API_TOKEN` и HTTP Bearer token. Доступ через обычную сеть, без токена и через браузер без корректных полномочий не даёт разрешение.
- `tests/test_swarm_resource_consent.py`, `tests/test_swarm_consent_store.py`: регрессионные сценарии; в рамках этого этапа **тесты и сборки не запускались**.
- `pyproject.toml`: публичное имя автора в метаданных будущих сборок заменено нейтральным обозначением. Ранее опубликованные версии и история Git могут сохранять прежние сведения — это не очистка истории.

### Пример локальной выдачи разрешения для будущего использования

Запрос идёт на `POST /v1/swarm/resource-consent` с заголовками `Content-Type: application/json`, `Authorization: Bearer <LESHY_API_TOKEN>` и телом:

```json
{
  "action": "grant",
  "agreement_revision": "2026-11-11.8",
  "confirmation": "РАЗРЕШАЮ ИСПОЛЬЗОВАНИЕ РЕСУРСОВ",
  "scopes": ["cpu"],
  "limits": {"cpu": 20, "gpu": 0, "ram": 0, "storage": 0, "network": 0},
  "duration_seconds": 3600
}
```

Отзыв: `{"action": "revoke"}` на тот же endpoint с теми же заголовками. **Предоставление согласия НЕ запускает публичные вычисления:** сервер ещё не принимает внешние задачи, при статусе `resource_sharing_enabled=false` и `external_jobs_accepted=false`.

## Дальнейшие шаги разработки

- Привязать допуск **каждой** внешней задачи к подтверждённому transport identity, актуальному локальному согласию и квотам. Не полагаться на заявленный peer ID или JSON-флаг.
- Добавить явный экран UI с текстом соглашения, лимитами, сроком, кнопкой отзыва и оценкой расходов. Создать безопасный способ локального первичного подтверждения без необходимости ручного API.
- Сделать рабочий runtime limiter CPU/GPU/RAM/трафика, изолированное выполнение, отмену задач и переключатель экстренного отключения. Исполнение опасных OS-действий и доступ к секретам не должен включаться общим разрешением на вычисления.
- Проверить юридические документы и технические запреты на каждом релизе, провести ревью текущих прав пользователей, а затем — независимую экспертизу для применимых юрисдикций.
