# Автономное обслуживание зарегистрированного SSH-сервера (1.10.163)

## Что изменилось

Раньше SuperAgent мог подготовить текстовую инструкцию, но **не мог сам вызвать имеющийся SSH-терминал**. В результате Леший мог написать «обновление инициировано» или попросить владельца исполнить `tail -f /var/log/apt/history.log`, хотя у фонового агента не было исполнительной квитанции. Теперь у явно сформулированной задачи «зайди на сервер и обнови пакеты» есть *отдельный типизированный исполнитель*, минуя генерацию shell-команд языковой моделью.

Исполнитель автоматически:
1. Проверяет, что модуль `remote-admin` включён, владелец **уже в момент создания поручения** имел действующую Web-сессию с подтверждённым провайдером (включая Telegram Bot API), и она остаётся действительной и сервер **ранее зарегистрирован с независимой проверкой SSH host key**.
2. Определяет IP из исходного поручения. Если IP не указан, работает **только если сервер в профиле один**. При неоднозначности или постороннем IP не выбирает сервер случайно.
3. Находит **ровно один подходящий JSON-файл SSH-доступа** по полю `host` в доверенном каталоге, который владелец уже настроил. Содержимое и пароль **не выдаются LLM, Web, Knowledge, Telegram, логам, GitHub или кластеру**. Чтение файла выполняется только внутри доверенного SSH-исполнителя.
4. Сам определяет фактическую ОС удалённого компьютера через SSH `uname` / `/etc/os-release`, сравнивая проверенный ключ сервера перед отправкой пароля. Для запроса «узнай ОС сервера» ограничивается проверенными данными без изменения ОС.
5. Для **Ubuntu/Debian** исполняет фиксированный сценарий `apt-get update` + `apt-get -y upgrade` в фоне SuperAgent (до 30 минут); никаких произвольных команд из ответов модели. Работает по SSH, используя существующую учётную запись. При необходимости sudo пароль передаётся через stdin `sudo -S`, не через аргументы процесса/командную строку.
6. Проверяет код завершения команды и **отдельным новым SSH-подключением** повторно проверяет число доступных пакетов и `dpkg --audit`. Только код 0, ноль оставшихся обычных обновлений и чистый dpkg дают статус `ready`. В остальных случаях возвращает `failed` или `blocked` с фактической причиной.
7. Отчитывается в той же задаче SuperAgent без просьбы присылать команды или лог. Если связь потеряна/команда зависла/Леший перезапущен во время обновления — статус **неизвестен**, повторный запуск `apt` автоматом запрещён до проверки. Успех **не выдумывается**.

## Границы

- Только Linux Ubuntu/Debian для автоматического `apt`. Если обнаружен Windows, Fedora, Arch или неизвестная ОС, агент сообщает реально определённую ОС и не запускает неподходящий пакетный менеджер. Расширение на другие ОС — отдельные проверяемые типизированные операции, а не универсальный shell.
- Только зарегистрированные узлы, активная сессия владельца и включённый `remote-admin`. Гостевой Web, знание IP, текст Telegram от постороннего и незарегистрированный сервер не дают доступа.
- Сервис **не включает Ubuntu Pro/ESM Apps** и **не перезагружает сервер** автоматически. `sudo` может отказать из-за политики сервера; отказ — не успех, а отчёт о реальном препятствии.
- Если нажали «Стоп» **после** начала транзакции apt, нельзя безопасно убивать dpkg посреди обновления: Леший перестанет запускать новые этапы, но уже начатый удалённый процесс может продолжаться. Итог после разрыва связи остаётся неподтверждённым до отдельной проверки.
- В настоящее время фоновые SSH-задания не мигрируют между разными узлами кластера. Повтор после рестарта нельзя делать автоматически из-за возможных изменений на сервере.
- Существующая авторизация отдельных произвольных SSH-команд в Web по-прежнему требует точного одноразового подтверждения. Новый маршрут не выдаёт LLM универсального привилегированного терминала.

## Тестирование

Добавлены проверки распознавания поручения, изоляции владельцев, доступа Telegram с действующей Web-cookie, выбора зарегистрированного IP, использования защищённого каталога, определения ОС, проверки `apt` и обработки разрыва связи. Все тесты имитируют SSH и не изменяют действительный сервер. Полный Windows/Linux E2E с реальным сервером не подтверждён до испытания владельцем.
