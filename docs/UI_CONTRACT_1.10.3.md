# UI-контракт Лешего 1.10.3

## Обязательный сценарий 4 → 3

### Вариант 4 — стартовый экран

При открытии Web UI пользователь видит минималистичный экран:
- тёмный лесной фон;
- визуальное ядро Лешего;
- название «Леший»;
- фраза «Я здесь. Слушаю. Думаю. Помогаю.»;
- поле ввода;
- кнопка отправки;
- компактные переходы к Поиску, Знаниям, Обучению, Задачам и Настройкам;
- отдельная кнопка «Голосовой разговор».

### Вариант 3 — рабочий режим

После первого сообщения или запуска голосового разговора интерфейс без перезагрузки раскрывается в профессиональный режим:
- слева сайдбар: Обзор, Чат, Знания, Обучение, Задачи, Инструменты, Система, Настройки, Логи;
- по центру диалог;
- справа системная панель: модель, активный backend, GPU/NPU/CPU, база знаний, обучение, Telegram, NAS/sync, сервисы;
- в шапке остаётся компактный индикатор состояния Лешего.

## Голосовой разговор в реальном времени

В Web UI обязательна отдельная кнопка «Голосовой разговор».

Поведение:
1. Одно нажатие запрашивает доступ к микрофону и запускает голосовую сессию.
2. Пока сессия активна, Леший постоянно слушает пользователя.
3. После окончания реплики она локально распознаётся через голосовой backend Лешего и отправляется в обычный `/v1/chat`, сохраняя ту же session_id.
4. Ответ автоматически озвучивается локальным TTS.
5. После окончания озвучивания Леший снова переходит в состояние «Слушаю» без повторного нажатия кнопки.
6. Повторное нажатие завершает голосовую сессию.
7. Во время разговора UI обязан показывать состояние: «Слушаю», «Распознаю», «Думаю», «Говорю», «Ошибка».
8. Голосовой режим не должен создавать отдельную историю — текст и голос остаются в одном диалоге.
9. Если пользователь начинает говорить во время озвучивания, озвучивание должно быть остановлено и новая реплика получает приоритет (barge-in).
10. При отсутствии локальной голосовой модели UI должен показать понятную ошибку и сохранить возможность обычного текстового чата.

## Полностью офлайн

Голосовой контур обязан работать без доступа в интернет:

`микрофон → локальный STT → локальная LLM → локальный TTS → динамики`.

Запрещено использовать:
- облачные STT/TTS;
- внешние voice API;
- браузерные голосовые сервисы, которые могут отправлять аудио или текст во внешнюю сеть;
- любой fallback, требующий интернет-соединения.

Допускается интернет только как отдельный инструмент самого Лешего для явного web-search/research. Голосовой ввод, распознавание, генерация ответа и озвучивание от этого не зависят.

## Техническая база

- STT: существующий локальный endpoint `/v1/voice/transcribe` и локальная модель Vosk.
- LLM: локальный runtime Лешего.
- TTS: отдельный локальный backend. Для релиза 1.10.3 сервер должен отдавать локально синтезированный звук; браузерный `speechSynthesis` не считается достаточным и не используется как релизный fallback.
- Голосовые модели и ресурсы хранятся локально вместе с данными Лешего и не загружаются во время разговора из внешней сети.

## Quality Gate

Релиз 1.10.3 не считается готовым, пока не пройдены проверки:
- кнопка голосовой сессии присутствует и на варианте 4, и на варианте 3;
- первый запуск запрашивает microphone permission;
- реплика превращается в текст и попадает в тот же chat session;
- ответ озвучивается локально;
- после ответа прослушивание возобновляется автоматически;
- остановка сессии освобождает микрофон;
- отказ голосового backend не ломает текстовый чат;
- barge-in прекращает текущую озвучку;
- переход 4 → 3 выполняется без перезагрузки и без потери первой реплики;
- offline smoke-test выполняется при заблокированном внешнем интернете и подтверждает полный цикл STT → LLM → TTS;
- во время offline smoke-test не должно быть внешних сетевых запросов, кроме явно отключённого web-search/research контура.
