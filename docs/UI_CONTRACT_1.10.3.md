# UI-контракт Лешего

Этот документ фиксирует обязательные правила пользовательского интерфейса Лешего. Новые функции не должны откатывать или ломать эти правила.

## Основная оболочка

Web UI Лешего строится по той же навигационной логике, что современный ChatGPT:

- слева — новый чат, поиск и история диалогов;
- каждый новый диалог хранится отдельно и получает автоматическое название;
- у каждого диалога есть меню действий и отдельное закрепление;
- по центру — чистая область текущего диалога;
- снизу — единый округлый composer с вложениями, микрофоном и отправкой/остановкой генерации;
- справа сверху — компактные действия текущего чата;
- постоянная правая системная панель запрещена: дополнительные действия открываются только dropdown/popover-меню;
- Обзор, Знания, Обучение, Задачи, Инструменты, Система, Логи, Marketplace и Настройки открываются через меню профиля/аватарки, а не занимают постоянную навигацию слева.

При добавлении Marketplace, NAS, моделей, инструментов, голосовых функций и других модулей основная компоновка чата не должна меняться или возвращаться к старой многоколоночной панели.

## Типографика — обязательное правило

Типографика должна оставаться максимально близкой к desktop-интерфейсу ChatGPT по плотности и визуальному масштабу.

Базовый стек шрифтов:

`ui-sans-serif, -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif`

Целевые размеры:

- основной текст сообщений — около 15 px, line-height около 1.55;
- пользовательское сообщение — около 15 px;
- история чатов и меню — около 14 px;
- поле ввода — около 16 px;
- служебные подписи — 11–12 px;
- код — около 13 px моноширинным шрифтом.

Запрещено без отдельного решения пользователя глобально увеличивать основной текст, меню, историю чатов или composer. Новые UI-модули должны наследовать эту типографику.

## Поведение чата

- Ответ Лешего идёт настоящим streaming-потоком.
- До первого токена показывается состояние «Леший думает…».
- При реальном интернет-поиске показываются состояния поиска и изучения источников.
- Во время генерации отправка превращается в Stop.
- Код отображается отдельными блоками с кнопкой «Копировать».
- Новая пользовательская реплика и ответ сохраняются в текущую историю.
- При ручном переименовании автоматическое название больше не должно его перезаписывать.

## Действия с чатами

Меню `⋯` чата должно поддерживать реальные операции:

- Переименовать;
- Закрепить / Открепить;
- Заблокировать / Разблокировать;
- Поделиться;
- Архивировать / Вернуть из архива;
- Удалить.

Удаление любых пользовательских данных, файлов, plugin/skill и других объектов выполняется только после отдельного подтверждения пользователя.

## Голосовой разговор

Голосовой UX обязателен во всех интерфейсах, где доступен микрофон.

Браузер не выполняет распознавание через Web Speech API. Цепочка:

микрофон → `getUserMedia`/`MediaRecorder` → локальный ASR Лешего → локальная LLM → локальный TTS.

Интерфейс должен показывать состояния «Слушаю», «Распознаю», «Думаю», «Говорю», «Ошибка» и поддерживать barge-in — пользователь может перебить голосовой ответ.

Wake-word/обращения: «Привет, Леший», «Слушай, Лёша», «Слушай, Леший», «Окей, Лёша», «Окей, Леший» и естественные обращения по имени там, где контекст однозначен.

## Адаптивность

На desktop история занимает отдельную левую колонку. На небольшом экране она становится выезжающей панелью. Никакая системная карточка или меню не должны перекрывать основной чат на desktop.

## Quality Gate

Изменение Web UI не считается завершённым, если после него:

- возвращается старое вертикальное меню разделов;
- появляется постоянная правая панель поверх чата;
- история чатов пропадает с левой стороны;
- composer перестаёт соответствовать согласованной компактной форме;
- заметно увеличивается типографика относительно зафиксированного масштаба;
- streaming, Stop, копирование кода или голосовой UX перестают работать;
- новая функция перестраивает оболочку вместо добавления себя через существующие меню/настройки.
