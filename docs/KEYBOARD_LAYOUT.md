# Восстановление ошибочной раскладки в чате

Леший определяет короткие сообщения, похожие на естественный текст, набранный в противоположной русской/английской раскладке.

Примеры: `ghbdtn` → «привет», `rfr ltkf` → «как дела», `GHBDTN` → «ПРИВЕТ», `rfrfz gjujlf` → «какая погода», `crjkmrj dhtvtyb` → «сколько времени».

## Поведение

1. **История не меняется**: в БД хранится ровно первоначальное сообщение. Исправленный вариант вычисляется только на этапе интерпретации.
2. Обычная генерация получает системную подсказку с предполагаемым текстом. Приложение добавляет детерминированное «Похоже, вы имели в виду: „…“», а не зависит от желания LLM повторить эту фразу. В SSE Web/Telegram префикс отправляется один раз; совпадающая фраза, сгенерированная моделью, удаляется из видимого потока.
3. Запросы о **погоде и времени** по исправленному тексту маршрутизируются к проверяемым инструментам (`weather_answer`, `clock_answer`), а не к догадкам LLM. Ответ в базе совпадает с финальной версией, отправленной пользователю.
4. Алгоритм намеренно консервативен. Не исправляет URL, команды, IP, пути, цифровые токены, код, смешанные кириллическо-латинские строки. Непонятные и низкоуверенные сообщения проходят без вмешательства; автоматическая коррекция **не** должна исполнять инструменты ОС.

## Ограничения

Это первый этап для короткого русского/английского текста и двух фактологических маршрутов. Общий поиск, все команды и произвольные вложения не переписываются автоматически. Длинные, смешанные и редкие фразы могут не распознаться. Система не гарантирует, что LLM правильно ответит по смыслу; гарантируется только формат обнаруженного и обработанного сообщения.

Проверки предусмотрены в `tests/test_keyboard_layout.py`: регрессии распознавания, CapsLock, строгие негативные случаи, один префикс для обычных/потоковых ответов, фактические маршруты и сохранение исходного текста. Полный Windows/Web/Telegram E2E в этой ветке ещё не подтверждён.
