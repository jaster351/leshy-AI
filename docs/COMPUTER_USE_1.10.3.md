# Computer Use Лешего 1.10.3+

## Цель

Леший должен уметь по явной просьбе пользователя работать с компьютером как человек: видеть экран, понимать текущее состояние интерфейса, управлять окнами и вкладками, нажимать элементы, прокручивать страницы, вводить текст, читать результат и проверять, что действие действительно выполнено.

Ключевой цикл:

`наблюдение экрана -> понимание состояния -> план действия -> выполнение -> повторное наблюдение -> проверка результата`

Леший не должен выполнять длинные последовательности действий вслепую по заранее рассчитанным координатам.

## Полностью локальное наблюдение

Анализ пользовательского экрана выполняется локально. Захват изображения не отправляется во внешние AI/vision API.

Поддерживаемые целевые платформы:
- Windows x86-64 и ARM64;
- Linux x86-64 и ARM64;
- macOS Apple Silicon.

Для понимания экрана допускается сочетание:
- локальной vision/VLM-модели;
- локального OCR;
- данных accessibility/UI Automation API операционной системы;
- DOM браузера, когда он доступен безопасному браузерному адаптеру;
- геометрии окон, курсора и активного приложения.

## Что Леший должен уметь видеть

Леший должен определять:
- активное окно и приложение;
- видимые кнопки, поля, меню, вкладки и диалоги;
- текст на экране;
- ошибки, уведомления и подтверждения;
- состояние загрузки страницы/приложения;
- изменения после собственного действия;
- положение курсора и область, в которой выполняется действие.

При наличии нескольких мониторов пользователь может разрешить наблюдение одного экрана, выбранного окна либо всех экранов.

## Браузер и вкладки

По просьбе пользователя Леший должен уметь:
- открыть сайт;
- создать, выбрать, закрыть и переставить вкладку;
- перейти назад/вперёд и обновить страницу;
- находить нужную вкладку по заголовку/URL/содержимому;
- читать страницу;
- заполнять формы;
- писать текст в редакторах и чатах;
- нажимать кнопки и ссылки;
- ждать появления результата и подтверждать его визуально.

Предпочтительный порядок взаимодействия: DOM/accessibility -> нативный UI Automation -> координаты/vision как последний универсальный уровень.

## Работа с приложениями

Computer Use не ограничивается браузером. Леший должен иметь платформенные адаптеры для:
- переключения окон;
- запуска приложений;
- открытия файлов;
- ввода текста;
- горячих клавиш;
- мыши и прокрутки;
- чтения UI accessibility tree там, где он доступен.

## Индикация пользователю

Во всех интерфейсах Лешего должен быть понятен текущий этап работы:
- `Смотрю экран`;
- `Ищу элемент`;
- `Проверяю страницу`;
- `Переключаю вкладку`;
- `Ввожу текст`;
- `Жду результат`;
- `Нужно подтверждение`;
- `Готово`;
- `Не удалось — проверяю другой способ`.

Это не публикация скрытой внутренней цепочки рассуждений. Пользователь видит краткий журнал фактических действий, использованных инструментов, проверок и результата.

## Приватность

По умолчанию:
- Computer Use выключен, пока пользователь явно его не разрешил;
- при активном наблюдении интерфейс показывает постоянный заметный индикатор;
- сырые кадры экрана не сохраняются на диск постоянно;
- кадр обрабатывается в памяти и удаляется после анализа;
- сохранение скриншотов возможно только отдельной настройкой/явной задачей;
- пароли и секреты не добавляются в долговременную память и базу знаний;
- приватный режим/список исключённых приложений должен позволять полностью запрещать наблюдение конкретных окон.

## Безопасность действий

Чтение экрана и безопасная навигация могут выполняться без отдельного подтверждения после того, как пользователь включил Computer Use для текущей задачи.

Рискованные действия требуют Human Approval Gate, в частности:
- отправка сообщения/письма от имени пользователя, если это не было явно частью команды;
- публикация или удаление данных;
- платежи и покупки;
- изменение паролей, ключей и настроек безопасности;
- установка/удаление ПО;
- выполнение административных действий;
- подтверждение юридически значимых операций.

Явная команда пользователя вроде «напиши этому человеку и отправь: ...» считается разрешением на конкретную отправку в рамках этой задачи, но не бессрочным разрешением на будущие сообщения.

## Проверка результата

После действия Леший обязан повторно получить состояние экрана и проверить ожидаемый эффект. Например:
- после нажатия `Отправить` убедиться, что сообщение появилось в переписке;
- после открытия вкладки проверить URL/заголовок;
- после ввода текста проверить, что текст действительно находится в нужном поле;
- после сохранения убедиться, что приложение подтвердило сохранение.

Если состояние не изменилось ожидаемым образом, действие не считается успешным.

## Quality Gate

Computer Use не считается готовым, пока нет автоматических тестов как минимум на:
- наблюдение -> действие -> повторное наблюдение;
- смену активной вкладки;
- ввод текста и проверку результата;
- обнаружение диалогового окна;
- несколько мониторов;
- отказ в разрешении screen capture;
- отсутствие сохранения кадров на диск по умолчанию;
- остановку Computer Use пользователем в любой момент;
- запрос Human Approval Gate на рискованное действие;
- восстановление после изменения геометрии/масштаба окна, чтобы не нажимать старые координаты вслепую.
