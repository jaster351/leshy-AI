# Что переписываем заново для первой рабочей сборки Leshy AI 1.10.3

Цель: не тратить время на восстановление каждого старого файла. Недостающие компоненты первой рабочей сборки пишутся заново по согласованной архитектуре и требованиям проекта.

## Приоритет 1 — рабочий runtime

Переписать/восстановить совместимые реализации модулей, которые уже ожидает `src/leshy/runtime.py`:

- `config.py` — единые настройки и пути LeshyBrain;
- `activity.py` — журнал активности обучения;
- `agent.py` — основной диалоговый агент;
- `approvals.py` — подтверждения рискованных действий;
- `embeddings.py` — embeddings/vector index;
- `experience.py` — обучение на опыте/оценках;
- `memory.py` — долговременная память;
- `model_repair.py` — устойчивый запуск/восстановление локальных моделей;
- `models.py` — реестр локальных моделей;
- `native_inference.py` — спецификация и запуск штатной GGUF-модели;
- `permissions.py` — разрешения инструментов;
- `privacy.py` — приватность и экспорт/удаление пользовательских данных;
- `sync18.py` — синхронизация переносимых знаний;
- `telegram.py` — полноценный диалоговый Telegram bridge;
- `verifier.py` — проверка candidate-знаний перед trusted;
- `workspace.py` — безопасная рабочая область инструментов.

Все эти модули должны писаться под текущий `main`, без зависимости от CineMax и без обязательных облачных API.

## Приоритет 2 — Web UI

Написать Web UI заново, если полноценной реализации в `main` нет.

Обязательный UX: вариант 4 → 3 из `UI_CONTRACT_1.10.3.md`.

Минимум:
- локальный API `/v1/chat`;
- история/сессии;
- статус модели и backend;
- Telegram status/config;
- кнопка `Самообучение: ВКЛ/ВЫКЛ`;
- состояние research/candidate/trusted;
- диагностика и журнал текущей работы;
- нормальная ошибка при отсутствии модели вместо падения UI.

## Приоритет 3 — Telegram

Написать единый Telegram bridge для обычного общения:
- long polling;
- тот же runtime и память, что Web UI;
- разрешённые пользователи/администратор;
- локальное защищённое хранение токена;
- reconnect/backoff;
- команды состояния и самообучения;
- отсутствие смешивания пользовательских переписок.

Существующие `telegram_people.py` и `telegram_birthdays.py` оставить как дополнительные возможности, а не как замену диалоговому Telegram-клиенту.

## Приоритет 4 — самообучение

Использовать уже имеющиеся `learning_control.py`, `curiosity.py`, `research.py`, `knowledge.py` и safety gate, связав их единым runtime/API/UI.

Правила остаются:
`research -> candidate -> verification -> trusted`.

При выключенном режиме автономное обучение запрещено. Обычный поиск по запросу пользователя остаётся доступен.

## Приоритет 5 — сборка

Создать заново сборочный контур в этом репозитории:
- `pyproject.toml`/зависимости;
- тест запуска импортов;
- unit/regression tests;
- Web smoke-test;
- Telegram bridge tests без настоящего токена;
- Windows frozen build;
- установщик `LeshySetup-1.10.3.exe`;
- GitHub Actions workflow только для `jaster351/leshy-AI`.

Сборка не должна обращаться к CineMax.

## Что сейчас не блокирует

До первой рабочей сборки не блокируют релиз:
- голосовой режим;
- vision;
- Computer Use;
- DeepSeek 32B;
- полный набор vendor-specific NPU адаптеров;
- System Tray/автозапуск/перенос Data Root, если они ещё не реализованы (требования сохранены для последующей Windows-сборки).

## Критерий результата

Пользователь устанавливает сборку, открывает Web UI, пишет сообщение и получает локальный ответ. После перезапуска сохраняется история/память. Telegram принимает сообщение и отвечает через тот же runtime. Интернет-поиск работает. Переключатель самообучения действительно управляет автономным обучением. Только после этого сборка считается пригодным рабочим инструментом.
