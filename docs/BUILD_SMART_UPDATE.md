# Умная Windows-сборка и ожидание простоя через API — #310

## Обычная команда

После слияния PR #310 достаточно обычной последовательности:

```powershell
cd C:\Users\JASTER\Documents\GitHub\leshy-AI
git switch main
git fetch origin
git pull --ff-only origin main
Get-Content .\VERSION
git rev-parse --short HEAD
.\windows\build.ps1
```

Пока PR #310 не объединён с main, привычная команда не использует новую логику.

## Порядок

1. Прямой запуск определяет полный Git HEAD и отказывается обновлять программу при несохранённых изменениях отслеживаемых файлов.
2. Если .autobuild/live-state.json содержит тот же SHA и VERSION и сохранены рабочие dist/Leshy/Leshy.exe и dist/LeshySetup-VERSION.exe, PyInstaller, smoke test и Inno Setup пропускаются без остановки Лешего.
3. Если Git HEAD изменился даже без повышения VERSION, исходники собираются в staging без прекращения работающих ответов. Инсталлятор готовится до остановки приложения.
4. Непосредственно перед публикацией при работающем Leshy.exe через локальный API GET /v1/status читается deployment_activity. Требуется 8 секунд после последнего диалога и 3 последовательных подтверждения простоя, отсутствие inference и его очереди.
5. Если API занят, ждать до 15 минут. Если API не отвечает, недостоверен, не принадлежит текущему LeshyBrain или не предоставляет deployment_activity, отменить остановку без потери данных.
6. Перед публикацией делается резервная копия исполняемой части, после остановки обновляются файлы dist/Leshy, сохраняется LeshyBrain. Если до обновления процесс работал, новый EXE запускается. При ошибке предпринимается восстановление предыдущего EXE.
7. Только после успешного развертывания обновляется .autobuild/live-state.json. Этот файл совместим со штатной логикой AutoBuilder.

## Подключение к API

- По умолчанию используется http://127.0.0.1:8765/v1/status. Для другого порта задайте переменную среды LESHY_BUILD_STATUS_URL, например http://127.0.0.1:8877/v1/status.
- Для защищённого API используется переменная среды LESHY_API_TOKEN. Токен не записывается в лог и не передаётся на внешние адреса; разрешены только localhost, 127.0.0.1, ::1.
- При HTTPS сертификат должен быть доверенным и соответствовать имени в адресе. Обход TLS-проверки запрещён.
- Для новой версии GET /v1/status возвращает deployment_activity со schema=1, active_conversations, idle_seconds, active_inference, waiting_inference и idle.

## Первая миграция со старой версии

Текущая версия main 1.10.177 не предоставляет deployment_activity. По ней нельзя достоверно определить простои. Если она запущена, при первой сборке новой версии после подготовки пакета скрипт откажется её останавливать. В свободный момент самостоятельно остановите старую версию и повторите ту же команду. Последующие обновления уже смогут использовать API.

## Ограничения

- Это контроль незавершённых ответов Web/Telegram и активного inference. Автономные длительные фоновые работы, которые необходимо штатно завершать до перезапуска, пока не отслеживаются.
- Между последней проверкой API и остановкой возможен новый запрос. Полностью атомарный режим обслуживания с запретом новых запросов пока не реализован; он нужен для строгой гарантии отсутствия прерывания.
- Скрипт не должен удалять приватный LeshyBrain, ключи или историю. При сбое отката временная резервная копия остаётся в .autobuild/direct-live-backup для ручного восстановления.
- При запуске через AutoBuilder StageOnly используется прежний цикл публикации и отката, без прямого ожидания из windows/build.ps1; это отдельный сценарий.
- Никакие Windows-сборки, GitHub Actions и автотесты этого PR не запускались. До merge нужны независимое ревью Codex на актуальном HEAD и разрешённая Windows-приёмка.
