# Порядок system-сообщений в GGUF / llama.cpp

Задача PR #74: защитить строгие chat templates от передачи system-сообщений после user/assistant.

## Интеграция

Тот же контракт уже реализован в основной ветке при интеграции Windows-исправлений PR #73: `LlamaServerLLM.chat` перед вызовом сервера использует `_normalize_system_messages(list(messages))` из `context_budget`. Применять старую версию изменения PR #74 напрямую было бы небезопасно: она перезаписывает актуальные изменения в `accelerator_runtime.py`.

`persona.with_leshy_identity` дополнительно поддерживает единственный начальный system-блок и не дублирует свою инструкцию. Для прямых вызовов backend соблюдение порядка обеспечивает `_normalize_system_messages`.

## Осталось проверить

Реальный запрос GGUF/Qwen со смешанным порядком системных сообщений, отрицательные сценарии и поведение 4096-token context. Локальные тесты и сборки не запускались по установленному ограничению.

Этот документ отмечает, что функциональная цель старого PR была объединена через PR #73; новых изменений исполняемого кода здесь нет.
