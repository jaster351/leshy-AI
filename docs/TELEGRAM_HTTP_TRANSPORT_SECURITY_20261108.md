# Telegram: безопасный транспорт и ошибки HTTP

Изменение от 08.11.2026, рабочая ветка (не подтверждено в runtime).

* Любой запрос транспорта допускается только к HTTPS api.telegram.org без нестандартного порта; загрузка медиа использует тот же транспорт.
* При системном прокси сохраняются настройки ОС и переменные окружения; HTTP-перенаправления запрещены. Пользовательский CA загружается с обязательной проверкой сертификата.
* При HTTPError сохраняются code, headers (включая Retry-After) и поток ответа для существующей обработки Telegram API; URL заменяется безопасной строкой без токена. Сетевые исключения преобразуются в сообщения без URL и пароля.
* Негативные сценарии: внешний хост, HTTP 302, HTTP 429, ошибки TLS, системный прокси, повторные обращения. Нельзя считать исправление проверенным без запуска тестов и пользовательской проверки.
* Совместимость: старые тесты, мокирующие request.urlopen, заменены на мокирование build_opener. Сохранение/чтение секретов и идентичность пользователей не менялись.

**Ограничение:** это статическая подготовка; локальные тесты и сборки не запускались по требованию владельца. Перед объединением сверить с параллельными PR по Telegram и проверить GitHub CI, если он доступен.
