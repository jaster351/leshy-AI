# GitHub только для входа в рой — решение 1.10.94

## Цель

Каждая публичная установка Лешего знает, где искать **начальные узлы**
глобальной сети. Каталог `swarm/bootstrap.json` находится в каноническом
GitHub-репозитории `jaster351/leshy-AI` и содержит **только** статические
адреса seed, не список пользователей.

После первоначального знакомства все актуальные сведения, распределённые
вычисления и общие знания должны идти по **сети узлов**, без GitHub.
Запись данных пользователей в GitHub **запрещена**.

## Выполнено

- `GitHubBootstrapDirectory`: read-only HTTPS GET канонического каталога
  `raw.githubusercontent.com/jaster351/leshy-AI/main/swarm/bootstrap.json`.
- Строгая схема `schema_version=1`, `network_id=leshy-public-v1`,
  не более 16 адресов, только одобренный вид HTTPS URL.
- Отклонение редиректов, адресов частных сетей и loopback (кроме
  явно разрешённого локального пилота), логинов/паролей/секретов в URL,
  неожиданных полей (в том числе пользовательской информации).
- Атомарное локальное сохранение публичного каталога в
  `LeshyBrain/cluster/bootstrap-directory.json`.
- Повторный запуск использует кэш, если рабочий seed известен;
  GitHub не участвует в обычном heartbeat.
- Если работающие seed потеряны, клиент переключается между известными
  адресами и при необходимости перечитывает GitHub не чаще одного раза
  в 15 минут. Недоступность GitHub не удаляет кэш.
- Ранее существовавшая настройка `LESHY_SWARM_BOOTSTRAP_URL` сохраняется
  для контролируемого пилота, но больше не требуется для нахождения
  опубликованного каталога.
- Переключатель auto-join остаётся включённым по умолчанию и доступен в
  настройках. В UI показываются источник, число seed и честное состояние
  `waiting_for_seeds`.

## Что **не** готово

**Важное:** пока `seeds: []`, ни один внешний ПК не сможет войти через
GitHub. Это не готовая мировая сеть.

Существующий подписанный HTTPS heartbeat к seed сохраняется из 1.10.92.
Он не выдаёт разрешения на вычисления: `resource_sharing_enabled=false`,
`remote_execution_enabled=false`. Также не реализованы публичный
peer discovery, защищённый P2P-транспорт, NAT traversal/relay,
обмен заданиями глобального уровня и единый арбитр.

Общая база знаний между двумя LAN-компьютерами сейчас частично
реплицируется, но не является идентичной. Для глобального роя нужна
отдельная проверяемая репликация, не копирующая личную память.

**Ни один URL из примера не следует публиковать в `bootstrap.json` как
настоящий.** Нужен хотя бы один реально доступный HTTPS seed под контролем
оператора; для устойчивости — несколько в независимых сетях.

## Следующий этап — обмен без GitHub

Когда seed доступен, он должен предоставлять адреса других участников
через собственный подписанный протокол. Затем узлы используют DHT/gossip
для объявления присутствия и распределения заданий. Каждый узел
постоянно сохраняет на диске ограниченную адресную книгу известных
проверенных peer (с TTL и подписью); при перезапуске пытается
подключиться к сохранённым peer до обращения к GitHub.

Общие знания хранятся как независимый версионированный набор фактов с
источниками, подписями, журналом изменений, конфликтами и Merkle-хешами.
После восстановления связи узлы догоняют изменения напрямую друг от
друга. Не следует объявлять совпадение баз по одному
`state=synchronized`: требуется контроль содержимого.

Трафик пользователя и его персональный контекст нельзя транслировать
всем узлам. Диспетчер передаёт задачи только подходящим доверенным
исполнителям, при отдельном разрешении пользователя; арбитр публикует
один итоговый ответ. Регистрация в сети и добровольная отдача
GPU/CPU — независимые настройки.

## Как проверить текущий этап

```powershell
Invoke-RestMethod "http://127.0.0.1:8765/v1/swarm/status" | ConvertTo-Json -Depth 5
```

С текущим пустым каталогом ожидаются `state=waiting_for_seeds`,
`seed_count=0` и `global_mesh_connected=false`. Значение
`registered` возможно только при рабочем HTTPS seed и
подтверждённой подписанной регистрации. Это всё ещё **не** готовый P2P.

Локальные автотесты и сборка Windows не запускались; совместимость
после пересборки должна быть подтверждена на реальных машинах.
