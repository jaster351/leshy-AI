# Гонка установки планировщика SuperAgent (11.11.2026)

`install_superagent_background_scheduler()` ранее проверял `_INSTALLED` без синхронизации. Два потока могли одновременно прочитать `False`, повторно обернуть `SuperAgentService._execute` и создать вложенные захваты одного inference-слота. Это могло привести к зависанию фоновой операции.

Установка теперь сериализована через `threading.RLock()`. Исходный метод захватывается локальным замыканием; `_INSTALLED` выставляется только после замены метода. Повторный вызов возвращается без повторной обёртки. Существующий публичный контракт функции не изменён.

Добавлен `tests/test_superagent_scheduler_install_race.py`: 12 параллельных установок должны вернуть один метод, а `_ORIGINAL_EXECUTE` должен ссылаться на исходный метод. Тест не запускался согласно ограничению владельца; выполнена только статическая проверка и read-back GitHub. Исправление не обеспечивает вытеснение уже выполняющегося backend и не считается релизом до интеграции в `main`.
