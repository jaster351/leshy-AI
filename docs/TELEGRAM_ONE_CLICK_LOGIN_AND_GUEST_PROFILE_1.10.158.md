# Telegram-подтверждение входа и профиль пользователя Лешего

Релиз 1.10.158. Сервис продолжает работать **по LAN-IP за NAT, без публичного домена**.

## Гостевой Web и непрерывная переписка

- Без Telegram/Google/Apple/VK пользователь может сразу общаться с Лешим.
- Сервер выдаёт каждому браузеру постоянный локальный UUID и HttpOnly cookie; чаты/память других браузеров не смешиваются. Гостевой профиль восстанавливается после перезагрузки и обычного перезапуска браузера, пока cookie сохранён.
- Когда пользователь подтверждает Telegram-вход в новом браузере, уже созданные гостевые диалоги и память этого браузера переносятся к тому же owner UUID, к которому привязан Telegram.
- При отключении cookie или полной очистке браузерных данных сервер не может угадать, кто был гостем, по IP: регистрация/привязка Telegram или код с уже подключённого устройства нужны для восстановления.

## Вход по кнопке

1. Web → Настройки → Профиль → **Войти через Telegram**.
2. Леший выдаёт временную ссылку `https://t.me/<bot>?start=auth_<random>` и отображает короткий код проверки (не секрет авторизации).
3. Пользователь открывает бота по ссылке. Бот отвечает **только в личном чате** с двумя inline-кнопками: «Подтвердить вход» / «Отменить».
4. Пользователь проверяет одинаковый код в браузере и боте. Только нажатие подтверждения с учётной записи Telegram ID завершает вход.
5. Браузер опрашивает свой локальный Web-сервер (не Telegram callback), получает подтверждение и загружает профиль.

Токены случайные, одноразовые, хранятся в SQLite в виде SHA-256, живут 5 минут и привязаны к Web cookie. Перезапуск Лешего не должен создавать прав на повторное использование старого токена; истечение времени и повторный callback отклоняются.

**Telegram ID не является правом администратора Лешего.** Telegram-вход даёт доступ только к связанным диалогам владельца учётной записи. Привилегированные команды продолжают проверяться старой отдельной owner policy.

## Имя, фото, сведения

- После подтверждения Леший получает от Bot API имя, фамилию, username, язык и неизменяемый Telegram user ID. Эти поля помещаются в локальный профиль.
- Аватар загружается с Telegram через существующее соединение бота / настроенный Telegram proxy. Бот-токен и Telegram file URL браузеру не передаются; Web получает изображение через защищённый cookie эндпоинт `/v1/identity/telegram/avatar` с локальным кэшем.
- Нижний левый блок Web (#profileMenuButton) отображает имя и фотографию пользователя вместо «Леший». Для гостя отображается «Гость» и локальный значок. Если фотография недоступна, используется первая буква имени.
- Общая модель профиля содержит ключ `provider`, поэтому Google/Apple/VK можно подключить в будущем после реализации и проверки OAuth; до тех пор они не выдают авторизацию, имя или права.

## Никаких внешних входящих подключений

Леший получает сообщения Telegram Bot API через polling и сам обращается к Telegram API и локальному хранилищу. NAT port forwarding, webhook, внешний HTTPS-домен или сторонний промежуточный сервер **не нужны**.

## Ограничения

- Для связи с Telegram нужен интернет и работающий Telegram bot token.
- По HTTP в недоверенной LAN cookie и запросы могут быть перехвачены; на недоверенных сетях используйте HTTPS.
- Перенос гостевых данных зависит от исправного локального хранилища, и для кластерного Web-входа на разных узлах отдельно требуется синхронизация owner mappings и истории.
- Проверки кода и тесты не являются подтверждённым E2E на пользовательских Windows/Linux/macOS.
