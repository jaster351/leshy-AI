# Временная блокировка опасных действий Browser Agent

Статус: **защитный fail-closed патч; без E2E-проверки**.

В `main` вызов `BrowserAgent.execute(action, approved=True)` обходил Human Approval Gate: вызывающий код сам мог выставить булев флаг, после чего адаптер получал `_approval_verified=True`.

Этот патч **временно запрещает** все `MUTATE`, `COMMIT`, `FINANCIAL` независимо от `approved`. Существующий `READ` остаётся доступным. Это осознанное временное ограничение функциональности: покупки, бронирования и отправка форм через BrowserAgent не заработают до внедрения настоящего серверного подтверждения.

Следующий этап: добавить серверный одноразовый grant с проверенным owner UUID, session ID, каноническим payload, TTL, атомарным consume и защитой от replay; провести проверку маршрутов Web/Telegram/API, исключить использование пользовательских полей как доказательства подтверждения. Только после этого заменить временный отказ проверкой grant и восстановить опасные действия.

Добавлены тесты на игнорирование legacy `approved=True`, поддельный `_approval_verified` и сохранение READ. Локальные сборки и тесты не запускались по запрету владельца. Существующий внешний CI нельзя считать успешным без фактических шагов runner. До подтверждённых E2E и read-back в `main` **не считать уязвимость полностью устранённой**.
