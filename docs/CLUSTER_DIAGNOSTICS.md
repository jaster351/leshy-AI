# Диагностика LAN-кластера Лешего

## Где смотреть

Откройте **Настройки → Распределённые вычисления → Диагностика кластера**.

Панель обновляется каждые 15 секунд, когда видна на экране. Кнопка
**Проверить сейчас** запрашивает данные без перезагрузки страницы.

Отображаются:

- версия запущенного Лешего;
- состояние переключателей «Кластер» и «Автообнаружение LAN»;
- `cluster_id` (отпечаток общего секрета, но не сам секрет);
- уникальный `node_id` компьютера;
- адрес локального узла и TCP-порт API;
- состояние UDP-приёмника `38765` и число увиденных узлов;
- список доверенных соседей, их ресурсы и последнее объявление;
- число активных распределённых задач, счётчики принятых и отклонённых
  сетевых объявлений, диагностические подсказки.

Подробный ответ доступен локально по авторизованному API:

```text
GET http://127.0.0.1:8765/v1/cluster/diagnostics
```

Общий статус по-прежнему доступен через:

```text
GET http://127.0.0.1:8765/v1/cluster/status
```

Информация о LAN-адресах и узлах **не включается в публичную агрегированную
статистику**. Секреты кластера не передаются в диагностическом JSON.

## Управление

Переключатель **Кластер** управляет действующим модулем
`distributed-cluster`. Выключение завершает фоновый обмен и очищает
список удалённых узлов; генерация обычного чата продолжает работать.

Переключатель **Автообнаружение LAN** отдельно управляет UDP-discovery
и действует без перезапуска Лешего. Его состояние сохраняется в
локальной таблице настроек `meta` для следующего старта.

Встроенные API управления:

```text
POST /v1/modules/toggle
{"name":"distributed-cluster","enabled":true}

POST /v1/cluster/autodiscovery
{"enabled":true}
```

Для изменений требуется та же авторизация, что для остальных локальных
настроек Лешего.

По умолчанию автообнаружение включено для совместимости с предыдущими
версиями; использовать кластер можно только с доверенными компьютерами.

## Консоль

В консоли Лешего, запущенного через веб-сервер или Windows launcher,
работает отдельный монитор текущего состояния. Он проверяет состояние
каждые 5 секунд и печатает строку при изменении готовности модели,
прогресса её скачивания, активности генерации, очереди или числа узлов.
Даже если ничего не меняется, каждые 30 секунд появляется строка
с отметкой времени, версией и временем работы. Поэтому отсутствие
новых сообщений журнала больше не выглядит как зависание.

Монитор не показывает текст сообщений, пользовательские идентификаторы
или секреты. Ошибки загрузки модели отображаются кратко; полные трассировки
остаются в файлах LeshyBrain/logs. Он не выбирает главный компьютер
и не изменяет настройки кластера.

При включении и выключении, изменении числа узлов и обнаружении новой
причины сбоя Леший дополнительно печатает события с **текущей версией**, например:

```text
[Леший 1.10.78] Кластер: ВКЛ | узел ... | cluster_id ... | UDP 38765: автопоиск
[Леший 1.10.78] Кластер: 2 узл. | автообнаружение ВКЛ | задач в работе 0
```

Пять секунд — интервал фонового обновления, **но одинаковые сообщения
каждые пять секунд не печатаются**. Для полной диагностики используйте API
или вкладку настроек.

## Однократное сопряжение двух доверенных компьютеров

Автоматическое обнаружение (UDP 38765) **не равно автоматическому доверию**.
При первой установке каждый компьютер генерирует свой секрет и уникальный
идентификатор. Поэтому первый запуск показывает `other_cluster`, даже если
пакеты между ПК прекрасно проходят.

Для одной локальной сети без центрального сервера используйте однократное
доверенное сопряжение. После него повторное обнаружение и регистрация
узлов происходят автоматически после каждой перезагрузки, если оба узла
запущены и сеть доступна.

1. На **первом доверенном ПК** выполните локально:

   ```powershell
   $status = Invoke-RestMethod http://127.0.0.1:8765/v1/status
   Join-Path $status.brain_dir 'cluster\cluster-secret.txt'
   ```

   Передайте указанный файл **по защищённому каналу** (например, USB).
   Не публикуйте содержимое секрета в чат или по незащищённому HTTP.

2. На **ПК №2** остановите Лешего и запустите из корня репозитория:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\windows\Join-LeshyCluster.ps1 -SecretFile E:\cluster-secret.txt
   ```

   Сценарий сам выбирает активное хранилище `dist\Leshy\LeshyBrain`
   для Windows-сборки, сохраняет резервную копию прежнего секрета
   и **не заменяет** `node-id.txt`. Если Вы запускаете напрямую
   `python -m leshy.web_server`, укажите `-BrainDir .\LeshyBrain`.

3. Перезапустите Лешего. Сравните `cluster_id` на двух ПК через
   `GET /v1/cluster/diagnostics`: он должен совпадать, `node_id` —
   различаться. Для обмена нужны UDP 38765 и TCP 8765 из доверенной
   локальной сети. Следите за `peer_count` и `cluster_task_delegated`.

Если задана `LESHY_CLUSTER_SECRET`, именно она имеет приоритет над файлом:
сценарий предупредит об этом и не будет создавать видимость сопряжения.

**Почему не соединяем все установки автоматически?** Иначе любой чужой
компьютер в Wi-Fi мог бы получить доверие и вычислительные задачи без
разрешения владельца. Первичное доверие должно быть осознанным,
а повседневное переподключение — полностью автоматическим.

## Почему один компьютер не видит другой

1. Если счётчик `other_cluster` растёт, обнаружены объявления с другим
   `cluster_id`: обычно у машин разные `cluster-secret.txt`. Для
   доверенного кластера секреты должны совпадать.
2. Если `same_node_id` растёт **от другого IP**, у обеих установок,
   вероятно, скопирован `node-id.txt`. На каждой машине этот файл должен
   быть своим.
3. Если нет принятых и отклонённых объявлений, проверьте локальную сеть,
   клиентскую изоляцию Wi-Fi, VLAN и Windows Firewall для `38765/UDP`.
4. Даже если узел обнаружен, для передачи заданий нужен `8765/TCP`
   (или указанный пользователем другой порт Лешего).
5. Счётчики отражают обнаружение узлов, **не факт ускорения генерации**.
   Для подтверждения распределённых заданий ищите события
   `cluster_task_delegated` и `multi_agent_finished` в журнале.

Не копируйте целиком `LeshyBrain` между работающими узлами. Файлы
`node-id.txt`, Windows DPAPI и учётные данные должны оставаться локальными.

## Проверка без сборки

Код внесён в исходный репозиторий. Компиляция, автотесты и проверка на
действующих компьютерах выполняются отдельно пользователем. До локальной
сборки новая панель на компьютерах не появится.
