# Жёсткий бюджет контекста LLM

Леший проверяет размер prompt непосредственно перед каждым вызовом локального LLM backend. Ограничения количества сообщений недостаточно: system-инструкции, память, RAG, веб-результаты и длинная текущая реплика могут превысить окно модели.

Бюджет вычисляется отдельно для фактически выбранного backend по его `n_ctx`, а из окна заранее резервируется `max_tokens` под ответ. При failover бюджет пересчитывается заново, поэтому переход с Vulkan 4096 на OpenVINO 2048 не отправляет в меньший backend прежний слишком большой prompt.

Сначала удаляется менее релевантная старая история. Сохраняются основной системный контракт и последние реплики. Текущая пользовательская цель не удаляется; в крайнем случае очень длинная реплика сокращается с сохранением её конца, где обычно расположен непосредственный вопрос. Избыточные RAG/system-блоки удаляются до обращения к backend.

При компактизации пишется событие `llm_context_compacted`: backend, `tokens_before`, `tokens_after`, `budget`, число удалённых и сокращённых сообщений.

Текущая оценка токенов намеренно консервативна и не требует внешнего tokenizer. Следующий этап — tokenizer конкретной GGUF-модели, когда runtime сможет предоставить его без тяжёлой обязательной зависимости.

Regression `tests/test_context_budget.py` проверяет длинную историю для 4096-token backend, повторное уменьшение prompt при failover на 2048-token backend и сохранение текущей пользовательской/reply-цели при малом окне.

## Автопродолжение оборванного ответа

Пользователь не должен вручную писать «продолжай» после обычного технического лимита генерации. Потоковый native llama.cpp backend отслеживает `finish_reason`. При `finish_reason=length` Леший автоматически делает внутренний запрос продолжения на том же backend и дописывает результат в тот же логический ответ.

Есть консервативная проверка очевидного логического обрыва на случай, если backend не передал причину завершения: незакрытый Markdown code fence, окончание на запятую/двоеточие/открывающую скобку или на служебное слово-связку после достаточно длинного ответа. Обычный законченный ответ с `finish_reason=stop` не получает лишнего продолжения.

Для продолжения передаётся компактный хвост уже сгенерированного текста и инструкция продолжить ровно с места обрыва без нового вступления и повторения. Совпадающий хвост на стыке удаляется. Защитный предел — шесть внутренних продолжений подряд. Diagnostics фиксирует `accelerator_stream_auto_continue`, `accelerator_stream_auto_continue_stopped` и `accelerator_stream_auto_continue_limit`.

Regression `tests/test_streaming_auto_continue.py` проверяет автоматическое продолжение после `finish_reason=length`, отсутствие лишнего запроса после нормального `stop`, эвристику очевидного обрыва и удаление повтора на стыке частей.
