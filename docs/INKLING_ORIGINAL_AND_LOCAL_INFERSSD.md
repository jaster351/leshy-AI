# Inkling 2 Mini (оригинал) и локальная технология InferSSD

Оригинал: https://huggingface.co/thinkingmachines/Inkling-2-Mini
Технология SSD streaming: https://github.com/wici-ai/inferssd

## Важно: это два разных механизма

- Оригинальный Inkling 2 Mini распространяется в формате Safetensors (NVFP4/MXFP8). Для него создан отдельный загрузчик полного checkpoint и экспериментальная попытка Transformers/Accelerate disk-offload. Это не InferSSD, совместимость на RTX 3070 Laptop не подтверждена.
- WiCi InferSSD — механизм индексирования, выборочной загрузки и предвыборки MoE-экспертов из SSD в RAM/VRAM. Его движок работает с поддерживаемыми GGUF MoE, а не с оригинальным checkpoint Safetensors. Inkling 2 Mini пока нет в официальном списке протестированных GGUF InferSSD.
- Использование удалённой видеокарты и вычисления по Wi-Fi категорически не предусмотрены.

## 1. Скачать оригинал на SSD (Windows)

В корне репозитория Лешего выполните:

```powershell
.\windows\Prepare-InklingOriginal.ps1 -Download
```

Скачивает оригинальный snapshot Hugging Face (веса, конфигурацию, процессор, токенизатор) рядом с установленным Лешим в `dist\Leshy\LeshyBrain\models\Inkling-2-Mini-original`, а файлы SSD offload размещает в `dist\Leshy\LeshyBrain\offload\Inkling-2-Mini`. Если установленная сборка отсутствует, используется `LeshyBrain` в корне репозитория. Для нестандартной установки можно явно указать `-BrainDir 'C:\путь\к\LeshyBrain'`. Старые пути `LESHY_INKLING_MODEL_DIR` и `LESHY_SSD_OFFLOAD_DIR` в окружении пользователя переписываются на эти каталоги. Прерванная загрузка использует HF cache; активная GGUF не заменяется.

При региональном `403` или сетевой ошибке загрузчик сначала пробует прямое соединение, затем существующие пользовательские прокси HTTP CONNECT `vpn.nidr.cyberhost.biz:7777` и `vpn.usa.cyberhost.biz:7777`. При необходимости пользователь может указать `LESHY_HF_PROXY_URL` (полный HTTP(S) proxy URL), который будет первым резервным вариантом. Прокси применяются **только к дочернему процессу скачивания Hugging Face**, включая hf_xet; локальный чат/InferSSD остаются на loopback. Если ни один маршрут не позволяет загрузить модель, инструмент сообщает о реальном `403`, а не помечает модель установленной.

Скрипт создаёт отдельную виртуальную среду `LeshyBrain/runtime/inkling-original-venv` (Python 3.11) и устанавливает туда зависимости. Он больше не обновляет глобальные `click`, `huggingface_hub` и другие пакеты, необходимые браузеру Лешего. Пакеты, ранее изменённые в глобальном Python старым скриптом, автоматически не откатываются.

Статус без повторной загрузки:

```powershell
.\windows\Prepare-InklingOriginal.ps1
```

## 2. Экспериментальный original-format SSD offload

```powershell
.\windows\Prepare-InklingOriginal.ps1 -InstallInference
$env:LESHY_INKLING_RAM_GIB = '8'
$env:LESHY_INKLING_VRAM_GIB = '6'
$env:PYTHONPATH = (Join-Path (Get-Location) 'src')
py -3.11 -m leshy.inkling_original ask --question 'Как Вас зовут?'
```

Проверка не гарантирует успешное размещение mixed NVFP4/MXFP8 оригинала на 8 ГБ VRAM; при нехватке памяти или неподдерживаемом формате должна выводиться реальная ошибка. После успешного вывода можно включить экспериментальный backend: `.\windows\Prepare-InklingOriginal.ps1 -Activate`. Windows-сборка запускает отдельный локальный Python sidecar: torch/transformers не требуется в самом PyInstaller EXE. Препаратор ставит только Python-модуль Лешего в внешний Python 3.11; зависимости ML устанавливаются флагом -InstallInference. При отказе оригинала fallback GGUF остаётся. Работа на RTX 3070 не подтверждена.

## 3. Реальный InferSSD для поддерживаемых GGUF MoE

Установите официальный Windows CLI из releases/README https://github.com/wici-ai/inferssd. Для выбранной GGUF-модели из каталога Лешего, поддерживаемой установленным InferSSD, можно включить:

```powershell
[Environment]::SetEnvironmentVariable('LESHY_LLM_BACKEND', 'inferssd', 'User')
```

По желанию укажите LESHY_INFERSSD_EXECUTABLE как полный путь к inferssd.exe. Леший запускает процесс inferssd serve только локально на 127.0.0.1, использует совместимый с OpenAI API протокол и при недоступности движка возвращается к штатному llama.cpp. Журнал: LeshyBrain/logs/inferssd-local.log.

InferSSD выбирает экспертов и организует SSD/RAM/VRAM-кэши сам: Python-код не имитирует этот механизм. Реальная скорость зависит от NVMe, PCIe, поддерживаемой GGUF MoE, CPU/GPU и расхода памяти. **Статус процесса не является доказательством**, что потоковая подгрузка экспертов действительно началась. При выключении режима верните `LESHY_LLM_BACKEND=native` и перезапустите Лешего.

## 4. Два узла: компьютер и сервер с собственными NVMe

**Каждый узел кластера Лешего использует свой локальный NVMe.** Доступ к диску другого узла через SMB/NFS/SSH не превращает его в расширение локальной VRAM, а подгрузка весов по сети не является заменой локальной NVMe. Конфигурация индивидуальная для каждого процесса Лешего; общая модель и знания кластера не означают общий физический кэш.

В Linux сначала определите фактическую точку монтирования NVMe (ничего не форматируя и не перемонтируя):

```bash
lsblk -o NAME,TYPE,TRAN,SIZE,MOUNTPOINTS
findmnt -T /path/to/your/nvme
df -h /path/to/your/nvme
```

Выберите **уже существующий** локальный путь к протестированной MoE GGUF (или первому shard из полного набора). Пример для Linux-сервера, подставьте свой реальный путь и установите переменные в окружение службы Лешего:

```bash
export LESHY_LLM_BACKEND=inferssd
export LESHY_INFERSSD_GGUF_PATH=/path/to/nvme/models/first-model-shard.gguf
# Optional, if the native executable is not on PATH:
# export LESHY_INFERSSD_EXECUTABLE=/path/to/inferssd
```

На Windows узле, если поддерживаемая GGUF лежит на другом **локальном** NVMe, аналогично используется `LESHY_INFERSSD_GGUF_PATH` с полным Windows-путём. По умолчанию старый путь `LeshyBrain/models/Qwen3-8B-Q4_K_M.gguf` не меняется; переключение на InferSSD только по явной настройке. Qwen3 8B — dense-модель, поэтому ей не нужна потоковая подгрузка MoE-экспертов. Наличие NVMe само по себе не делает модель MoE.

Для **оригинального Safetensors Inkling** на Linux-сервере вместо InferSSD используются существующие параметры `LESHY_INKLING_MODEL_DIR` и `LESHY_SSD_OFFLOAD_DIR`, которые можно направить на локальный NVMe; это обычный Transformers/Accelerate offload и работает лишь при совместимых весах и движке. SSD не добавляет физическую VRAM. Рабочая загрузка оригинала на сервере пока не подтверждена.

Официальный InferSSD предоставляет `inferssd serve -m /path/to/model.gguf` для Linux и готовый Windows-пакет; фактическая поддержка конкретной версии системы и драйверов определяется установленным релизом. Леший использует только локальный API `127.0.0.1`, никогда не открывая его наружу автоматически. Сведения: https://github.com/wici-ai/inferssd/blob/main/docs/quickstart.md .


## 5. Автоматическая подготовка при обновлении Лешего

**Вручную вводить команды подготовки не требуется.** Уже установленное задание
`Leshy AI - Git Build (15 min)` автоматически обновляет `main`, собирает и
публикует приложение. После успешной публикации оно регистрирует (один раз) и
запускает отдельное задание Планировщика
`Leshy AI - Model Provision (automatic)`. Оно выполняется независимо от
сборки: скачивание многогигабайтной модели не задерживает следующую проверку GitHub.

Windows-этап автоматически:

1. Пытается установить официальный нативный InferSSD из закреплённого релиза
   `261119.309`, если исполняемого файла ещё нет. Используется скачанный
   и запускаемый upstream PowerShell-установщик; при недоступном GitHub ошибка
   фиксируется в журнале, **обновление Лешего не отменяется**.
2. На том же компьютере, где установлен Леший, готовит исходные файлы
   `LeshyBrain/models/Inkling-2-Mini-original` и
   `LeshyBrain/offload/Inkling-2-Mini`, при необходимости через
   пользовательский HTTPS-прокси или проверенный резервный маршрут.
   До загрузки требуется не менее 45 ГиБ свободного места.
3. Использует отдельное Python-окружение `runtime/inkling-original-venv`,
   **не устанавливая весь пакет leshy-ai в это окружение**. После успешной
   загрузки оригинала туда же устанавливаются зависимости его инференса.
4. При сбое записывает причину и повторяет этап после паузы, не создавая
   параллельных больших загрузок.

Состояние: `LeshyBrain/runtime/model-provision/*.json`.
Журнал: `LeshyBrain/logs/model-auto-provision.log` (предыдущий журнал
ограничивается по размеру).

В Linux обновление, выполняемое через `linux/build.sh`, после восстановления
`LeshyBrain` запускает `linux/auto-prepare-models.sh` в отдельном процессе.
При наличии системных инструментов скрипт устанавливает официальный InferSSD
для Linux и подготавливает оригинальный Inkling на **локальном диске узла**.
Журнал: `LeshyBrain/logs/model-auto-provision-linux.log`. Для Linux требуется
реальный запуск обновления на самом сервере; изменение исходников в GitHub
само по себе не устанавливает на сервер программы.

**Ни один из подготовительных этапов не переключает автоматически действующую
Qwen3**, её режим рассуждений или сетевую маршрутизацию. Установка InferSSD
не означает, что выбрана совместимая MoE GGUF; оригинальный Inkling
использует иной механизм SSD offload. Запуск и измерение реального
инференса на каждом узле остаются необходимыми для подтверждения результата.

## 6. Проверяемая MoE-модель для настоящей подгрузки с NVMe

Одной установки InferSSD недостаточно: текущая Qwen3 8B — плотная модель,
а оригинал Inkling 2 Mini — Safetensors и не использует WiCi expert streaming.

После обновления фоновый подготовитель теперь дополнительно загружает
**Qwen3.6-35B-A3B UD-Q4_K_XL GGUF** — проверенный производителем InferSSD
вариант MoE (примерно 22,4 ГБ). Источник:
https://huggingface.co/unsloth/Qwen3.6-35B-A3B-GGUF
и список поддерживаемых GGUF:
https://github.com/wici-ai/inferssd#models .

Загрузка идёт через тот же прямой/прокси маршрут, что и оригинальная
Inkling. Хранение по умолчанию на **NVMe текущего узла**:
`LeshyBrain/models/InferSSD-Qwen3.6-35B-A3B/Qwen3.6-35B-A3B-UD-Q4_K_XL.gguf`.
Для другого **локального** NVMe можно заранее указать
`LESHY_INFERSSD_MODEL_DIR`. Независимый Xet/HF-кэш MoE размещается на
том же диске. Для нового скачивания необходимо не менее 45 ГиБ
свободного места. Проверяются формат заголовка GGUF, размер, локальная
SHA-256 и опубликованная LFS SHA-256, если она доступна.

Когда включён backend `inferssd`, но отдельный
`LESHY_INFERSSD_GGUF_PATH` не задан, Леший сам найдёт подготовленную и
валидированную GGUF-модель. Наличие GGUF **не включает** новый backend
само по себе: Qwen3 8B остаётся рабочей до реального тестирования
инференса на оборудовании.

На Windows этап записывается в
`LeshyBrain/runtime/model-provision/moe.json`,
журнал — `LeshyBrain/logs/model-auto-provision.log`;
на Linux — в `LeshyBrain/logs/model-auto-provision-linux.log`.

**Безопасное обновление Linux:** `linux/build.sh` собирает приложение
в `.autobuild/linux-package-dist`, проверяет его *до* замены рабочей
версии и публикует программные файлы с возможностью отката.
`dist/Leshy/LeshyBrain` больше не перемещается во время компиляции:
скачивание и кэш на NVMe сохраняют постоянный путь. Если установка
новой программы не удалась, восстанавливается прежняя программа,
а каталог данных не затрагивается.

Стадия «модель скачана» означает наличие файлов, но **не** подтверждает
скорость или работоспособность InferSSD на конкретной GPU/CPU.
Без отдельного успешного запуска нейросети статус
`ssd_streaming_verified` остаётся отрицательным.

## 7. Проверка настоящей SSD-подгрузки, без подмены результата

Обычный ответ `/v1/models` либо запуск процесса InferSSD **не доказывают**
чтение MoE-экспертов с NVMe. Леший теперь проверяет только **нормализованные
нативные события того же запуска**. Ищет в каталоге текущего InferSSD
`state/runs/*/native-events.jsonl` с контрактом телеметрии версии 1:

- `ssd.controller.begin` со `schema=1`;
- успешную `ssd.place.layer`, в которой реально выбраны MoE-эксперты;
- положительный `ssd.prefill.layer.read_bytes`, т.е. подтверждённые
  байты чтения через нативный SSD executor;
- файл `runtime.json` того же запуска должен ссылаться на точно тот же
  локальный GGUF-путь (`-m`/`--model`), а время наблюдения — не старше суток.

Если доказательств нет, `ssd_streaming_verified=false`. Настоящая
положительная проверка появится **лишь после успешной обработки запроса
через InferSSD на конкретной машине**. Результаты не подменяются
синтетическими показателями и не копируются с другого узла.

На Windows официальный установщик размещает движок в
`LeshyBrain/runtime/inferssd`, а резервно поддерживается прежний путь
`%LOCALAPPDATA%/inferssd`. Леший теперь передаёт нативному
`inferssd.exe` необходимые `INFERSSD_HOME` и `INFERSSD_RESOURCES`,
которые обычно выставляет официальный `inferssd.cmd`. Так нет вызова
`cmd.exe` с пользовательским именем файла.

На Linux установщик размещает движок в
`LeshyBrain/runtime/inferssd` и использует локальные бинарники узла.
Данные `LeshyBrain`, включая движок, модели и Xet-кэш, переживают
обновление основного приложения.

После запуска автоматической подготовки каждый узел записывает единый
копируемый JSON-отчёт:
`LeshyBrain/runtime/model-provision/storage-health.json`.
В нём указаны пути к оригиналу Inkling, MoE GGUF, свободное место на
соответствующих дисках и `ssd_streaming_verified` с источником
подтверждения. Создание отчёта само по себе не запускает модель и не
переключает текущую Qwen3.

Основа контракта событий:
https://github.com/wici-ai/inferssd/blob/main/docs/architecture/native-observations.md
