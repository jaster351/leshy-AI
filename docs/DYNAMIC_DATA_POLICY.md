# Политика статических и динамических данных

Леший обязан различать долгоживущие и динамические данные.

Для динамических данных (погода, курсы валют, новости, расписания, цены, версии ПО, статусы сервисов, текущие должностные лица, результаты событий и другие быстро меняющиеся факты) ответ должен по умолчанию опираться на актуальный внешний источник при наличии сети.

Каждая сохранённая динамическая запись должна иметь источник, `checked_at`, класс свежести и TTL/политику инвалидации. Устаревшее сохранённое значение нельзя выдавать как текущее без повторной проверки. Если live-проверка недоступна, Леший должен явно сообщить время последней успешной актуализации.

Запросы с маркерами «сейчас», «сегодня», «последний», «актуальный», «текущий», «погода», «курс», «цена», «расписание», «новости» и аналогичными повышают приоритет live-проверки.

Это правило действует для Web, Windows/desktop, Telegram, API и будущих интерфейсов.
