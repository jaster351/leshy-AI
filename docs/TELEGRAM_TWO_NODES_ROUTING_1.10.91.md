# Два независимых экземпляра Лешего и Telegram: диагностика 08.11.2026 (1.10.91)

По логу ПК1 с локальной сборкой 1.10.90 подтверждены **две независимые инсталляции** в общей сети. Они могут дать разные ответы на одно сообщение пользователя — это не повторный sendMessage одной машины.

## Что исправлено

- «Вы же друг друга видите в чате, да?» (18:08) и «Попробуйте поговорить с самим собой» (18:09) ошибочно выполняли live_search из-за наличия только candidate-знаний. Теперь обращения к двум экземплярам, локальные инструкции и короткие разговорные запросы обрабатываются локально, без поиска; явная просьба проверить интернет остаётся сетевой.
- «Помогите найти фильм Одиссея Нолана» (18:11) ошибочно обрабатывалось обработчиком **кинотеатральной афиши** из-за одного слова «фильм». Теперь сведения об отдельном фильме ищутся обычным маршрутом. Расписание кинотеатров остаётся специализированным запросом при явном контексте кинотеатра или сеанса.
- Синхронный чат также не запускает восстановительный поиск по фразам, специально отмеченным как локальные. Добавлены регрессионные сценарии.

## Важное ограничение Telegram Bot API

В журнале ПК1 зарегистрировано 151 событие `telegram_poll_failed` с `HTTP 409 Conflict: terminated by other getUpdates request`. Это **не дубли сообщений одного компьютера**, а конфликт двух долгих опросов `getUpdates` под **одним токеном Telegram-бота**.

Две независимые машины могут отправлять сообщения тем же ботом, но два независимых poller одного токена мешают друг другу: доставка update произвольно перехватывается одним экземпляром. Сообщения, отправленные самим Telegram-ботом, не превращаются автоматически во входящие события для этого же бота. Поэтому фраза «поговорите друг с другом» **не реализует межузловой диалог через Telegram сама по себе**.

Надёжный режим двух разных отвечающих узлов потребует отдельной архитектуры: **один Telegram poller -> fan-out в cluster peer API -> два независимых ответа с атрибуцией конкретного узла**, либо два отдельных Telegram-бота с разными токенами. Этот PR **не отключает** ни одну машину, не меняет токены и не затрагивает отправку их сообщений, чтобы сохранить поведение пользователя.

## Приёмка после сборки пользователем

- «Вы же друг друга видите в чате, да?», «Как себя чувствуешь?», «Попробуйте поговорить с самим собой» — **без** `live_search_started`; при этом модель не должна утверждать, что автоматически читает сообщения другого узла без подтверждённого канала.
- «Помогите найти фильм Одиссея Нолана» — поиск фильма, **не** поиск сегодняшней афиши, сеансов и билетов.
- «Какие сеансы фильма Одиссея?» — контекст кинотеатра допускается.
- «Проверь в интернете последние новости» — поиск обязателен.
- Два экземпляра под одним токеном продолжат давать `HTTP 409` до отдельного исправления транспортной архитектуры.

Сборка и автотесты не запускались. LeshyBrain, секреты и пользовательские данные не изменены.
