# Безопасность Telegram при системном прокси

При отключённом пользовательском Telegram-прокси транспорт сохраняет системные настройки HTTP(S)-прокси и обязательную проверку TLS, включая дополнительный `LESHY_TELEGRAM_CA_BUNDLE`. При этом переход по HTTP 301/302/307/308 запрещён: URL Telegram Bot API содержит секретный токен.

Ветвь с явно настроенным HTTP/SOCKS5-прокси уже использует `_NoRedirects`. Изменение добавляет аналогичную защиту для системного маршрута без переключения на CPU, отключения прокси или TLS.

## Проверка перед включением в main

Добавлены регрессионные тесты на системный маршрут, отказ при redirect и отсутствие токена в тексте исключения. Сборки и тесты не запускались по требованию владельца. Перед интеграцией требуется статически проверить вызывающие обработчики HTTP 429/Retry-After и исключения, а при разрешении — выполнить end-to-end тест с системным прокси, пользовательским CA и скачиванием фото/голоса. Нельзя считать изменение полностью проверенным до runtime-проверки.

Отдельная задача: исключить URL с bot token из любых HTTPError/URLError и логов, сохранив `HTTPError.code`, `headers` и `Retry-After`.
