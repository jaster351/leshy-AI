# Browser Agent Лешего

Browser Agent — единый слой действий Лешего в интернете. Он не является вторым AI-ассистентом и не заменяет LeshyBrain: планирование, память и диалог остаются в ядре Лешего.

## Архитектура

Целевая цепочка: `LeshyBrain -> Planner -> Browser Agent -> адаптер -> браузер -> Verifier`.

Основной интеллектуальный адаптер: Browser Use. Детерминированный исполнительный фундамент: Playwright. MCP поддерживается как дополнительный стандартный интерфейс для внешних инструментов, но не является обязательным для локальной работы.

Существующие browser-skills на Playwright сохраняются и постепенно переводятся на общий интерфейс Browser Agent.

## Безопасность

Все browser-действия классифицируются по риску:

- `read` — чтение, поиск и сравнение; может выполняться автоматически;
- `mutate` — изменение данных/заполнение и отправка форм; требует подтверждения;
- `commit` — бронирование, публикация, оформление заказа и другие внешние обязательства; требует подтверждения;
- `financial` — оплата, перевод, покупка и другие финансовые действия; всегда требует явного подтверждения пользователя.

Human Approval Gate находится над адаптерами. Поэтому Browser Use, Playwright, MCP или будущий Skill не могут обойти правило подтверждения.

Browser Agent поддерживает allowlist доменов. Перенаправление на неподтверждённый домен должно блокироваться до выполнения действия.

CAPTCHA и проверки присутствия человека не обходятся скрытно: управление возвращается пользователю.

## Следующие этапы

1. Адаптер существующих Playwright browser-skills к `BrowserAgent`.
2. Опциональный адаптер Browser Use с локальной LLM и локальным браузером.
3. MCP Tools Gateway и реестр устанавливаемых Skills.
4. UI подтверждения: действие, сайт, сумма/условия, `Подтвердить` / `Отмена`.
5. Verifier результата и журнал аудита.
6. E2E-тесты покупок/бронирований на тестовых сайтах без реальных платежей.

Внешние зависимости должны быть опциональными: отсутствие Browser Use или MCP не должно ломать основной чат Лешего.
