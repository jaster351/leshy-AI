# Browser Agent Лешего

Browser Agent — рабочий слой действий Лешего в интернете. Он не является вторым AI-ассистентом и не заменяет LeshyBrain: личность, память, диалог и выбор цели остаются в ядре Лешего.

## Что реализовано

Рабочая цепочка: `LeshyBrain -> BrowserPlatform -> BrowserAgent -> Browser Use / Playwright -> браузер`.

- **Browser Use** выполняет семантическое исследование сайтов и динамические браузерные задачи.
- **Playwright** выполняет детерминированные workflow и остаётся фундаментом существующих browser-skills.
- **LeshyBrowserUseLLM** подключает родную локальную `LLM.chat()` Лешего к Browser Use без обязательного OpenAI/Ollama или другого платного API.
- Системный Edge/Chrome/Chromium используется с отдельным профилем Лешего и сохранением browser state.
- Естественные запросы о товарах, билетах, гостиницах и бронированиях маршрутизируются в Browser Platform.
- Web UI показывает одноразовое подтверждение перед внешним обязательством или оплатой.

Первое сообщение вида «купи iPhone» или «забронируй отель» **не совершает покупку**. Леший сначала ищет и сравнивает варианты. После выбора (`купи первый`, `забронируй вариант 2`) создаётся отдельное подтверждение.

## Human Approval Gate

Действия делятся на уровни риска:

- `read` — поиск, чтение, сравнение: может выполняться автоматически;
- `mutate` — изменение данных: требует подтверждения;
- `commit` — заказ, бронирование, публикация и другое внешнее обязательство: требует подтверждения;
- `financial` — списание денег: отдельное явное подтверждение, включая сумму и валюту.

Approval одноразовый, привязан к владельцу и действует ограниченное время. Он намеренно не сохраняется на диск: после перезапуска старое разрешение невозможно повторно использовать.

Browser Use получает внутренний `_approval_verified` только после прохождения Human Approval Gate. Финансовый адаптер дополнительно требует `approval_summary`; изменение суммы, валюты, получателя, количества или дополнительных услуг после подтверждения запрещено.

## Доменная изоляция и CAPTCHA

Browser Use и Playwright получают allowlist доменов. Переход/редирект за его пределы блокируется.

CAPTCHA, challenge и 2FA не обходятся скрытно. Browser Agent останавливается и возвращает управление человеку.

Пароли, cookies, CVV, токены и другие секреты нельзя включать в публичные approval-данные и диагностический результат.

## Web API

Runtime `web_server_impl8` добавляет защищённые API:

- `GET /v1/browser/approvals` — ожидающие подтверждения;
- `POST /v1/browser/approvals/resolve` — одноразовое подтвердить/отменить;
- `POST /v1/documents/convert` — локальный Document Intelligence;
- `GET /v1/tools/extensions` — установленные MCP/Skills;
- `POST /v1/tools/extensions/inspect` — просмотр разрешений до установки;
- `POST /v1/tools/extensions/install` — подтверждённая изолированная установка;
- `POST /v1/tools/extensions/uninstall` — подтверждённое удаление;
- `POST /v1/tools/call` — вызов зарегистрированного MCP tool.

`browser-approval-panel.js` показывает в Web UI кнопки `Подтвердить` / `Отмена`, а для финансового действия — отдельное `Подтвердить оплату`.

## MCP / Skills Marketplace

`ToolRegistry` хранит манифесты локально. Опасные permissions (`mutate`, `desktop`, `secrets`, `financial`) требуют approval до вызова tool.

`ExtensionMarketplace` ставит Python MCP-расширение в отдельный venv. Marketplace требует закреплённую версию пакета, HTTPS-ссылку на исходный репозиторий и указанную лицензию. После установки сервер обязан успешно объявить MCP tools; иначе установка откатывается.

## Document Intelligence

`DocumentIntelligence` использует MarkItDown для PDF/DOCX/XLSX/PPTX и поддерживаемых текстовых форматов. Обработка локальная; удалённый URL не принимается как путь к документу. Для PDF предусмотрен fallback через pypdf, для простых текстовых форматов — встроенный reader.

## Computer Use

В Лешем уже имеется отдельный `ComputerUseController` и адаптеры наблюдения/действий desktop UI. В настройках он теперь представлен самостоятельным модулем `computer-use`; Browser Agent не подменяет Computer Use.

## Отказоустойчивость

Если Browser Use не может выполнить read/research, BrowserAgent может перейти к следующему совместимому адаптеру, а исследовательский сценарий сохраняет результаты обычного live search. Отсутствие Browser Use/MCP не должно ломать общий чат.

## Проверки

Regression-набор покрывает:

- поиск сначала, а не немедленную покупку;
- выбор первого/второго/третьего варианта;
- необходимость суммы для оплаты;
- owner-bound и одноразовый approval;
- отсутствие секретных arguments в публичном approval;
- запрет non-read Browser Use без approval;
- запрет финансового действия без approval summary;
- локальный Document Intelligence и запрет URL;
- сохранение/выключение MCP manifest;
- запрет небезопасного удалённого HTTP MCP;
- обязательное подтверждение dangerous MCP tool;
- обязательное подтверждение установки расширения.

Реальные платежи не используются в CI. Финальный E2E финансового действия проверяется на тестовом/песочном сценарии без списания денег.
