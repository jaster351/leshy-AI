# Устойчивость выборочной подгрузки Knowledge при повреждении индекса

Дата: 2026-11-12. Изолированное дополнение к интегрированному PR #155.

При обновлении `knowledge/updates/index.json` возможен момент, когда файл отсутствует, содержит неполный JSON, недекодируемые байты или недоступен из-за файловой гонки. Вызов `find_catalog_matches` происходит в интерактивном маршруте, поэтому ошибка чтения индекса не должна прерывать пользовательский чат.

Реализация: при `OSError`, `UnicodeError`, `ValueError` или `TypeError` поиск возвращает пустой список; никаких неиндексированных JSONL-пакетов автоматически не сканируется и никакие сведения не импортируются. Исправление не меняет переключатель самообучения, обычный поиск уже сохранённых знаний и ежечасную синхронизацию.

Регрессионные сценарии добавлены в `tests/test_repository_knowledge.py`: неполный JSON, не-UTF-8 индекс, отсутствие индекса, отсутствие записей в LeshyBrain при ошибке. Сценарии **добавлены, но не запускались локально**. Требуется проверка существующим CI и отдельный end-to-end smoke в разрешённой среде перед признанием функции готовой.

Оставшийся риск: индекс с формально корректным JSON, но повреждёнными вложенными метаданными может потребовать отдельной схемной валидации; исправление намеренно узкое, чтобы не менять контракт PR #155.
