# 1.10.104 — исправление поиска, контекста и Browser Use

Дата: 12.11.2026. Проблема подтверждена по сообщениям, скриншотам и runtime-логам на двух ПК с версией 1.10.103 в Web и Telegram.

## Исправления
- `realtime_chat.py` и `app.py`: при «Зайди на официальный сайт» / «ответь на первоначальный вопрос» предмет поиска берётся из истории **той же сессии**, уже проверенной по owner_id. Не передавать голую последующую фразу в поиск.
- `contextual_web_query.py`: прямой URL преобразуется в целевой поисковый запрос `site:<домен> <тема из пути>` без `https`, параметров запроса и случайного идентификатора статьи.
- Результаты URL-поиска принимаются только с заданного домена или его поддоменов и при наличии достаточного совпадения по теме. В частности, результаты Википедии про HTTPS больше не должны подменять статью Rockstar.
- При отсутствии подходящих источников система не должна выдавать догадки за прочитанную страницу.
- `browser_use_adapter.py`: Browser Use показывает фактический ответ Browser Agent пользователю. Отдельное завершение browser-задачи не считается прочитанной статьёй. Для READ при пустом или типовом результате применяется резервный Playwright, если он доступен.
- Добавлены `unittest` тесты `test_contextual_web_query.py` и `test_browser_use_result.py`.

## Границы изменения
Это не гарантирует доступ к каждому сайту (CAPTCHA, JS, региональная блокировка, сетевые сбои) и не исправляет целиком весь механизм 4096-токенного контекста. Неверное понимание темы моделью всё ещё возможно. Также код не доказывает, что каждый веб-сниппет соответствует фактическому тексту страницы. Не сообщать, что страница прочитана, если доступ не подтверждён.

Прежние правила изоляции Telegram-пользователей, ограничения Browser Use и отключение небезопасных browser-действий сохраняются.

## Ручные проверки
1. Web: «Когда выйдет GTA VI и сколько дней осталось?» → «Зайди на официальный сайт» → URL Rockstar с `?id=1%27`. В истории должна сохраняться GTA VI; выдача про HTTPS недопустима.
2. Telegram: та же последовательность в личном и групповом чате с разными пользователями. Ответы не должны получать данные чужой сессии.
3. Browser Use: чтение публичной страницы Habr должно вернуть название и содержание либо явную ошибку чтения — не одну квитанцию «задача завершена».
4. При отключении сети/блокировке сайта должен появляться честный отказ от утверждений, которых нет в доступных источниках.
5. Проверить Windows на ПК1 и ПК2, Web и Telegram; сравнить `VERSION`, журнал `live_search_started`, `user_source_read_failed`, `chat_stream_web_refusal_detected`, `browser_agent_browser_use_completed`.

**Проверки:** исходники проверены по GitHub. Исполнение тестов, сборки на ПК пользователей и E2E не выполнялись — их результат нельзя считать подтверждённым.
