# Память по текущему запросу, а не по последнему сообщению любого чата

Issue #99, Codex, ветка `codex/99-request-memory-query`; база main `b4bfd27faa3535ef9a77b6ffe5dc4e43e49f27b4`, подготовка версии 1.10.197. Прямой приоритет владельца19.11.2026: знания и память в ответах.

## Причина и поведение

В `advanced_modules_runtime._compose_memory_context` использовался `latest_user_query(owner_id)`. Этот SQL выбирает последнее сообщение пользователя во всех его сессиях. Например, пока чат A готовит ответ о резервном копировании, в чат B того же профиля приходит вопрос о саде. Чат A мог искать память и GraphRAG по вопросу о саде. Это подмена темы внутри одного владельца; межпрофильная утечка этим наблюдением не доказана.

Теперь обычный `LeshyApp.chat` передаёт `lookup_query`, а потоковый `RealtimeChatManager._build_context` — `lookup_query or message` в `_memory_context`. Все параметры относятся к текущему вызову. Обёртка advanced modules передаёт тему непосредственно в память и граф. Общего изменяемого состояния запроса, нового фонового процесса или повторного чтения последнего сообщения нет.

Текущая тема может быть уточнена по истории этого диалога. Поэтому `capture_text` отдельно содержит исходный `message`. Поиск использует уточнение, а существующий auto-capture — исходные слова пользователя при включённом самообучении. Вызов интеллектуального слоя с темой, но без исходного сообщения передаёт пустой capture-текст; синтезированная тема не сохраняется. Прямой legacy-вызов `IntelligentMemoryEngine.context(owner, query)` сохраняет прежнее поведение.

Постоянные правила профиля по-прежнему загружаются базовым слоем, переключатели памяти/графа действуют независимо, повторное включение одного правила в дополнительный блок не допускается. Legacy `_memory_context(owner)` без вопроса сохраняет базовый профиль, но не дополняет его сведениями по случайной соседней сессии. Схема SQLite, фильтры owner, LeshyBrain и существующие записи не мигрируют и не меняются при разработке.
