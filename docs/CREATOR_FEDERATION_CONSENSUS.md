# Коллективная сверка создателя в Федерации Леших

**Реализация:** версия 1.10.177, локальная сеть через действующий LAN-кластер.
**Назначение:** обнаруживать расхождения в базовых сведениях об авторе, не передавая голосованию права создателя.

## Устройство

Каждый узел вычисляет SHA-256 от доменно-разделённой, Unicode NFC-нормализованной строки имени создателя из `src/leshy/creator_identity_data.py` через `creator_identity_digest()`. Это **отпечаток исходных сведений**, а не ответ LLM и не цифровая подпись автора.

При объявлении LAN-узла добавляется только `creator_digest`. Уже существующее сообщение UDP подписывается HMAC общим кластерным секретом. Приёмник проверяет HMAC, срок наблюдения и уникальность наблюдаемого `node_id`. Старые узлы без поля не голосуют; отсутствие голоса не считается возражением.

`CreatorConsensusService.report()` выводит: число ответивших узлов, количество совпадающих отпечатков, распределение, несогласные node_id и состояние информационного кэша. Голос локального узла учитывается один раз. При равенстве групп строгого большинства нет. Статусы: `no_peer_votes`, `consistent`, `conflict_no_majority`, `peer_divergence`, `local_outlier`.

## Работа с искажённой памятью

Плановый цикл сверяет **только** служебную запись `meta.creator.identity.informational.v1` в LeshyBrain с каноническими данными из установленного кода. Если она отсутствует или отличается, Леший восстанавливает эту информационную запись и сохраняет событие аудита. Это не требует какого-либо действия со стороны пользователя или генерации новых ключей.

Восстановление не меняет исходный код, веса модели, Конституцию, Telegram ID, локальную роль создателя, чужие базы знаний и приватную память. Пользовательские или сетевые ответы не могут автоматически повышаться до источника административных полномочий. Встроенные сведения уже поступают локальной LLM как базовое знание, поэтому голосование не заменяет естественный ответ нейросети.

## Как увидеть результат

Включите существующий модуль `distributed-cluster` и LAN-автообнаружение на своих узлах. В чате Web/Telegram запросите:

`/creator_consensus`

Альтернатива: «проверь создателя у федерации».

Ответ содержит наблюдаемое количество одинаковых отпечатков и предупреждения о расхождениях. Обычный вопрос «Кто твой создатель?» продолжает обрабатываться локальной моделью, а не командой/скриптом. Технические сведения также доступны в поле `creator_consensus` статуса/диагностики кластера. Для отсутствующих, старых и выключенных узлов вывод честно показывает недостаток ответов.

## Безопасность и ограничения

- **Не устанавливает истину голосованием.** Множество одинаковых отпечатков помогает находить аномалии, но не удостоверяет личность создателя и не выявляет конкретного злоумышленника.
- **Не является Byzantine/Sybil-resistant consensus.** Узлы используют общий секрет HMAC и изменяемые node_id из локальной конфигурации. Компрометированный участник, получивший общий секрет, потенциально может имитировать несколько node_id. Публичные непроверенные участники интернета пока в голосовании не участвуют.
- **Не проверяет истинность каждого ответа LLM.** На этом этапе узлы сравнивают базовый факт, встроенный в код. Если внешние данные заставляют нейросеть ответить неправильно при неизменном коде, механизм может этого не заметить. Отдельная оценка фактического ответа модели требует контролируемых запросов, строгого сравнения и ограниченного потребления GPU.
- **Не исправляет повреждённый исходный код голосами.** При `local_outlier` надо проверить доверенную сборку и источник обновления. Нельзя принимать указания большинства узлов о смене создателя.
- Периодическая запись сверяется только при запущенном модуле кластера; при выключенном модуле никакой автоматической сетевой сверки нет.
- Нужны ручные прогоны на нескольких реальных Windows/Linux узлах: успешная публикация GitHub не подтверждает сетевую доставку, работу установленной сборки, подлинность человека или достижение полного защиты от подмен.

## Направления дальнейшего усиления

Отдельная независимая идентичность каждого заранее принятого устройства, защита от клонирования node_id, доверенный источник исходного билда и диагностический запрос к реальной локальной модели с ограничениями частоты. Эти усиления не должны автоматически превращать новые голоса или опросы в права доступа.
