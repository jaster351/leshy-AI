# Автоматическое определение GPU без привязки к конкретным моделям

## Что изменилось в 1.10.31

**Добавлено: универсальное обнаружение видеокарт.** Леший определяет производителя и видеоустройство автоматически, не используя списки RTX, Radeon, Arc или других моделей. Это позволяет видеть новое поколение GPU без изменения исходного кода.

**Добавлено: сведения об оборудовании.** В `/v1/hardware` и панели «Производительность» отображаются доступные имя, производитель, версия драйвера и объём VRAM. Данные, которые ОС не сообщает достоверно, остаются неопределёнными. В частности, поле `Win32_VideoController.AdapterRAM` на Windows имеет 32-битное ограничение, поэтому пограничные значения около 4 ГиБ не выдаются за объём памяти современных дискретных GPU.

**Добавлено: обнаружение Linux и macOS.** На Windows сведения поступают из `Win32_VideoController` (CIM/PowerShell), на Linux — из `/sys/class/drm` и, при наличии, `lspci -D -nn`, на macOS — из `system_profiler SPDisplaysDataType -json`. Отсутствие внешней утилиты не приводит к аварийному завершению.

**Исправлено: не обещать multi-GPU по факту обнаружения двух видеокарт.** Реальная поддержка распределения модели зависит от выбранного backend и версии llama.cpp.

## Принцип определения производителя

Основной идентификатор — PCI Vendor ID из аппаратного устройства. Это стабильные коды **производителей**, а не перечень моделей или версий. При отсутствии PCI ID используется имя, предоставленное драйвером. Неизвестный производитель не блокирует обнаружение GPU.

## Граница между обнаружением и работой модели

- **GPU обнаружен** означает, что операционная система сообщает о наличии устройства.
- **GPU backend кандидат** означает, что можно попытаться подготовить Vulkan/совместимый GPU runtime. Это ещё не означает, что модель на нём запущена.
- **Работоспособность GPU** подтверждается только успешным запуском backend и пробным inference. Существующие механизмы health/failover должны выполнять эту проверку.
- **CUDA, ROCm, Metal:** в этом изменении они не подключаются автоматически. Текущий рабочий маршрут `resolve_execution_plan` для GPU сохраняет `vulkan`; появление названия CUDA/ROCm в характеристиках не означает, что движок уже встроен.
- Если драйвер отсутствует или backend не запускается, чат должен переходить на доступный резерв; число GPU не гарантирует ни скорости, ни успешного запуска.

## Совместимость и диагностика

Публичные поля `HardwareCapabilities` и API сохранены. Добавлены только `gpu_devices` и `gpu_offload_compiled`. Последнее поле фиксирует наличие поддержки GPU-offload у импортированного `llama_cpp`, **а не** результат реального inference.

Синтетические regression-тесты охватывают Windows с разными PCI Vendor ID, Linux с двумя адаптерами, работу без sysfs, macOS, неизвестный GPU, отсутствие GPU и сохранение auto-плана. Тесты не требуют настоящих карт.

Локальные сборки и автотесты не запускались по правилу владельца. До внешнего CI и реальной проверки Windows/Linux/macOS изменение нельзя считать подтверждённым end-to-end.
