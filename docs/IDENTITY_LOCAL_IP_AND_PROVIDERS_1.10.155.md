# Профили Лешего без внешнего домена: LAN/IP, Gravatar, провайдеры

Версия: 1.10.155. Леший остаётся локальным, без NAT port forwarding, облачного сервера и обязательного внешнего домена.

## Что работает по IP

- Web создаёт локальный профиль с HttpOnly cookie.
- Telegram привязывается к Web через существующий одноразовый код.
- **Новая привязка другого Web-браузера**: откройте «Профиль Лешего» на первом ПК, выберите «Получить код для другого ПК», на втором откройте тот же экземпляр Лешего по LAN-IP, вставьте код и нажмите «Войти по коду». Код — случайный 128-битный токен, действителен пять минут и используется один раз. Идентичность владельца проверяется серверной сессией, не параметром owner_id. Память владельца доступна после подтверждения, чужие профили не объединяются автоматически.
- **Gravatar** — опциональный аватар в карточке профиля. Email нормализуется и хешируется SHA-256 до записи в SQLite, сырой адрес не сохраняется. При показе изображения браузер обращается к Gravatar и передаёт идентификатор-хеш третьей стороне. Это **не способ аутентификации** и не доказательство владения адресом; можно отключить. На HTTP в локальной сети email при отправке формы и одноразовые коды не защищены от перехвата; используйте только доверенный сегмент LAN либо включите HTTPS.

## Google, Apple, VK ID

В карточке профиля явно показан статус каждого провайдера. Пока **нет рабочего OAuth входа**: данные провайдеров не приравниваются к владельцу, не создаются «входы» через неподтверждённые email, аватары или внешние профили.

- Google Web OAuth требует заранее зарегистрированный callback с HTTPS и допустимым доменным именем; исключение для loopback/localhost не делает LAN-IP допустимым callback другого компьютера.
- Apple Sign in для Web требует Services ID, зарегистрированный HTTPS-домен и callback; IP/localhost запрещены.
- VK ID для Web требует регистрацию приложения и доверенный Redirect URI. Работоспособность по произвольному LAN-IP не предполагается.
- Для интеграции провайдеров **в будущем** нужен URL с HTTPS-доменом, доступный клиенту, и зарегистрированные OAuth приложения. Секреты/ключи нельзя размещать в репозитории.

Режим IP и Telegram не отключаются после добавления внешних провайдеров. Никакая «проверка по email» или профиль Gravatar не может выдать владельцу полномочия.

## API

- `GET /v1/identity/status` → `avatar`, `providers`, `browser_pairing_available`.
- `POST /v1/identity/gravatar` JSON `{"email":"..."}` → аватар; требует существующую cookie и тот же Origin.
- `POST /v1/identity/gravatar/clear` JSON `{}` → очистка.
- `POST /v1/identity/browser/pair` JSON `{}` → одноразовый код.
- `POST /v1/identity/browser/accept` JSON `{"code":"..."}` → Web-сессия становится идентичностью владельца, которому принадлежит код.

Существующие API Telegram не изменены. Полный Windows/Linux/macOS UI/E2E ещё требует проверки после локальной сборки.
