# Интернет-кластер: идентификация и предварительная регистрация

**Состояние в 1.10.94:** автоматическая регистрация доступна через
статический каталог начальных HTTPS-адресов на GitHub, который читается
**только** как точка первоначального входа и кэшируется локально.
Регистрация с известным seed и дальнейшие heartbeat **не используют GitHub**.
Ни пользовательские данные, ни статусы участников, ни общие знания в
репозиторий не записываются. Авто-вступление включено по умолчанию,
отключается в настройках.

**Каталог пока пуст**: доступные публичные seed ещё не опубликованы.
Полноценные P2P, NAT traversal, независимый обмен заданиями, единая
версионированная база знаний и выполнение чужих задач **НЕ работают**.
LAN-кластер сохраняет существующий HMAC-протокол.

## Реализовано в 1.10.20

- Ключ Ed25519 создаётся **для каждого локального пользователя отдельно**, без
  передачи закрытого ключа серверу, координатору или в блокчейн.
- Файл приватного ключа хранится в каталоге LeshyBrain/cluster/community-keys,
  имя файла — хэш локального идентификатора пользователя.
- Публичный ключ можно передавать другим участникам для проверки подписи.
- Сообщения содержат версию протокола, тип, временную метку, одноразовый nonce,
  публичный ключ, полезную нагрузку и подпись.
- Проверяются корректность подписи, срок действия, допустимый тип сообщения
  и повторное воспроизведение (in-memory replay cache).
- Приватные ключи **не восстанавливаются автоматически** и не копируются
  удалённым узлам. Владелец должен самостоятельно и безопасно сохранять backup.

## Следующие обязательные задачи перед публичным запуском

1. **Явный opt-in для вычислительного участия** и лимиты CPU/GPU, RAM,
   батареи и времени работы. Автоматическая регистрация в публичном реестре
   не даёт разрешения выполнять чужие задачи. Параметр auto-join должен быть
   прозрачно описан в установщике, так как включает исходящий сетевой контакт
   и раскрывает оператору bootstrap IP-адрес клиента.
2. **Защищённый интернет-транспорт**: TLS, проверка peer identity,
   bootstrap/discovery, relay/NAT traversal, защита от DoS и rate limits.
3. **Разрешение задач на стороне исполнителя**: строгие capabilities, квоты,
   резервирование слотов, таймауты, отказ от подозрительного узла.
4. **Приватность**: личные переписки и память не уходят на чужой компьютер без
   отдельного согласия. TLS защищает канал, но не скрывает текст от исполнителя.
5. **Проверка вычислений**: валидация задач, контроль подмены результатов,
   репутация без необходимости публичного блокчейна.
6. **Общий протокол LAN и интернет**: один формат подписанных команд и результатов,
   общие правила балансировки для Linux, Windows и macOS.
7. **Интеграционные проверки** с несколькими машинами, обрывами сети и нагрузкой.

Подписанное сообщение доказывает владение приватным ключом, но **не
предоставляет** права выполнять задания. Модуль src/leshy/community_identity.py
специально не привязан к HTTP endpoint — открывать его для недоверенных
пользователей до появления авторизации и TLS запрещено.

Android Worker остаётся отдельной будущей модификацией.
