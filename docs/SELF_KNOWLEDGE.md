# Самоописание возможностей Лешего

С версии 1.10.113 Леший читает **локальный** машинный каталог функций
из корня установки `capabilities.json`. Каталог хранится в GitHub и
устанавливается вместе с программой. После обновления оба компьютера получают
одинаковое описание кода; состояние каждый компьютер определяет самостоятельно.

## Два независимых источника

- `capabilities.json` — **что реализовано** (`implemented`, `partial`,
  `planned`), каким инструментом это проверять, какие ограничения известны.
- `CHANGELOG.md` — **что менялось и когда**. Он остаётся человекочитаемой
  резервной историей и **не** используется для вывода «функция работает».
  Полная копия существовавшего на момент внедрения файла сохранена в
  `docs/archive/CHANGELOG_BACKUP_2026-11-12.md`.

`CapabilityRegistry.snapshot(app)` дополняет каталог состоянием локального
runtime (`ready`, `disabled`, `unavailable`, `not_checked`).
Отсутствие проверки не трактуется как отсутствие функции или как успех.
Результаты E2E никогда не выводятся из наличия исходного файла.

## Как Леший использует это

На вопросы «Что ты умеешь?», «Какие у тебя возможности?» и запросы о
собственных изменениях `app.py` и `realtime_chat.py` получают краткий
контекст через `CapabilityRegistry.context_for_question(app)`.
Это одинаковый подход для обычного чата и потоковых Web/Telegram-сообщений.
Каталог не добавляется в каждую генерацию, чтобы не занимать контекст модели.

В Web UI метод `DashboardService.capabilities()` берёт ту же информацию
и сохраняет совместимые поля `ready` и `detail`. Там же доступно различие
между готовностью отдельных функций и их полной реализацией.

Если каталог повреждён или отсутствует, Леший читает заголовки
`CHANGELOG.md` **только как историю**. Он не придумывает список работающих
инструментов из текста истории.

## Правило для дальнейших релизов

При добавлении/изменении исполняемой возможности:

1. Обновить соответствующий элемент `capabilities.json` (или добавить новый).
2. При изменении кода поднять `VERSION` и описать реальное изменение в
   `CHANGELOG.md`, включая непроверенные сценарии и ограничения.
3. Установщик Windows копирует оба файла рядом с `Leshy.exe`.
4. Не заявлять об успешной сборке, вызове инструментов, подключении GitHub или
   E2E-проверке, если такой результат не был реально получен.

`VerifiedToolReceipts` подтверждает факт исполнения инструмента, но не
истинность любого текста, который инструмент вернул. Реестр не даёт новых прав
на управление ОС и не запрещает создание новых модулей. Инструменты, доступные
через `app.tool_registry`, и модули `app.module_manager` могут
добавляться в динамический список; если они не подключены к конкретному
экземпляру, список остаётся пустым, а не выдуманным.

## Проверка после установки (без запуска из этого PR)

Открыть штатную панель возможностей; спросить «Что ты умеешь?» в Web и Telegram;
временно отключить фоновое обучение и проверить статус `disabled`; отключить
Telegram и убедиться, что он не назван работающим; сверить VERSION и
проверить наличие двух файлов рядом с `Leshy.exe`.

В этом изменении локальные сборки, тесты и Windows E2E не запускались.
