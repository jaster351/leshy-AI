# Проверка прав перед SSH/RDP-действиями SuperAgent

Этот модуль — **одна независимая граница авторизации**, а не готовый удалённый исполнитель. Его можно подключить к существующей разработке `feature/superagent-ssh-executor-20261113` после проверки совместимости с актуальным `main`. Не нужно переносить или перезаписывать файлы `superagent.py`, `ssh_os_verifier.py` и `remote_os_fingerprint.py` параллельной ветки.

## Контракт исполнителя

1. Получить серверную Web-cookie из HTTP-запроса. Ни `owner_id` из JSON, ни Telegram username, ни IP, ни файл с паролем не подтверждают личность.
2. Установить защищённое соединение с узлом и получить **реально наблюдаемый** fingerprint ключа удалённой стороны. Нельзя доверять fingerprint из формулировки пользователя, LLM или произвольного заголовка HTTP.
3. Проверить регистрацию узла и полномочия `RemotePermissionPolicy.require(...)` через `RemoteActionBoundary.perform()` **после проверки host key, но до отправки пароля и выполнения удалённых команд**. Факт владения сервером подтверждается независимым механизмом регистрации узла, не одним IP/known_hosts.
4. Для `inspect` разрешены только заранее определённые неизменяющие команды диагностики, выбранные серверным кодом, например `uname -s`, `cat /etc/os-release` с ограничением вывода. Не передавать в них текст, сформированный моделью.
5. Для `execute`, `update`, `reboot` и `rdp` дополнительно необходима **серверная** проверка конкретного одноразового подтверждения. До её подключения слой отказывает по умолчанию.
6. Повторять проверку актуальности cookie, прав и отпечатка **перед каждым действием**, включая повтор после approval. Отзыв прав должен останавливать последующие операции; ранее полученное решение нельзя кешировать как вечное разрешение.
7. Не записывать cookie, файлы с паролями, приватные ключи, командный вывод с секретами в логи, Knowledge, распределённый рой или отчёты. Журнал — только идентификатор узла, тип действия, безопасный статус, короткая квитанция.
8. Отдельный RDP-транспорт пока **не реализован**. Проверка TCP/3389 — не авторизация и не управление рабочим столом. Для будущих RDP-кадров потребуются изоляция сессий, consent, визуальный approval и ограничения на запись/управление.

## Область текущих изменений

- `src/leshy/superagent_remote_action_boundary.py`: единый deny-by-default шлюз со свежими проверками пользователя, прав узла и подтверждений.
- `tests/test_superagent_remote_action_boundary.py`: сценарии чужого узла, чужой сессии, отзыва, неверного fingerprint, разделения разрешений и approval race.

**Не готово / не проверено:** вызывающий слой Web/Telegram/SuperAgent, фактический SSH transport, регистрация узлов с криптографическим доказательством владения, RDP-сессия и браузерный E2E. Наличие этого модуля не означает, что SSH/RDP уже работает для пользователя.
