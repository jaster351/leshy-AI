# Универсальная поддержка с локальным закрытым справочником

Публичный код не содержит названия работодателя, доменов, внутренней переписки и ключей. Режим активируется для задач подготовки ответа клиенту в Web/Telegram через `/support` или отдельный источник заявок `support_ticket_notice`.

**Стиль сохранён:** один готовый короткий ответ на «Вы», естественно, по существу, без лишних приветствий и подписей, без выдуманных проверок или выполненных действий. Автоматическая отправка в клиентские тикеты не разрешена.

## Автоматическое подключение знаний

В публичном дереве есть **только шифртекст** `resources/support_reference.enc`. Он включается в сборку Windows через PyInstaller `--add-data`, а ключ отсутствует в Git и EXE.

При обычном запуске `Leshy.exe` Леший проверяет наличие ключа Windows CurrentUser DPAPI в `LeshyBrain/private/support.key.dpapi` или в `LESHY_SUPPORT_PROFILE_KEY`. Если ключ есть и шифртекст прошёл аутентифицированную расшифровку, частный справочник готов автоматически.

При первом запуске ключ может быть автоматически импортирован из файла `Leshy-Support-Key.key` или из ранее скачанного владельцем `Local-Support-Profile.zip` в стандартной папке Windows Downloads. Дополнительный установочный скрипт **не** нужен. Ключ проверяется по содержимому пакета; после успешной проверки хранится в профиле пользователя под DPAPI и больше не требуется скачивать его после обновлений. Исходные файлы в Downloads не удаляются автоматически: пользователь может удалить их самостоятельно после активации.

Если ключа нет, Леший продолжает работу с универсальными правилами, **не придумывая** закрытые тарифы. Нельзя безопасно опубликовать одновременно шифртекст и ключ в одном публичном репозитории: это сделало бы шифрование бесполезным.

## Диагностика сборки

Frozen smoke-test сохраняет журнал исключений в `.autobuild/logs/frozen-smoke.stderr.log` и стандартный вывод в `.autobuild/logs/frozen-smoke.stdout.log`. При `exit code 1` он выводит хвост лога прямо в сообщение об ошибке. Временный smoke-процесс не импортирует частные ключи владельца.

**Ограничения:** эта функция не обеспечивает синхронизацию секретов между компьютерами или узлами роя. При запуске от другой Windows-учётной записи понадобится отдельное локальное предоставление ключа. Публичная история Git может по-прежнему содержать прежние сведения и требует отдельной очистки.
