# Browser Use: жизненный цикл coroutine (12.11.2026)

Частичное исправление Issue #154. Ранее `execute()` создавал `self._run(action)` до вызова `_run_sync()`. Если вызов происходил внутри уже работающего event loop, а запуск рабочего потока завершался исключением, созданная coroutine оставалась без await и порождала предупреждение `coroutine 'BrowserUseAdapter._run' was never awaited`.

Теперь `_run_sync` принимает фабрику coroutine. Объект создаётся внутри выбранного контекста `asyncio.run`, после успешного начала рабочего потока. Для обычного синхронного вызова используется текущий поток; при работающем loop — отдельный рабочий поток. API `BrowserUseAdapter.execute` не изменён.

Добавлены regression-тесты: сбой старта потока без создания coroutine, обычный синхронный вызов, вызов из активного event loop. **Тесты и локальные сборки не запускались** согласно ограничению владельца. Нужны CI и end-to-end проверка Web/Telegram/API; исправление не закрывает диагностику CDP, блокировку профиля и остальные пункты Issue #154. Изменение не затрагивает сохранённые профили браузера, cookies, идентичность пользователей и LeshyBrain.
