# Приоритет фонового inference: границы и регрессии (Issue #100)

Основа аудита: `main` `2133b41967571af4adf0c2a7ec2e411c1bd5ad9b` (10.11.2026).

## Что подтверждено исходниками

`src/leshy/inference_scheduler.py` сериализует доступ к одному inference slot. Очередь сортируется по убыванию priority и FIFO при равном priority: Web=100, Telegram=70, background=10. Отмена и timeout удаляют ожидающую заявку. **Уже активный запрос не вытесняется**: приоритет не гарантирует интерактивную latency, если произвольная длительная фоновая LLM-задача успела захватить слот.

`src/leshy/background_backend.py` предпочитает NPU, CPU, GPU, но GPU остаётся допустимым fallback. Общие provider-объекты могут конкурировать с пользовательским чатом. Наличие класса маршрутизатора само по себе не доказывает, что все фоновые вызовы идут через него.

## Что добавлено

`tests/test_inference_scheduler_priority_regression.py` покрывает порядок при одновременном ожидании Web/background, отмену ожидающего background, timeout без утечки очереди и назначение приоритетов. Это **только контракт очереди**, а не подтверждение preemption или E2E auto-title. Тесты не запускались по требованию владельца.

## Что остаётся сделать до runtime-исправления

1. **Уточнение по `main` 1.10.97:** `DashboardService.sessions()` в `src/leshy/dashboard.py` не запускает LLM; `_schedule_auto_title()` только регистрирует пропуск, а `_auto_title_one()` формирует заголовок детерминированно из первого пользовательского сообщения. Поэтому исторический 83-секундный auto-title из Issue #100 **нельзя считать воспроизводимым на текущем `main` без новых runtime-логов**. Проверять другие фоновые producers отдельно и прослеживать их маршрут до scheduler/provider.
2. Сохранить запрет массовой обработки старых сессий при старте; для прочих фоновых генераций ограничить количество, дедлайн и повторное планирование.
3. Перед началом background LLM проверять интерактивный спрос; обеспечить отмену/дедлайн для длительной генерации и безопасный отказ, не удаляя заголовки и историю.
4. Проверить fallback NPU -> CPU -> GPU при активном пользовательском GPU и health/circuit breaker для OpenVINO 503.
5. Добавить E2E regression на отсутствие LLM-вызовов при перечислении старых сессий после рестарта и на конкуренцию иной длительной фоновой задачи с пользовательским запросом; затем read-back runtime точек. Не заявлять о подтверждённом исправлении в Windows без проверки.

Документ фиксирует границы проверки, а не готовность runtime.
