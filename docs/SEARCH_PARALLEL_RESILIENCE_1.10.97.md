# Интернет-поиск Лешего: независимые резервные каналы (1.10.97)

## Диагноз по пользовательским журналам 07–08.11.2026

В предоставленных журналах есть 10 событий interactive_search_budget_exceeded
и 8 chat_stream_search_failed с сообщением «Свежий интернет-поиск не
завершился за 12 секунд». Встречаются HTTP/2 connection reset и ошибки
ddgs backend duckduckgo/yahoo/startpage. При этом часть запросов успешно
возвращала источники: интернет не исчезает целиком, а отдельные
поисковики не укладываются в заданное время.

Ранее FallbackSearch вызывал поставщиков строго последовательно:
SearXNG -> DuckDuckGo HTML -> DDGS (иногда до 9 backend).
Один подвисший источник лишал остальных времени.

Журналы относятся к нескольким запускам версий 1.10.75–1.10.91.
До пересборки установленных приложений последующие исправления не
появятся на ПК.

## Реализация

Все обычные источники запускаются независимо в параллельных потоках:

- Настроенный SearXNG: не более 4 секунд HTTP ожидания.
- DuckDuckGo HTML: отдельный запрос, ограничение 6 секунд.
- Bing RSS: независимый HTTPS XML поисковый маршрут, ограничение 4 секунд.
- DDGS: три резервных backend Google/Mojeek/Yandex с индивидуальным
  timeout 3 секунды; в интерактивном запросе они не блокируют быстрый
  ответ другого источника.

Первый подтверждённый непустой набор ссылок побеждает. HTTP 200 без
результатов, captcha/HTML вместо RSS, ошибки HTTP/2 или timeout
**не считаются успешным поиском**.

Общий параллельный поиск ограничен 8 секундами. Потоки daemon,
максимум 12 одновременных внешних поисковых работников на процесс.
Незавершившийся поиск не может бесконечно плодить потоковые задания.
В интерактивном чате обычный budget остаётся 12 секунд, но **явный запрос
пользователя к интернету** получает максимум 18 секунд, чтобы успеть
встроить результаты в ответ. Фоновое самообучение продолжает делать
повторные попытки при полном outage.

Важно: отказ всех независимых сайтов или самого доступа к интернету
невозможно гарантированно пережить. Леший должен сообщить о временном
отсутствии проверенных источников, **не выдумывая свежую информацию**
и не выдавая старые знания за результаты актуального поиска.

## Диагностика для каждого компьютера

После обновления и запуска Лешего:

```powershell
Invoke-RestMethod "http://127.0.0.1:8765/v1/search/providers" | ConvertTo-Json -Depth 5
```

Поля: requests, successes, unavailable, last_successful_provider,
last_success_at, provider_successes, provider_errors, provider_empty.
Это **счётчики за текущий запуск**; запросы и URL пользователей
на этом endpoint не раскрываются. Если настроен LESHY_API_TOKEN,
доступ требует соответствующей авторизации.
В runtime логах будут события search_parallel_provider_selected и
search_parallel_exhausted с именем backend и временем, но без текста запроса.

## Локальная проверка

На каждом ПК отдельно:

1. После пересборки проверьте версию 1.10.97.
2. Спросите у Лешего: «Найди в интернете последние новости Python и
   покажи ссылки на источники». Дождитесь ответа.
3. Повторите status endpoint. Последний успешный provider и successes
   должны измениться, если поиск действительно вернул результаты.
4. При DNS блокировке/прокси могут быть недоступны все поисковики,
   что будет отображено как unavailable и не маскируется выдуманным ответом.

Регрессионные сценарии: tests/test_search_parallel.py,
tests/test_search_budget_policy.py и tests/test_reliable_search_startup.py.
Сборка, тесты и настоящий сетевой запуск на ПК пользователя не выполнялись.
