# SuperAgent: SSH-проверка доверенных узлов

## Назначение

`superagent_verified_ssh.inspect_remote_os` — самостоятельный серверный исполнитель **только чтения**. Он выполняет реальную SSH-аутентификацию, но запускает исключительно фиксированные команды определения ОС: `uname -s` и `cmd.exe /c ver`. Он не запускает пользовательский shell, обновления ОС, перезагрузку или RDP и не принимает команды от модели.

## Условия доступа

1. Пользователь должен иметь действующую серверную Web-сессию и привязанный подтверждённый аккаунт провайдера. `owner_id` из тела запроса или localStorage не является удостоверением личности.
2. Узел должен быть отдельно зарегистрирован после **независимого доказательства владения** на целевом компьютере. В текущем `main` нет готового UI регистрации и валидатора такого доказательства. По умолчанию все незарегистрированные узлы запрещены.
3. У пользователя должно быть право `inspect` именно для указанного узла. Другие полномочия (`execute`, `update`, `reboot`, `rdp`) не возникают автоматически.
4. Цель — буквальный IP, совпадающий с `node_id` доверенного узла. Перед передачей пароля удалённый SSH host key сравнивается по SHA-256 с зарегистрированным отпечатком. Ротация ключа требует отдельной безопасной проверки и обновления привязки.
5. Файл доступа выбирается только по имени в уже настроенной папке владельца. Формат: UTF-8 JSON с полями `host`, `username`, `password`. Пример **без действующих паролей**:

```json
{"host":"192.168.5.12","username":"operator","password":"<secret stored locally>"}
```

Нельзя включать действующие файлы доступа в репозиторий или Knowledge. Файл ограничен 8 КиБ; пароли и содержимое не записываются в аудит, HTTP-ответ или квитанцию.

## Фактический статус

Этот этап добавляет защищённый исполнитель, регрессионные сценарии и серверный путь `POST /v1/superagent/ssh/inspect`, который требует API-доступа, активного задания SuperAgent, Web-cookie владельца, подтверждения в запросе, same-origin заголовков, включённого `remote-admin` и права `inspect` на сопряжённый узел. Путь запускает только read-only проверку ОС; результат **не** помечает задание завершённым и не отправляет автоматически в LLM.

Пакет `paramiko` нужен в среде, где исполняется SSH; в базовой установке `main` он не обязателен. Полный пользовательский сценарий требует ещё серверного сопряжения/регистрации узлов, интеграции в SuperAgent tool loop, UI подтверждений и защищённой доставки результатов, а также реальных E2E на доверенном стенде. SSH в GUI и RDP **не считаются готовыми**.

До E2E не передавать в runtime произвольные команды или возможность менять ОС. Все внешние источники, включая SSH-баннеры и текст диагностик, считать недоверенными данными.
