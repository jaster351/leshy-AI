# Постоянные правила общения Лешего — гарантированная запись

## Проблема

Ответ языковой модели «запомнил» сам по себе не подтверждает наличие
записи в LeshyBrain. Общий поиск воспоминаний может не выбрать правило
стиля для тематически несвязанного вопроса. Из-за этого пользователь
наблюдал возврат к театральному стилю после обещания соблюдать правила.

## Контракт первой реализации

Явные сообщения вроде «Установи постоянное правило: ...»,
«Леший, запомни правило: ...», «Категорически запрещаю ...» и
«Сохрани правило: ...» обрабатываются детерминированным маршрутом чата.
Не требуется отдельная команда или панель: ответ с ID записи показывается
в обычных Web и Telegram чатах.

Маршрут:
1. Чат идентифицирует реального владельца текущей сессии.
2. Распознаётся только прямая инструкция отправителя, не цитата,
   содержимое Telegram Reply, сайт или ответ модели.
3. Правило сохраняется в существующей SQLite-таблице `memories` с
   `kind=dialogue_rule` и конкретным `owner_id`.
4. Только после чтения обратно из БД отправляется подтверждение с ID.
5. При следующих запросах этого же owner правила всегда выбираются
   отдельно от ранжирования обычных воспоминаний и фонового обучения.
6. Правила не дают никаких дополнительных полномочий на файловую систему,
   исполнение команд, SSH/RDP или доступ к чужим пользовательским данным.

Сохранение личных правил в общем `web:local`, `shared` и `standalone`
запрещено до подтверждения индивидуального профиля. При этом остальные
известные форматы owner_id не являются сами по себе криптографической
аутентификацией: внешний авторизационный контур остаётся обязательным.

Ограничения для короткого контекста модели: максимум 12 правил,
1200 символов на правило, суммарно 3600 символов. Длинное сообщение
не считается сохранённым; пользователь получает честную просьбу разделить
его на отдельные правила. Записи не распространяются автоматически на
другой `owner_id`, устройство или неподтверждённый Telegram/Web профиль.

Запросы «Какие правила ты помнишь?» не являются запросами на запись.
Они обслуживаются отдельным read-only маршрутом: ответ строится по реальным
строкам `memories` текущего owner с ID, источником и датой записи.
Если подтверждённых правил нет, Леший сообщает об этом, а не придумывает
«воспоминания» из образа персонажа или старой переписки.
Обычные диалоги не должны произвольно изменять постоянные правила.
При отключённом самообучении уже сохранённые правила продолжают работать;
явная просьба пользователя сохранять правило не является самообучением.

## Что ещё не доказано

Наличие записи и передача её в контекст не гарантируют идеальное выполнение
моделью. Нужны E2E проверки Web/Telegram/Windows на реальном ПК:
сохранение, перезапуск, длинная история, 4096-токенный backend, соблюдение
формата и отсутствие межпользовательской утечки.

Полная синхронизация профилей между устройствами и редактирование/удаление
конкретных правил через UI пока не реализованы этим изменением.
До полноценного владельческого связывания Telegram и Web — отдельные
профили. Не следует заявлять обратное.
