# Временное заземление динамических данных

## Цель

Запросы о погоде, новостях, курсах валют, расписаниях и других меняющихся данных нельзя отвечать по старому локальному знанию как по текущему. Перед генерацией Леший должен определить текущую локальную дату среды выполнения, интерпретировать относительные слова («сегодня», «завтра», «вчера») и выполнить свежий интернет-поиск с конкретной календарной датой.

## Погода

Фраза вида:

`Расскажи погоду в Челябинске на сегодня`

обрабатывается так:

1. определяется текущая локальная дата и время;
2. «сегодня» преобразуется в конкретную дату `YYYY-MM-DD`;
3. эта дата добавляется в поисковый запрос вместе с человекочитаемой русской датой;
4. модель получает временной контекст перед генерацией ответа;
5. свежие результаты поиска имеют приоритет над старым trusted/candidate знанием для текущей погоды.

Погода без слова «сегодня» по умолчанию трактуется как погода на текущую дату.

## Web и очередь inference

Локальная LLM работает через единый inference scheduler. Web имеет приоритет выше Telegram, но scheduler не прерывает уже начавшуюся генерацию. Поэтому если Telegram уже занял единственный inference-slot, Web ждёт завершения текущего ответа.

Интерактивное ожидание очереди ограничено 90 секундами. Web UI также имеет watchdog: если 90 секунд нет ни activity-события, ни новых токенов, текущий stream останавливается и интерфейс выходит из состояния бесконечного ожидания.

Это особенно важно при перезапуске приложения во время ответа: старое HTTP/SSE-соединение не должно оставлять Web UI в состоянии «Леший думает…» на много минут.
