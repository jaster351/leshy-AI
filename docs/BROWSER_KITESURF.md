# Kitesurf: дополнительный браузерный движок для Лешего (1.10.148)

Исследованный источник: https://github.com/cloudflare/kitesurf (14.11.2026). Лицензия: Apache-2.0. Леший использует **самостоятельно написанный адаптер**, не копирует Rust/TS/WASM исходники Cloudflare и не включает их в GPL-2.0-only поставку.

## Что представляет собой Kitesurf

Kitesurf — экспериментальный browser engine на Cloudflare Workers. Он реализует HTML/DOM/layout/paint (Blitz/Stylo/другие библиотеки), JS через Boa в WebAssembly, скриншоты и Chrome DevTools Protocol (CDP) через WebSocket. Документация подтверждает работу с Puppeteer, но не полную совместимость с Chrome. Для размещения в Cloudflare требуются платный Workers plan и Dynamic Workers. Локальная разработка с wrangler dev не требует оплаты Cloudflare.

В README и AGENTS.md проекта явно отмечены ограничения браузерных API, отсутствие гарантированной поддержки ряда Chrome-возможностей и антибот-фингерпринтинга. Это не способ гарантированно обойти CAPTCHA/блокировки.

## Архитектура Лешего

Добавлен собственный модуль src/leshy/kitesurf_cdp_adapter.py. Цепочка:

    BrowserPlatform → BrowserAgent → Browser Use / Kitesurf CDP / системный Chromium

Kitesurf включается **только явной локальной настройкой**, по умолчанию выключен. В режиме чтения конкретной ссылки «Изучи https://...» он пробуется до обычного Browser Agent. Для многостраничного интеллектуального исследования основным остаётся Browser Use. Kitesurf извлекает видимый текст отдельной страницы, но не является отдельной LLM и не должен объявлять вычитанный текст полноценным анализом.

При несовместимости CDP Леший возвращается к обычному Chromium. Технические ошибки в read-only действиях теперь допускают выбор следующего браузерного движка. При CAPTCHA, необходимости участия владельца или запрете политики переход к другому движку **не происходит**. Платежи, покупка, публикация, ввод данных и все изменяющие действия **не выполняются через Kitesurf**.

## Безопасность

- Настройка LESHY_KITESURF_CDP_URL принимает только ws://127.0.0.1:PORT/devtools/browser или ws://[::1]:PORT/devtools/browser, где PORT в диапазоне 1024–65535. Внешние IP, DNS-имена, пользовательские логины, URL с токенами и подменённые пути блокируются.
- Локальный /json/version проверяется на Browser=Kitesurf/... и Protocol-Version=1.3. Прокси при обращении к локальному discovery отключён.
- Для каждой страницы создаётся отдельный браузерный контекст, не переносится пользовательский Chrome/Edge профиль или сохранённые cookies. Service workers отключаются.
- До навигации должен зарегистрироваться перехват запросов: только HTTP(S), стандартные порты, разрешённые домены, без буквальных внутренних IP и localhost. Если CDP не поддержал этот контроль, навигация не начинается.
- CAPTCHA/challenge требуют участия пользователя. Снимки cookies, исходный текст страницы, полный URL и секреты не публикуются в диагностике.
- Доменный фильтр и блокировка приватных буквальных IP не дают абсолютной защиты от DNS-rebinding; Kitesurf следует запускать с отдельными сетевыми ограничениями, не имея доступа к важным внутренним хостам.

У самого Kitesurf нет встроенной авторизации CDP. Его порт нельзя публиковать в LAN/Internet. Cloudflare требует Cloudflare Access или эквивалентную защиту. Удалённые CDP-сервисы Леший намеренно не принимает в этой версии.

## Локальный запуск (опционально)

Согласно официальному README нужны Node.js 22+, pnpm 9.15.4, Bazelisk. В отдельной папке:

    git clone https://github.com/cloudflare/kitesurf.git
    cd kitesurf
    pnpm install --frozen-lockfile
    pnpm run dev

Проверьте http://127.0.0.1:8787/json/version — ожидаются Kitesurf/... и CDP 1.3. Перед запуском Лешего укажите локальный CDP-адрес:

PowerShell:

    $env:LESHY_KITESURF_CDP_URL = "ws://127.0.0.1:8787/devtools/browser"

Linux:

    export LESHY_KITESURF_CDP_URL=ws://127.0.0.1:8787/devtools/browser

Пример пользовательского запроса: «Изучи https://example.com/». Для отключения уберите переменную из окружения и перезапустите Лешего. Движок запускается **отдельно**; инсталлятор Лешего не скачивает его, не создаёт платную подписку и не включает Cloudflare-код в проект.

## Текущие границы качества

Kitesurf README гарантирует CDP для Puppeteer; фактическая совместимость текущего Python Playwright connect_over_cdp, Chrome target contexts, Fetch interception, redirects и close требует **реального E2E**. В данном релизе это опциональный экспериментальный backend; представлены mock-тесты, но ещё не утверждается, что на целевом Windows/Linux он работает безупречно.

Следующие этапы после E2E: автономный локальный CDP-брокер с авторизацией владельца, ресурсными лимитами, отчётами по скриншотам и отдельными sandbox-политиками. Код чужих проектов не копировать. Полные браузерные действия всё равно должны проходить существующий Human Approval Gate.
