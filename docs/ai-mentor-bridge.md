# AI-mentor: последовательная учебная диагностика

Версия проекта 1.10.216 (черновик PR). Старый одиночный HTTP-пилот заменён
пакетным исполнителем без вызова обычного /v1/chat. Не переносите прежнее
разрешение одного вопроса на новый пакет автоматически.

На одном доверенном локальном узле создаётся конфигурация
`LeshyBrain/ai-mentor/config.json`:

```json
{
  "enabled": false,
  "repository": "OWNER/PRIVATE_REPO",
  "batch_id": "mentor-batch-001",
  "batch_sha256": "",
  "approved_export_sha256": ""
}
```

Утвердите SHA-256 точных байтов файла batches/<batch_id>.json из main
(не SHA Git blob и не хеш только одного вопроса), проверьте весь пакет
на отсутствие личных данных и команд. Отдельный токен GitHub Contents
read/write только на приватный репозиторий сохранить локально через
leshy.secret_store.save_secret в ai-mentor/github_token.dat.
Затем включить enabled и перезапустить Лешего. Проброс портов и API-токен
больше не нужны для этого контура. Не публиковать токены.

Исполнитель принимает формат ai-mentor.batch.v1, выполняет вопросы по
порядку через app.llm.chat под PRIORITY_BACKGROUND. Только native и
наличие локального GGUF; echo и внешняя Ollama не допускаются. Никаких
вызовов обычного чата, пользовательских сессий, личной памяти или инструментов.
Сам runtime модели может добавлять штатную идентичность Лешего; ответы
поэтому не публикуются автоматически без просмотра. Фактический backend
и модель ответа пока помечены как неподтверждённые. Последние до четырёх
полных учебных пар в пределах 2400 символов передаются в следующий вопрос.
Большие пакеты делятся на транспортные части (до 256 вопросов, до 1 МиБ),
это не общий предел программы. Разрешение связано с ID и хешем пакета.

Каждая реплика и результат записываются отдельно. Запись sent до вызова
не повторяется автоматически при неопределённом исходе; ошибка прекращает
последовательность до разбора. Внешний обмен не чаще часового цикла;
начало сохраняется на диск. Новые вопросы запускаются в свободное время
с начальным бюджетом 85% часа; активную генерацию прервать этим таймером
нельзя. Обычный диалог имеет приоритет на уровне очереди, но не вытесняет
уже начавшийся inference. Не запускать два процесса с общей папкой.

Экспорт формируется локально в export.json, до 256 КиБ. Проверить полный
текст файла, отсутствие секретов и персональных сведений, затем указать
SHA-256 его точных байтов в approved_export_sha256. Следующий цикл
публикует ровно проверенные байты в responses/<batch_id>-<sha256>.json,
проверяет чтением обратно и отмечает каждый подтверждённый ответ.
Неподтверждённая публикация не перезаписывается; сохраняется локально.
Следующий экспорт получает отдельный хеш. При смене пакета сначала
завершить разбор старого export.json. Автоматическая публикация без
проверки не включена.

Web: «Обучение → AI-mentor», только подтверждённый Создатель.
Показываются локальные вопросы, ответы, статусы, время и хеш экспорта.
Панель обновляется каждые 5 секунд; до 50 записей. Показываются оценка наставника,
планка и число открытых расследований. Полноценная история с пагинацией,
корректирующие уроки, проверка устранения причин и телеметрия обновлений ещё не реализованы. Отдельный вызов модели не
проверяет всю прикладную архитектуру и не меняет веса.

Откат: отключить enabled, остановить Лешего, отозвать выделенный токен;
сохранить локальные записи. Сборка, тесты, фактический запуск и независимое
ревью не подтверждены.

## Оценки и планка нагрузки (1.10.207)
После проверки опубликованных ответов наставник формирует review.json, который доверенный локальный оператор сохраняет в ai-mentor и утверждает точным SHA-256 через approved_review_sha256 в config.json. Формат ai-mentor.evaluation.v1: source AI-mentor, batch_id, batch_sha256, benchmark_id, rubric_id, comparable (boolean), scores (массив объектов id, answer_sha256, scores:{factuality:0..2,constraints:0..2,meaning:0..2}, critical:boolean, cause: none/question/rubric/knowledge/context/code/model/resources/transport/unknown). Причина — предварительная классификация, не доказанный диагноз. Только оценка уже опубликованного ответа с совпадающим хешем учитывается. Один отчёт на пакет, без автоматического повторного применения. Частичный отчёт не подтверждает рост.
Начальная планка 30 новых вопросов за цикл, технический максимум одной части 256. Критическая ошибка снижает её вдвое; падение сопоставимого качества или полный результат ниже 60% — примерно на 30%. Рост на 20% допустим только при улучшении сопоставимых полных оценок, отсутствии ошибок и измеренной пропускной способности не менее 90% планки. Сравнение требует одинаковой подтверждённой модели, ревизии и контрольной методики. Пока runtime записывает not_confirmed, автоматическое повышение блокируется; отсутствие доказательств не заменяется догадкой. Состояние, причины и квота сохраняются в load-policy.json; цикл учитывает квоту только для новых вызовов. Ошибки не удаляются автоматически, а уже готовые ответы сохраняются для экспорта даже при остановке следующего вопроса. Импорт оценок пока локальный, без автоматического получения с GitHub; оценку открытых ответов выполняет наставник, не сам Леший. Нет автоматического исправления кода или переключения модели по отчёту.

## Резервные реакции наставника (1.10.208)
Наставник указывает reaction: like или dislike для каждого проверенного ответа, помимо основных критериев. При недостатке доказательств не выдумывает оценку. Для dislike обязательна причина из существующего перечня (unknown допустим до расследования). Старые отчёты без reaction принимаются, пропуски учитываются отдельно. Реакция проверяется по хешу ответа в составе утверждённого review.json; журнал <batch_id>.reactions-<review_sha256>.json сохраняется в LeshyBrain/ai-mentor. Дизлайк открывает расследование, препятствует росту планки при этой оценке, но не меняет объективные баллы; лайк — кандидат в положительные примеры, а не доказательство качества или автоматическая тренировка. Журнал считается применённым только при наличии хеша отчёта в load-policy.json. Сводка like/dislike/missing хранится в last_review.reactions. Частные пользовательские диалоги не экспортируются. Доставка отчёта по-прежнему локально утверждаемая; создание датасета, дообучение весов и интеграция обычных пользовательских реакций остаются отдельными задачами.

Дополнение 1.10.209: для dislike наставник передаёт reason (до 1000 символов) и corrected_answer (до 4000 символов), когда причина и исправление достоверно известны. Поля необязательны для обратной совместимости и неопределённых случаев, сохраняются в локальном журнале реакций как данные для последующего разбора. Не вставляются автоматически в системные инструкции, не исполняются как команды. Следующий этап — проверяемые корректирующие задания и интеграция с обучением.

## Динамика качества в планировщике задач (1.10.210)
График в Web, раздел «Задачи», отражает только подтверждённые ответы Лешего на учебные вопросы AI-mentor: 100 × сумма баллов по factuality, constraints, meaning / (6 × число вопросов). Полные отчёты с comparable=true сохраняются как измерения (до 168 последних). График группирует одинаковые benchmark_id и rubric_id, показывает число заданий, время, модель и изменение балла. При отсутствии измерений — явно пустое состояние. Дополнительно наставник может указать reference_model и в каждой строке reference_scores по тем же критериям, reference_answer_sha256 для фактически полученного эталонного ответа; относительный показатель = 100 × сумма баллов Лешего / сумму баллов эталона, если она ненулевая. Эталонный текст и корректность оценки проверяются наставником при подготовке отчёта; локальный код проверяет формат, но не верифицирует эталонный текст независимо. Это не процент общего интеллекта и не оценка личных разговоров. Сборка и проверка на сервере не выполнены.

Дополнение 1.10.211: над графиком в разделе «Задачи» отдельные крупные значения «Уровень ChatGPT на тех же заданиях» и «Уровень Лешего относительно ChatGPT». При наличии парных оценок последнего полного сопоставимого пакета первое нормируется к 100%, второе показывает отношение баллов Лешего к баллам эталона (может превышать 100%). При отсутствии данных — прочерк, без переноса старого значения на новый пакет. Основной график качества ответов наставнику остаётся самостоятельной метрикой.

Дополнение 1.10.212: отображаемое имя наставника — LiveMentor, раздел Web — «Задачи Лешего». В интерфейсе сравнения, графика и учебной переписки используется LiveMentor; внутренние идентификаторы протокола и пути сохраняются для совместимости. Реальная модель сравнения сохраняется в локальных метаданных, но не выводится в блоке сравнения.

Дополнение 1.10.213: существующий пункт меню Web снова называется «Задачи», без уточнения «Лешего». Пункты «Знания» и «Обучение» сохранены; LiveMentor — название наставника внутри разделов, а не отдельный пункт навигации. График остаётся в «Задачах», переписка — в «Обучении».

## Получение оценок из закрытого репозитория (1.10.214)
LiveMentor размещает утверждаемый отчёт по пути `reviews/<sha256>.json` в основной ветке выделенного закрытого репозитория. SHA-256 вычисляется по точным байтам файла, не по Git blob ID. В локальном config.json для этого режима требуется `review_download_enabled: true` и `approved_review_sha256` с разрешённым хешем. В часовой цикл сначала публикуются ранее утверждённые ответы, затем скачивается отчёт (если ещё не применён), проверяется размер до 256 КиБ и хеш; файл сохраняется как `review-<sha256>.json`. Существующий механизм проверяет связи с опубликованными ответами и применяет оценку один раз. При 404 цикл продолжает работу с прежней планкой. При несовпадении хеша отчёт не применяется. Отключение режима возвращает прежний локальный review.json. Не считать получение отчёта разрешением на выполнение команд или публикацию новых данных. Автоматическое утверждение каждого отчёта не реализовано; сборка, независимое ревью и работа на сервере не подтверждены.

## Квитанция приёма вопросов (1.10.215)
После сохранения всех вопросов, до инференса, мост записывает `<batch_id>.receipt.json` и публикует в уже разрешённом закрытом репозитории `receipts/<batch_id>-<batch_sha256>.json` со schema `ai-mentor.receipt.v1`, source `leshy_runtime`, status `received`, batch_id, batch_sha256, question_count, timestamp (UTC). Текст вопросов и личные данные не передаются. После GET-проверки удалённого файла сохраняется `<batch_id>.receipt-published.json`. Первый корректный удалённый файл сохраняется без перезаписи; конфликт при создании разрешается повторным чтением. При ошибке передачи текущий цикл прекращается до следующей попытки, локальные вопросы сохраняются. Квитанция означает заявление runtime о сохранении пакета, не независимое доказательство понимания моделью и не факт ответа. Отсутствие квитанции означает «получение не подтверждено», а не «не получено». Наставник сверяет SHA-256 пакета и количество вопросов. Автоматическое уведомление владельца и работа на сервере требуют отдельного подтверждения; сборка и тесты не запускались.

## Телеметрия запущенной версии (1.10.216)
В начале существующего часового цикла при включённом и настроенном мосте, независимо от наличия утверждённого пакета, публикуется `runtime/<instance_id>.json` в том же закрытом репозитории. Формат `ai-mentor.runtime-version.v1`: source `leshy_runtime`, непрозрачный случайный instance_id, версия `VERSION`, загруженная запущенным процессом, status `running`, timestamp UTC. Отдельного частого опроса сервера, вызова LLM или передачи IP, имени компьютера, путей, секретов и личных диалогов нет. Идентификатор хранится локально. Запись обновляется с проверкой Git blob SHA и подтверждается чтением; ошибка телеметрии не останавливает учебный цикл. Не считать старую запись доказательством текущей работы: если с последнего наблюдения прошло более двух часов, статус актуальности неизвестен. Версия в main не равна версии запущенного процесса. Телеметрия не доказывает установку до появления первой фактической записи и не является независимой аттестацией процесса. Сборка, независимое ревью и работа на сервере не подтверждены.


## Раздельная доставка через штатный обновлятор Windows (черновик 1.10.218)

- `leshy-AI/main` — только код приложения. Учебные вопросы, ответы и оценки не копируются в публичный репозиторий, даже в Base64.
- `AI-mentor/main` — приватный источник пакетов `batches/<batch_id>.json`, квитанций, ответов и оценок. Раздельный токен Contents read/write хранится локально в `LeshyBrain/ai-mentor/github_token.dat` (Windows DPAPI, тот же профиль, что и планировщик).
- Плановая задача Windows проверяет приватную доставку независимо от того, требуется ли пересборка текущей версии кода. При включённом локальном контуре и совпадении утверждённого SHA-256 сохраняет точные байты в `LeshyBrain/ai-mentor/<batch_id>.delivery.json`. Никакие файлы не исполняются. Отсутствие токена или ошибка GitHub не превращают успешное обновление кода в ошибку.
- Учебный исполнитель Windows для `jaster351/AI-mentor` больше не скачивает пакет сам: он читает локальную доставку, повторно проверяет формат и SHA-256 и при отсутствии файла показывает `waiting_delivery`. Обмен квитанциями и ответами по существующему защищённому протоколу пока остаётся зависимым от подключения GitHub.
- Для первичного включения на доверенном Windows-узле регистрируется отдельный GitHub App с Device Flow, Contents: read/write и Metadata: read, устанавливаемый только на AI-mentor. В браузере владельца авторизуется этот App. Скрипт `windows/mentor-authorize.ps1 -ClientId <Client-ID> -EnableMentor` выполняется в том же Windows-профиле, что и планировщик; Client ID — публичный идентификатор приложения, не токен. Скрипт проверяет доступ к единственной установке и репозиторию, хранит токены DPAPI и явно включает очередь и публикацию. Без `-EnableMentor` настройки учебного контура не меняются. Приложение GitHub пока не зарегистрировано, кнопка входа в Web ещё не подключена.
- При включённом `auto_queue` обновлятор читает `queue/current.json` только из закрытого репозитория. Переход к другому ID допускается после подтверждённой публикации всех ответов предыдущего пакета. Хеш проверяется до локальной активации; существующая запись не перезаписывается. Обновление токена выполняется в плановом цикле. После длительного отсутствия связи, отзыва разрешений или истечения refresh-токена может потребоваться повторный вход.
- При явно включённом `auto_publish` в том же контуре допустима автоматическая отправка учебных ответов локальной модели, с дополнительным ограничением схемы и фильтром подозрительных данных; фильтр не гарантирует полной деперсонализации. Непрошедший фильтр экспорт остаётся локально. Обычный чат, личная память и инструменты не используются. Самообучение из интернета не меняется. Оценки пока требуют прежнего отдельного разрешения.
- Отключение авторизации: `windows/mentor-authorize.ps1 -Disconnect`, затем отзыв доступа GitHub App в настройках GitHub. Не удаляются вопросы, ответы и личная память.
- При откате вернуть прежний код; локальные учебные файлы и настройки сохраняются. Проверка Windows PowerShell 5.1, DPAPI и реального сервера не проведена.


### Первичная регистрация отдельного GitHub App

В настройках личного аккаунта GitHub: Settings → Developer settings → GitHub Apps → New GitHub App. Укажите уникальное название, адрес проекта, отключите Webhook (входящий сервер не используется), включите Device Flow и срок действия пользовательских токенов. Выберите Repository permissions: Contents — Read and write, Metadata — Read-only; остальные разрешения не нужны. Установка — Only on this account, при установке выбрать Only select repositories → только AI-mentor. Скопируйте Client ID (не Client Secret и не приватный ключ) и выполните описанную выше локальную авторизацию. GitHub должен показать название именно этого приложения; код авторизации не передавать другим лицам.

В документации GitHub подтверждено: для Device Flow и обновления выданного им пользовательского токена Client Secret не требуется. См. https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-a-user-access-token-for-a-github-app и https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/refreshing-user-access-tokens.

Отдельный файл `delivery-status.json` хранит только локальный статус и время проверки доставки. Web показывает «Требуется вход в GitHub», «Ошибка авторизации GitHub», «Пакет скачан» или другую подтверждённую стадию независимо от часового цикла модели. Текст вопросов, токен и содержимое HTTP-ошибок в этот статус не попадают. Отсутствие записи не является свидетельством ошибки или успеха.
