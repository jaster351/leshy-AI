# AI-mentor: последовательная учебная диагностика

Версия проекта 1.10.207 (черновик PR). Старый одиночный HTTP-пилот заменён
пакетным исполнителем без вызова обычного /v1/chat. Не переносите прежнее
разрешение одного вопроса на новый пакет автоматически.

На одном доверенном локальном узле создаётся конфигурация
`LeshyBrain/ai-mentor/config.json`:

```json
{
  "enabled": false,
  "repository": "OWNER/PRIVATE_REPO",
  "batch_id": "mentor-batch-001",
  "batch_sha256": "",
  "approved_export_sha256": ""
}
```

Утвердите SHA-256 точных байтов файла batches/<batch_id>.json из main
(не SHA Git blob и не хеш только одного вопроса), проверьте весь пакет
на отсутствие личных данных и команд. Отдельный токен GitHub Contents
read/write только на приватный репозиторий сохранить локально через
leshy.secret_store.save_secret в ai-mentor/github_token.dat.
Затем включить enabled и перезапустить Лешего. Проброс портов и API-токен
больше не нужны для этого контура. Не публиковать токены.

Исполнитель принимает формат ai-mentor.batch.v1, выполняет вопросы по
порядку через app.llm.chat под PRIORITY_BACKGROUND. Только native и
наличие локального GGUF; echo и внешняя Ollama не допускаются. Никаких
вызовов обычного чата, пользовательских сессий, личной памяти или инструментов.
Сам runtime модели может добавлять штатную идентичность Лешего; ответы
поэтому не публикуются автоматически без просмотра. Фактический backend
и модель ответа пока помечены как неподтверждённые. Последние до четырёх
полных учебных пар в пределах 2400 символов передаются в следующий вопрос.
Большие пакеты делятся на транспортные части (до 256 вопросов, до 1 МиБ),
это не общий предел программы. Разрешение связано с ID и хешем пакета.

Каждая реплика и результат записываются отдельно. Запись sent до вызова
не повторяется автоматически при неопределённом исходе; ошибка прекращает
последовательность до разбора. Внешний обмен не чаще часового цикла;
начало сохраняется на диск. Новые вопросы запускаются в свободное время
с начальным бюджетом 85% часа; активную генерацию прервать этим таймером
нельзя. Обычный диалог имеет приоритет на уровне очереди, но не вытесняет
уже начавшийся inference. Не запускать два процесса с общей папкой.

Экспорт формируется локально в export.json, до 256 КиБ. Проверить полный
текст файла, отсутствие секретов и персональных сведений, затем указать
SHA-256 его точных байтов в approved_export_sha256. Следующий цикл
публикует ровно проверенные байты в responses/<batch_id>-<sha256>.json,
проверяет чтением обратно и отмечает каждый подтверждённый ответ.
Неподтверждённая публикация не перезаписывается; сохраняется локально.
Следующий экспорт получает отдельный хеш. При смене пакета сначала
завершить разбор старого export.json. Автоматическая публикация без
проверки не включена.

Web: «Обучение → AI-mentor», только подтверждённый Создатель.
Показываются локальные вопросы, ответы, статусы, время и хеш экспорта.
Панель обновляется каждые 5 секунд; до 50 записей. Показываются оценка наставника,
планка и число открытых расследований. Полноценная история с пагинацией,
корректирующие уроки, проверка устранения причин и телеметрия обновлений ещё не реализованы. Отдельный вызов модели не
проверяет всю прикладную архитектуру и не меняет веса.

Откат: отключить enabled, остановить Лешего, отозвать выделенный токен;
сохранить локальные записи. Сборка, тесты, фактический запуск и независимое
ревью не подтверждены.

## Оценки и планка нагрузки (1.10.207)
После проверки опубликованных ответов наставник формирует review.json, который доверенный локальный оператор сохраняет в ai-mentor и утверждает точным SHA-256 через approved_review_sha256 в config.json. Формат ai-mentor.evaluation.v1: source AI-mentor, batch_id, batch_sha256, benchmark_id, rubric_id, comparable (boolean), scores (массив объектов id, answer_sha256, scores:{factuality:0..2,constraints:0..2,meaning:0..2}, critical:boolean, cause: none/question/rubric/knowledge/context/code/model/resources/transport/unknown). Причина — предварительная классификация, не доказанный диагноз. Только оценка уже опубликованного ответа с совпадающим хешем учитывается. Один отчёт на пакет, без автоматического повторного применения. Частичный отчёт не подтверждает рост.
Начальная планка 30 новых вопросов за цикл, технический максимум одной части 256. Критическая ошибка снижает её вдвое; падение сопоставимого качества или полный результат ниже 60% — примерно на 30%. Рост на 20% допустим только при улучшении сопоставимых полных оценок, отсутствии ошибок и измеренной пропускной способности не менее 90% планки. Сравнение требует одинаковой подтверждённой модели, ревизии и контрольной методики. Пока runtime записывает not_confirmed, автоматическое повышение блокируется; отсутствие доказательств не заменяется догадкой. Состояние, причины и квота сохраняются в load-policy.json; цикл учитывает квоту только для новых вызовов. Ошибки не удаляются автоматически, а уже готовые ответы сохраняются для экспорта даже при остановке следующего вопроса. Импорт оценок пока локальный, без автоматического получения с GitHub; оценку открытых ответов выполняет наставник, не сам Леший. Нет автоматического исправления кода или переключения модели по отчёту.
