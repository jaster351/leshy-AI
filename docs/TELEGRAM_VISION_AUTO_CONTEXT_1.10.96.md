# Telegram: распознавание фотографий и вопросы после снимка (1.10.96)

## Причина ошибки

Раньше Telegram Vision требовал ручных переменных LESHY_VISION_ENDPOINT и LESHY_VISION_MODEL.
Даже установленную локальную мультимодальную Ollama-модель он не обнаруживал.
Кроме того, вопрос «Кто это?» без Reply после фотографии попадал в текстовую модель
без доступа к изображению; Леший отвечал о собственной личности.

## Изменения

Если указан полный локальный LESHY_VISION_ENDPOINT с моделью,
сохраняется совместимость с OpenAI-style API. В противном случае Леший
проверяет на локальном Ollama адресе http://127.0.0.1:11434 список
установленных моделей через GET /api/tags и vision capability
через POST /api/show, после чего отправляет снимок только в
локальный POST /api/chat (messages с images).
Прокси и редиректы для передачи фото запрещены, внешние Vision API
не используются. Текстовая модель без подтверждённой vision-capability
не назначается для распознавания фотографий.

Последнее фото хранится десять минут в памяти процесса: только Telegram
file_id, размер и MIME, без байтов изображения, паролей и секретов.
Записи разделены по Telegram chat_id и user_id, всего не больше 256.
Вопросы «Кто это?», «Что на фотографии?», «Опиши фото» и подобные
поступают повторно в Vision с исходным фото даже без Reply.
Если модель недоступна, Леший явно сообщает об этом и не выдумывает ответ.

## Как запустить локальную Vision

На компьютере установите и запустите Ollama, затем в PowerShell:

    ollama pull qwen2.5vl:3b
    ollama list

После скачивания Ollama-модели перезапустите Лешего. Модель будет
обнаружена автоматически без LESHY_VISION_ENDPOINT. Скачивание
нескольких гигабайт не выполняется скрытно при получении фото.

Если используемый GGUF Qwen3.5 в llama.cpp рассчитан на изображения,
ему всё равно нужен совместимый mmproj и соответствующий запуск
мультимодального backend. Наличие GGUF само по себе недостаточно.

## Ограничение двух компьютеров

Кэш фото в этой версии локален для одного процесса. Если первое
сообщение получит ПК1, а следующее — ПК2, контекст по-прежнему теряется.
Для двух узлов с одним Telegram-ботом необходим один poller/gateway и
передача контекста задач на вычислительные узлы; backoff HTTP 409
сам по себе не решает эту проблему.

Автотесты добавлены в tests/test_telegram_vision.py.
Windows-сборка, реальные проверки и автоматические тесты не запускались.
