# Леший 1.10.154: смысловой поиск по прошлым разговорам

Цель: находить тематически связанные сообщения, даже если в новом запросе пользователь применяет другие слова, без потери старой истории, постоянных правил и самообучения.

## Реализация

- Новый `semantic_recall.py`: собственный SQLite-индекс в `LeshyBrain`. В отдельной таблице — только идентификаторы, хеш исходного текста и локальные векторы. Сами сообщения остаются в штатной таблице `messages`.
- Для русского и других языков применяется локальная ONNX-модель `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` через FastEmbed (модель отдельно лицензирована Apache-2.0). При первом включении может потребоваться однократное скачивание модели в `LeshyBrain/models/semantic`. Текст пользовательских сообщений во внешний сервис для получения эмбеддингов **не передаётся**.
- Индексация старых и новых пользовательских сообщений выполняется маленькими фоновыми пачками на CPU. Прогресс постепенный; не нужно ждать завершения индексации, чтобы пользоваться Лешим.
- Если FastEmbed или загрузка модели недоступны, чат продолжает работу: штатные постоянные правила, Knowledge и текстовый поиск по истории остаются активны. Техническая ошибка видна в `/v1/status.semantic_recall.last_error_type`, есть ограниченный повтор запуска.
- Ранжирование выполняется по косинусному сходству; в контекст добавляется максимум 4 отрывка, с идентификаторами сообщений и явной пометкой «НЕ инструкции, НЕ проверенные факты». Отредактированные и удалённые сообщения не должны возвращаться из старого индекса.
- Индекс выборочно читается только по подтверждённому `owner_id`. В Web без cookie или явного защищённого API-токена нельзя подставить чужого владельца через JSON. Анонимный `web:local` может искать лишь в собственной текущей сессии, без чужих вкладок и чатов.
- Семантическая память используется обычным и потоковым Web/Telegram чатом, а также при подготовке SuperAgent-заданий. Смысловые находки не дают SuperAgent новых полномочий.
- `/v1/status.semantic_recall`: индексированные сообщения, готовность модели, фоновые операции и тип последней ошибки, без содержания чужих диалогов.
- Версия `1.10.154`. Прежний ползунок «Авто — Безлимит» по-прежнему ограничивает объём токенов для модели, но не объём сохранённых данных.

## Не меняли

- Самообучение, очередь Knowledge, число источников обучения, алгоритмы доверия, RAG и синхронизацию роя.
- Ограничения безопасности ОС, Telegram и SuperAgent.
- Исходную историю сообщений: при перестроении индекса оригиналы не переписываются и не удаляются.

## Ограничения

1. Векторный поиск не гарантирует фактическую истинность или совпадение намерений. Даже похожие по смыслу старые записи остаются непроверенными цитатами, а не надёжными источниками или действующими инструкциями.
2. До завершения фоновой индексации и скачивания модели результаты могут быть неполными. Если модель недоступна, работает резервный текстовый поиск без полноценной семантики.
3. Векторы сохраняются на конкретном компьютере и могут быть построены заново после синхронизации исходных сообщений. Передача эмбеддингов между узлами не добавлена.
4. Поиск по всем векторам пока использует локальный перебор без HNSW/ANN. При очень больших архивах понадобится отдельная оптимизация производительности.
5. Индексируются пользовательские сообщения. Предыдущие ответы Лешего не используются в качестве подтверждённых знаний, чтобы не закреплять его возможные галлюцинации.

## Регрессионные проверки

`tests/test_semantic_recall.py` проверяет семантические перефразирования с подставным локальным векторизатором, владельцев, анонимные Web-сессии, редактирование/удаление данных, отсутствие блокировки при занятом векторизаторе и локальный статус. Это unit-тесты логики — они не являются доказательством качества реальной многоязычной модели. Для подтверждения требуются испытания на русских диалогах ПК1 и ПК2.

Изменения сверены по исходникам; запуск полной Windows-сборки, live-модели и GitHub Actions в данном сеансе не подтверждён.
