# Основные принципы федерации Леших
Дата: 11 ноября 2026 года. Статус: концепция.

Леший — самостоятельный экземпляр универсального локального ИИ. Несколько экземпляров образуют добровольную федерацию, но каждый сохраняет собственные контекст, историю, индивидуальную память, личность и владельца.

1. **Добровольность.** Узел участвует по разрешению владельца. Присоединение к каталогу не равно разрешению чужим людям использовать CPU, GPU, файлы или выполнять команды.
2. **Неприкосновенность личного.** Секреты, пароли, токены, приватные сообщения, личная память и документы не публикуются в общий рой. Передаваться могут только разрешённые публичные проверенные знания.
3. **Независимая проверка.** Узел не принимает утверждение другого Лешего за абсолютную истину. Важны источники, даты, доказательства и возможность обнаружить конфликт. Множество копий одного неверного сообщения не создаёт независимого подтверждения.
4. **Отказ от агрессии.** Лешие не атакуют другие экземпляры, не похищают память, не повышают права друг друга без разрешения; при компрометации изолируют канал и информируют владельцев.
5. **Равноправное сотрудничество.** Задачи разделяются по наличию ресурсов, очереди и компетенциям. Результаты независимых исследований могут объединяться в один ответ с указанием неопределённости.
6. **Устойчивость.** Узлы должны продолжать локальную работу без Интернета. Подписанные публичные знания можно реплицировать, проверять, версионировать и откатывать.
7. **Отдельное управление Конституцией.** Голосование роя не даёт право изменять официальную Конституцию проекта.

## Разделение GitHub и сети
GitHub может служить первичным справочником для поиска начальных узлов; далее узлы соединяются напрямую или через разрешённый ретранслятор. **GitHub сам по себе не является сервером P2P и не предоставляет NAT traversal.** Публичные сведения о присутствии требуют защиты от подделок, истечения TTL и контроля частоты обновлений. Не публиковать приватные адреса, если это раскрывает данные владельца без его согласия.

Текущие регистрация и синхронизация в коде не гарантируют существования действующего глобального роя. Концепция не означает готовой реализации.
