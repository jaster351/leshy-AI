# Что нового в «Лешем»

Здесь описаны **понятные пользователю изменения**, а не технический список коммитов. Записи разделены на «Добавлено», «Улучшено», «Исправлено» и «Известные ограничения». Если функция только запланирована или проверяется, она не объявляется выпущенной.

Текущая версия определяется файлом [VERSION](VERSION). История изменений ниже основана на изменениях, объединённых в основную ветку; это **не означает**, что новая версия уже опубликована как проверенный Windows-установщик.

## 1.10.56 — ограничение контекста и медленных fallback LLM

- Консервативная оценка токенов учитывает кириллицу/Unicode, чтобы русскоязычный диалог реже превышал контекст 4096 при переключении GPU/NPU/CPU.
- Пустые ответы и ответ только в `<think>` считаются ошибкой backend, а не успехом.
- После медленного сбоя (30+ секунд) не запускается последовательная дорогостоящая цепочка fallback на другие устройства. Быстрые ошибки сохраняют failover.
- Добавлены регрессионные сценарии контекста, Reply и пустой генерации. Исправлены тестовые JPEG-байты vision-маршрута.
- Это не мгновенная отмена уже зависшего вызова — длительность одного запроса определяется таймаутом конкретного runtime. Тесты и CI не запускались.

## 1.10.55 — фотографии Telegram: отдельный локальный vision-маршрут

- Фото без подписи и подписи к фото больше не игнорируются и не отправляются в текстовую LLM без изображения.
- После проверки Telegram allow-list и адресации группы скачивается ограниченное изображение JPEG/PNG/WebP через Bot API; данные и токен не записываются в логи.
- Поддерживается явно настроенный локальный OpenAI-совместимый vision endpoint (`LESHY_VISION_ENDPOINT`, `LESHY_VISION_MODEL`), только loopback; внешняя передача фото запрещена.
- При отсутствии модели или недоступном backend возвращается конкретная причина; Telegram Reply и owner ID сохраняются.
- Изображение не сохраняется в SQLite; в истории остаются текст вопроса и ответ.
- Добавлены регрессионные тесты. Нет встроенной vision-модели: для реального распознавания нужно настроить локальный vision backend. GitHub Actions и сборки не запускались.

## 1.10.50 — переносимый откат и защита завершённых заданий

**Защита от повторного выполнения:** команда `/agent answer`
теперь принимается только для задания в состоянии `waiting`.
Ответ уже завершённому заданию не возвращает его в очередь.

## 1.10.49 — строгая проверка архива и ограничение чтения

### Исправлено

**Проверка отката:** наличие даже повреждённого исходного файла по старому
пути теперь означает, что архивный откат не завершён. Ранее модуль
проверял только совпадение SHA-256 исходного файла и мог принять
подменённый файл за отсутствующий. Сверка не удаляет такие файлы.

**Ограничение проверяемого размера:** SHA-256 документов теперь
вычисляется только для файлов размером не более 16 000 байт.
Это предотвращает чтение неограниченно больших подменённых файлов
во время проверки и восстановления. Формат ответа команд выровнен.

### Проверка

Добавлены два регрессионных сценария. Код проверен по исходникам,
но локальные тесты и сборки не запускались. GitHub Actions — отключены.

## 1.10.48 — проверяемый эффект и обратимый откат документа

### Добавлено

**Проверка реального результата.** Команда `/agent verify ART-ID`
сверяет фактически сохранённый документ по SHA-256. Неизменность
квитанции сама по себе не считается подтверждением.

**Обратимый откат через архив.** `/agent rollback ART-ID` требует
команды владельца, проверяет исходные байты и переносит документ в
отдельный архив рабочего пространства без потери содержимого. Повтор
подтверждённого отката идемпотентен; восстановление после сбоя
проверяет архив и исходник без новых файловых изменений.

### Исправлено

Задания с любым уже созданным документом нельзя случайно повторно
пустить в LLM через `retry` или `answer`: для новой попытки нужно
явное новое задание. Добавлены сценарии местного тестирования изоляции
владельца, повреждённых файлов, отката и аварийного восстановления.

### Ограничения

Отменять можно только новые Markdown-артефакты Cognitive Core на локальном
томе; универсальный откат системы не реализован. GitHub Actions не
запускались. Локальные тесты и работа на Windows пока не подтверждены.

## 1.10.47 — защита от повторных действий после прерывания

### Исправлено

**SuperAgent не генерирует предложенный документ повторно.** Если
предложение записано в SQLite, но процесс остановился до состояния
`waiting`, после восстановления ожидается исходное подтверждение владельца.
Команды `retry` и `answer` не обходят Human Approval Gate.

**Сверка файла и базы.** Задания, оставшиеся `queued` после сбоя
записи, восстанавливаются по существующему файлу и SHA-256, без
повторного создания документа. Недоставленные отчёты отправляются
без повторного выполнения инструментов.

### Тестирование

Добавлен тест аварийного завершения дочернего процесса с файловой
блокировкой. Тесты и сборка не запускались; код опубликован без GitHub
Actions. Windows/Linux требуют локальной верификации.

## 1.10.46 — единый исполнитель SuperAgent для одной базы

### Исправлено

**Двойное исполнение при втором процессе.** Только владелец локальной
межпроцессной блокировки может восстанавливать задания `working`,
получать задания из очереди и выполнять их. Второй процесс не сбрасывает
активное задание первого и ждёт освобождения блокировки. После завершения
процесса файловый lock освобождается операционной системой.

**Согласование документов.** Подтверждение или отклонение документа
допускается только активным экземпляром SuperAgent. При завершении
процесса lock не отдаётся, пока worker ещё жив.

### Ограничения

Для сетевой файловой системы и многосерверного кластера понадобится
распределённый coordinator; сейчас поддерживается локальная SQLite.
Добавлены регрессионные сценарии, но полноценная локальная проверка
на Windows пока не выполнена. GitHub Actions не запускались.

## 1.10.45 — восстановление подтверждённых документов Cognitive Core

### Добавлено

**Сверка файлов с журналом SQLite после перезапуска.** Если запись
была прервана, Леший проверяет существующий документ по SHA-256:
целый файл подтверждает выполнение, отсутствующий или повреждённый
переводит задачу в заблокированное состояние без повторной записи.
Частичные файлы не удаляются и не заменяются автоматически.

**Обработка истёкших согласований.** Просроченные предложения
получают статус `expired`, а ожидающая задача — `blocked`.
Отдельно устраняется ситуация, когда файл уже помечен `applied`,
но статус задачи ещё `waiting`.

### Исправлено

Минимальные тестовые экземпляры SuperAgent теперь имеют безопасный
путь рабочего пространства без отдельного Settings. Ошибка создания
файла немедленно переводит ожидающую задачу в `blocked`.

### Ограничения и проверка

Полная локальная проверка на Windows не выполнялась; добавлены
регрессионные сценарии для автономного запуска вне GitHub Actions.
CI/CD в GitHub остаётся без автоматических запусков до 1 декабря 2026 года.

## 1.10.43 — согласование артефактов Cognitive Core

### Добавлено

**Human Approval Gate для документов SuperAgent.** Агент может подготовить
новый Markdown-документ, но не записывает его самостоятельно. Владелец
просматривает содержимое через `/agent preview ART-ID` и отдельно
подтверждает `/agent approve ART-ID` или отклоняет.
Создание допускается только в отдельном каталоге рабочего пространства,
без перезаписи; после записи проверяется SHA-256. Предложение
привязано к владельцу и конкретному заданию.

### Ограничения

Это не универсальное управление файлами и не самостоятельное изменение
проекта. Прочие изменяющие инструменты запрещены. Файлы создаются только
после явного подтверждения; локальные тесты и сборка не запускались.
GitHub CI остаётся без автоматических событий до 1 декабря 2026 года.

## 1.10.42 — журнал инструментальных шагов Cognitive Core

### Добавлено

**Устойчивый журнал SuperAgent.** Разрешённые read-only инструменты записывают
начало и результат каждой операции в SQLite: идентификатор задачи,
попытка, шаг, квитанция, SHA-256 входных аргументов и результата.
Тексты запросов/ответов повторно не сохраняются. Команда статуса показывает
последний шаг, недоступный другому владельцу.

### Исправлено

**Ложное «готово» после ошибки модели.** Пустой, незавершённый или неправильно
сформированный JSON-отчёт теперь переводит задачу в `blocked`, а не в `ready`.
После прерывания запуска недоделанные шаги помечаются `interrupted`; безопасное
чтение может повториться в новой попытке. Повторный шаг одной попытки отклоняется.

### Известные ограничения

Изменяющие инструменты не добавлены: нет гарантий exactly-once для внешних
операций. Сборка и автотесты не запускались; локальная проверка обязательна.
GitHub Actions остаются без автоматических триггеров до 1 декабря 2026 года.

## 1.10.19 — распределение нагрузки и голосовые сообщения

### Добавлено

**Статистика вычислительного кластера в настройках.** Теперь можно увидеть общую доступную мощность подключённых узлов и их загрузку. Это помогает понять, почему задача отправляется на определённый компьютер и где не хватает ресурсов. Показываются агрегированные показатели, без раскрытия приватных сведений отдельных узлов.

**Голосовые сообщения Telegram.** Леший получил маршрут локального распознавания голосовых сообщений через faster-whisper: голос преобразуется в текст, который передаётся обычному диалоговому обработчику. Это позволяет общаться с ассистентом голосом без обязательного облачного распознавания. Доступность зависит от установленных компонентов и ресурсов устройства.

### Улучшено

**Распределение задач между компьютерами.** Планировщик учитывает уже занятые вычислительные слоты и резервирует место при назначении задачи. Это уменьшает вероятность перегрузки одного узла, когда другие свободны.

**Контроль номера версии.** При изменении исполняемого кода, интерфейса, зависимостей или сборки CI должен требовать повышения версии. Это помогает отличать новые сборки от старых и понимать, какая версия установлена.

### Известные ограничения

**Анализ фотографий Telegram.** Зарегистрирована ошибка, при которой при отправке фотографии Леший сообщает о недоступности локальных LLM backend. Причина пока не подтверждена, полноценная проверка маршрута фото → vision → ответ остаётся открытой: [задача #75](https://github.com/jaster351/leshy-AI/issues/75).

**Устойчивость браузерного агента.** В диагностике зафиксировано аварийное завершение Chrome до подключения CDP. Самовосстановление и проверки продолжаются: [задача #67](https://github.com/jaster351/leshy-AI/issues/67).

## Как читать этот журнал

- **Добавлено** — новая пользовательская возможность и её назначение.
- **Улучшено** — существующая возможность стала удобнее, быстрее или надёжнее.
- **Исправлено** — конкретная устранённая неисправность, если устранение подтверждено.
- **Известные ограничения** — проблемы, которые ещё нельзя считать решёнными.

Планируемые функции и нерешённые ошибки отслеживаются в [Issues](https://github.com/jaster351/leshy-AI/issues); предложения изменений — в [Pull Requests](https://github.com/jaster351/leshy-AI/pulls). Источник кода — только [jaster351/leshy-AI](https://github.com/jaster351/leshy-AI).
