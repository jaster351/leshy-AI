- Подписанный Ed25519 heartbeat по HTTPS к известному bootstrap, безопасный отказ от редиректов, обрывов и неподходящих URL, повторное подключение с backoff. Передаются только публичный идентификатор узла и минимальные версии протокола.

- Важное ограничение: публичное предоставление CPU/GPU, обработка чужих данных, глобальная P2P-сеть и арбитраж пока не реализованы и остаются выключены; существующий LAN-кластер и личные данные не менялись.

## 1.10.72 — исправление преждевременного обрыва ответов по логам 7 ноября

- SSE теперь контролируется по отсутствию **реальных токенов модели**, а
  не останавливается сразу по истечении фиксированных 70/90 секунд, если
  Vulkan/CPU продолжает выдавать текст. Отдельный жёсткий потолок 360 с
  (`LESHY_STREAM_MAX_SECONDS`, допустимые значения 60–900 с) сохраняет
  защиту от действительно бесконечного ответа.
- Отсчёт генерации начинается после успешного запуска llama-server.
  Ненужные HTTP keepalive не засчитываются как активность модели,
  но реальные content/reasoning tokens поддерживают активный поток.
  Отзыв через кнопку Стоп остаётся немедленным best-effort.
- Если GPU или NPU медленно завершился **без единого видимого ответа**,
  разрешена одна попытка через доступный CPU: прежний запрет любого
  fallback после 30 секунд делал переписку недоступной.
  Дорогой последовательный GPU→NPU→CPU fallback не возвращён.
- Доработаны регрессионные сценарии для 1.10.67: живая медленная
  генерация сохраняется, hard deadline защищает от бесконечного потока.
  Изменения требуют реального Windows smoke: тесты/сборки/Actions не запускались.

## 1.10.40 — отключения клиентов Web API и исправления Cognitive Core

### Исправлено

**Web API на Windows:** при отмене браузером HTTP-запроса или закрытии
соединения во время записи JSON больше не должен появляться многократный
traceback `ConnectionAbortedError: [WinError 10053]`. Обрыв обрабатывается
на уровне HTTP-обработчика, включая вложенные Web API маршруты. Остальные
исключения остаются диагностируемыми. Если интерфейс продолжает терять
ответы, необходимо проверить отдельно причины отмены запросов.

**Cognitive Core:** исправлена строка подсказки после результата инструмента
и экранирование локального теста версии. Добавлена проверка лимита двух
вызовов инструментов и регрессионный сценарий обрыва HTTP.

### Проверка

Исправление опубликовано в исходниках; работоспособность на Windows
проверяется после локальной сборки владельцем. GitHub Actions, автотесты и
облачные сборки не запускались.

## 1.10.39 — инструменты чтения для Cognitive Core

### Добавлено

**SuperAgent получил строго ограниченные инструментальные шаги.** Он может
обращаться к доверенной базе знаний и получать версию приложения; результат
передаётся модели вместе с квитанцией реально выполненного чтения.
Допустимы максимум два запроса на задачу, повторения и попытки вызвать
неразрешённые операции блокируются. Доступ к ОС, файловым изменениям и
платным сервисам не расширен. Квитанция чтения не доказывает внешнее действие.

### Проверка

Добавлены сценарии локальной проверки безопасности и инструментального цикла.
Сборка и автотесты не запускались; работа на оборудовании пользователя пока
не подтверждена. CI/CD GitHub остаётся отключённым для автоматических событий
до 1 декабря 2026 года.

## 1.10.38 — первый контур проверки выполнения Cognitive Core

### Добавлено

**Контроль реального выполнения задач SuperAgent.** Задачи на изменение
файлов, системы и внешних сервисов больше не могут завершаться одним
заявлением языковой модели об успехе: требуется квитанция от исполнителя.
Без неё задача получает статус «заблокировано», а не «готово».
Текстовые запросы продолжают работать. Это первый, а не полный этап
Cognitive Core; см. [документацию](docs/COGNITIVE_CORE.md).

### Временно изменено

**GitHub Actions до 1 декабря 2026 года.** Автоматические события
`push` и `pull_request` удалены из трёх workflows. Оставлен только
ручной запуск, который не следует использовать при действующих лимитах.
Возврат CI/CD требует отдельного разрешения после проверки расходов.

### Проверка

Проверка кода и полноформатная локальная проверка на оборудовании владельца
ещё не подтверждены. Автосборка и автотесты GitHub не запускались.

## 1.10.19 — распределение нагрузки и голосовые сообщения

### Добавлено

**Статистика вычислительного кластера в настройках.** Теперь можно увидеть общую доступную мощность подключённых узлов и их загрузку. Это помогает понять, почему задача отправляется на определённый компьютер и где не хватает ресурсов. Показываются агрегированные показатели, без раскрытия приватных сведений отдельных узлов.

**Голосовые сообщения Telegram.** Леший получил маршрут локального распознавания голосовых сообщений через faster-whisper: голос преобразуется в текст, который передаётся обычному диалоговому обработчику. Это позволяет общаться с ассистентом голосом без обязательного облачного распознавания. Доступность зависит от установленных компонентов и ресурсов устройства.

### Улучшено

**Распределение задач между компьютерами.** Планировщик учитывает уже занятые вычислительные слоты и резервирует место при назначении задачи. Это уменьшает вероятность перегрузки одного узла, когда другие свободны.

**Контроль номера версии.** При изменении исполняемого кода, интерфейса, зависимостей или сборки CI должен требовать повышения версии. Это помогает отличать новые сборки от старых и понимать, какая версия установлена.

### Известные ограничения

**Анализ фотографий Telegram.** Зарегистрирована ошибка, при которой при отправке фотографии Леший сообщает о недоступности локальных LLM backend. Причина пока не подтверждена, полноценная проверка маршрута фото → vision → ответ остаётся открытой: [задача #75](https://github.com/jaster351/leshy-AI/issues/75).

**Устойчивость браузерного агента.** В диагностике зафиксировано аварийное завершение Chrome до подключения CDP. Самовосстановление и проверки продолжаются: [задача #67](https://github.com/jaster351/leshy-AI/issues/67).

## Как читать этот журнал

- **Добавлено** — новая пользовательская возможность и её назначение.
- **Улучшено** — существующая возможность стала удобнее, быстрее или надёжнее.
- **Исправлено** — конкретная устранённая неисправность, если устранение подтверждено.
- **Известные ограничения** — проблемы, которые ещё нельзя считать решёнными.
